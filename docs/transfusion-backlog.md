# 輸血オーダーの不足機能(JAHIS 患者安全ガイド 輸血編との突き合わせ)

2026-11-01 に、JAHIS 技術文書 25-101「医療情報システムの患者安全ガイド(輸血編)Ver.2.3」
(2025-10、<https://www.jahis.jp/standard/detail/id=1206>)の第 7 章「システム機能要件」を
輸血オーダーの実装と 1 項目ずつ突き合わせた記録。実装済みの範囲と設計判断は
`docs/transfusion-order-design.md`、他の部門をまたぐ課題は `docs/functional-gap-backlog.md` §2.4。

- **［事実］** = ガイドの記載、またはこのリポジトリ・上流の実装で確認した内容
- **［提案］** = 本メモの提案

ガイドは電子カルテ(オーダエントリ)に加えて、看護システム・臨床検査システム・輸血管理システムが
別にある構成を前提にしている(ガイド 5 章)。このリポジトリは輸血部門の業務(受付・出庫・実施)も
自前で持つので、輸血管理システム側の要件のうち「割付・払出」は対象に入れ、「在庫・発注・入庫」は
従来どおり対象外にする(§7.6)。

着手の推奨順は **A → B → C → D → E**(§2)。A は小さく、血液型の取り違えに直結する。

---

## 0. 結論

1. **血液型の扱いが、ガイドが挙げるインシデントの形のまま**。医師がチップで型を手で選び、
   型はヘッダに 1 つしか持てない(§7.2)。
2. **出庫がボタン 1 つ**で「どのバッグを出したか」を記録しないため、割付・払出のチェック
   (ガイド 7.3.3 の ①〜⑤)を置く場所が無い(§7.3)。
3. **投与時の照合が無い**。患者認証・製剤認証・確認者 2 名・副反応の定型化のいずれも無い(§7.5)。

---

## 1. プロセス別の不足

### 7.1 輸血関連検査

［事実］ガイドは、輸血前に血液型検査を 2 回(同一患者から異なる時点で採った 2 検体)行い、
その履歴をシステムで確認できること、履歴が無ければ製剤依頼までに検査をオーダーできることを求める。

| ガイドの要件 | 現状 | 不足 |
|---|---|---|
| 血液型検査 2 回の履歴を確認できる | **対応済み(2026-11-01)**。異なる日の 2 検体で一致したときに確定、1 回だけ・不一致は印 | — |
| 履歴が無いとき、依頼までに検査をオーダーできる | 設計書 §7 で申し送り済み | オーダー画面から血液型・不規則抗体の検査オーダーを呼び出す |
| 結果入力時に前回値と比べる | プロファイルタブで型を上書きできる | 前回と異なる型が入ったら警告する |
| 検体ラベル(患者 ID・氏名・性別・生年月日) | 検体検査のラベルで満たしている | — |
| 輸血関連情報カードの印刷(望ましい) | 無い | 帳票 1 枚(血液型・不規則抗体・輸血歴・副反応歴) |

#### 7.1-1 検査結果の血液型がオーダー画面の参照に出ない(不具合に近い)

［事実］オーダー画面の輸血前検査の参照(`usePretransfusionResults`、`api/queries/transfusion.ts`)は
LOINC(ABO 883-9 / RhD 10331-7 / 不規則抗体 890-4)で引いている。一方、検体検査の結果は
施設の結果項目コード + JLAC11 / JLAC10 で保存され(`fhir/labResultHelpers.ts` の `buildCodeCodings`)、
LOINC を持たない。seed のオーダー項目では ABO 血液型が JLAC11 `K1001000021100004`、RhD が
`K1006000021100004` で、不規則抗体(`160161410`)には JLAC11 が付いていない。

［事実］2026-11-01 の開発環境では LOINC 883-9 の Observation が 3 件あり、3 件ともプロファイルタブで
手入力したもの(`method` = tested)だった。JLAC11 コードの結果は 0 件。

［導出］今の参照表示は「検査部門から返った結果」ではなく「手で登録した型」を見ている。ガイド 7.2.3-2
(患者血液型は検査部門から報告された結果のみを表示する)の逆になっている。

［提案］参照は JLAC11 の分析物コード(`K1001` / `K1006`)でも引く。不規則抗体は JLAC11 が無いので、
結果項目コード(160161410)で引き当てる。

**対応済み(2026-11-01、段階 A)**。検査結果の検索は、結果項目マスタの血液型・不規則抗体の項目を引いて
から結果項目コードと JLAC11 で行う(`useBloodType`)。異なる日の 2 検体で一致したときだけ「確定」とし、
1 回だけ・不一致は印を付ける。手入力の情報源から「検査確定」を外した(`docs/features/patient-profile.md`)。
プロファイルタブの型(LOINC)と検査結果(JLAC11)の両方を出し、出どころを並べて示す。

### 7.2 血液製剤依頼

［事実］ガイドの依頼項目は、血液型・製剤名・単位数・使用場所・使用予定日・使用目的・緊急度・コメント。
リスク事例は、(1) 危機的出血時に依頼血液型を手入力で誤った、(2) 医師が患者血液型を手入力で誤った、
(3) 使用場所を誤って別部署へ払い出された、の 3 つ。

| ガイドの要件 | 現状 | 不足 |
|---|---|---|
| 緊急度レベルⅠ/Ⅱ/Ⅲ(準備時間の目安 10 / 30 / 60 分) | **対応済み(2026-11-01)**。`priority` の stat / asap / urgent | — |
| 型が未確定でレベルⅠなら、赤血球は O・血漿は AB を設定する | **対応済み(2026-11-01)**。型は製剤ごとに持ち、確定していなければ区分ごとの既定 | — |
| 輸血できる型以外は入力できない | **対応済み(2026-11-01)**。製剤区分ごとの適合表で選べない型は押せない | — |
| 血液型「不明」を明示して登録できる(付録 2 リスク分析シート #1) | **対応済み(2026-11-01)**。ヘッダに `unknown` | — |
| 患者血液型は検査結果だけを表示し、原則手入力させない | **対応済み(2026-11-01)**。患者の型は検査結果から写し、医師は手で入れない | — |
| 型の 2 回確定・抗体スクリーニングの有効期限・交差用検体の期限をチェックする | **一部対応(2026-11-01)**。2 回確定と不規則抗体の有効日数(施設設定)は依頼時と出庫時に警告。交差用検体そのものの期限は持っていない | §7.3 |
| チェックで追加依頼が要るとき、依頼画面を容易に呼び出せる | 無い | 検体検査オーダーの呼び出し(7.1 と共通) |
| 使用場所 | **対応済み(2026-11-01)**。`locationReference`、入院中は入院病棟が初期値 | — |
| 使用目的 | **対応済み(2026-11-01)**。`reasonCode.text` | — |
| 輸血・副反応の履歴を次回の依頼に反映する(7.5.3-3 の注記) | **対応済み(2026-11-01)**。副作用「あり」の記録を警告(表示のみ)に出す | — |

注意区分マスタの「輸血拒否」(`no-transfusion`)は、**対応済み(2026-11-01)** で確認を要する警告として出す。

#### 7.2-1 血液型をヘッダから明細(製剤区分ごと)へ移す

［事実］危機的出血(レベルⅠ・型未確定)では、1 回の依頼で「赤血球は O、血漿は AB」になる。
ガイド 7.3.2-2 には、依頼が O 型だったためそのまま O 型の FFP を割り付けて出庫した事例がある。

［導出］今の構造(ヘッダの `transfusion-abo` / `transfusion-rhd` に 1 つ)では、O を選べば FFP も O の
依頼になり、上の事例と同じことが起きる。

［提案］型を製剤明細の ServiceRequest に移す。既定値は「患者の確定型 + 緊急度 + 製剤区分」から決め、
選択肢は区分ごとの適合表で絞る。既存オーダーのヘッダの型は、読むときに明細へ割り当てて互換をとる。

#### 7.2-2 血液型を誰が決めるか(設計書 §2.5 の見直し、要判断)

［事実］設計書 §2.5 は「検査結果から自動で入れない(自動で入ると医師の確認が形骸化する)」という方針で、
医師が型を選び、検査結果は隣に並べて見比べる形を採っている。ガイドはこれと逆で、患者の型は検査結果
だけを表示し、依頼の型は緊急度から決め、適合しない型は入力させない。

［提案］ガイドに寄せる。ガイドが挙げるインシデントは、手入力した型の誤りそのものであるため。
あわせて、プロファイルタブの情報源「検査確定」は検査結果から作るものに限り、手入力は「本人・家族の申告」
「他院からの情報」に限る。

### 7.3 血液製剤割付・7.4 血液製剤払出

［事実］今の出庫は Task を `in-progress` に進めるだけで、どのバッグを出したかを記録しない
(`pages/TransfusionWorklistPage.tsx`)。

［事実］ガイド 7.3.3 の割付時チェックは次の 5 つ。不一致のときは警告を出す。
- ① 患者の型とバッグの型
- ② 依頼の型とバッグの型
- ③ 依頼の製剤種とバッグの製剤種
- ④ 使用予定日とバッグの有効期限
- ⑤ 不規則抗体のある患者に抗原陰性血が割り付けられているか

ほかに、型の 2 回確定、抗体スクリーニングの期限、交差適合試験の結果入力(赤血球)、自己血が本人のものか、
照射の要否、危機的出血時の異型適合血のチェックを求める。払出では、バーコードで患者分のバッグかを照合し、
赤血球で交差適合試験が不適合なら出庫させない(医師と協議した場合を除く)。

| 不足 | 提案 |
|---|---|
| 払出の記録が無い | **対応済み(2026-11-01)**。出庫記録ハブの `Procedure` + バッグごとの `MedicationDispense`(製剤番号・型・有効期限・照射・交差適合試験の結果・出庫者と適合試験者)。設計書 §2.7.1 |
| ①〜⑤のチェック | **対応済み(2026-11-01)**。出庫入力の警告(①患者の型 ②依頼の型 ③依頼の製剤 ④有効期限 ⑤不規則抗体陽性の確認)。不適合は確認を要する警告(医師と協議のうえ出すときは理由を残す) |
| 製剤マスタに照射の要否が無い | **対応済み(2026-11-01)**。`requires_irradiation` |
| バッグのバーコード読み取り | **対応済み(2026-11-01)**。ISBT 128 の 4 構造を 1 つの読み取り欄で振り分ける(`fhir/isbt128.ts`) |
| 輸血検査区分が 2 つだけ | **対応済み(2026-11-01)**。コンピュータクロスマッチ・生食法・交差試験なしを追加 |
| 抗原陰性血の照合 | 不規則抗体の特異性(抗 E など)を患者側に、抗原情報をバッグ側に持たせて照合する(段階 E) |
| 出庫票 | 交差適合試験の結果も刷る(付録 2 リスク分析シート #2)。帳票は未作成 |

### 7.6 血液製剤管理

［事実］ガイドは発注・入庫(二次元バーコードでの入庫確認、外観検査の記録)・在庫(製剤種別・血液型別・
期限切迫・割付済みか)・廃棄と返品の理由を求める。製剤の記録は使用日から 20 年以上保存する。

［提案］在庫・発注・入庫は輸血管理システムの領域として引き続き対象外にする(設計書 §1)。
ただし、出庫したが使わなかったバッグの**返却・廃棄の記録**は §7.5 の未実施バッグと対になるので、
払出記録(`MedicationDispense`)の状態として持つ。製剤番号からの逆引き(遡及調査)はロット管理画面
(`docs/lot-number-design.md`)で済んでいる。

### 7.7 自己血輸血

［事実］ガイドは自己血採血ラベル(患者 ID・氏名・血液型・製剤番号・採血日・使用予定日・有効期限・患者署名欄)、
有効期限の自動計算と手入力の禁止、有効期限が使用予定日より前なら警告またはラベル発行不可、割付時に本人の
血かを確認することを求める。リスク事例は、ラベルの日付の書き誤りと、手術日を確かめずに採血して期限切れに
なったもの。

［事実］製剤マスタに区分 `auto`(自己血)はあるが、採血の計画・記録・ラベルは無い。

［提案］`functional-gap-backlog.md` §2.4 の案(輸血検査区分に `autologous-collection`、採血の `Procedure`、
採取した製剤を `MedicationDispense` で台帳化して払出の候補にする)に、手術日から逆算した採血予定、
有効期限の自動計算、使用予定日との比較を足す。ラベルは検体ラベルの `.tlf` を流用する。

### 7.8 造血幹細胞移植

［事実］ガイドは、移植患者であることが分かる状態で、移植前・移植後の血液型を電子カルテで管理すること、
ABO 不適合移植後に誤った型で依頼したら確認メッセージを出すことを求める(いずれも望ましい)。

［提案］患者の血液型に「移植後に輸血に使う型」(製剤区分ごと)を持たせ、オーダーの既定値と適合表に使う。
血液内科で移植を行う施設がない限り優先度は低い。

## 2. 進め方

| 段階 | 内容 | 規模 |
|---|---|---|
| A | **対応済み(2026-11-01)**。血液型の参照を結果項目コードと JLAC11 で引く(§7.1-1)。2 回一致で「確定」と判定する。「検査確定」は検査結果からだけにする(§7.2-2) | 小 |
| B | **対応済み(2026-11-01)**。緊急度Ⅰ〜Ⅲと「不明」、型を明細へ移して適合する型だけ選べるようにする(§7.2-1)。抗体スクリーニングの期限、使用場所・使用目的、輸血拒否と副反応歴の表示 | 中。FHIR の構造が変わる |
| C | **対応済み(2026-11-01)**。払出記録(バッグごとの `MedicationDispense`)と割付チェック ①〜⑤、マスタに照射の要否、交差適合試験の結果(不適合は理由を残して通す)。出庫票の帳票は残り | 大 |
| D | **対応済み(2026-11-01)**。投与時の照合と確認者、払出済みバッグとの突き合わせ、副反応の症状項目と時点の観察、遅発性副反応の追記、未実施バッグの記録と警告 | 大 |
| E | 自己血、輸血関連情報カード、抗原陰性血の照合、移植後の血液型(コンピュータクロスマッチは検査区分として段階 C で追加済み) | 中 |

§7.2-2(血液型を誰が決めるか)はガイドに寄せた(患者の型は検査結果だけ、製剤の型は適合表で絞る)。
