# 指導・管理料オーダーの設計

医師がカルテから医学管理料(点数表 B 章。特定疾患療養管理料・生活習慣病管理料など)と在宅(C 章)を
算定するためのオーダー。`docs/receipt-billing-backlog.md` B-10 / D-5 の「医学管理料をカルテに入力する手段が無く、
栄養食事指導料以外の指導料が一切算定されない」を埋める。

実装日: 2026-10-29。

本文中の区別:
- **［事実］** = FHIR R4 / JP Core の仕様、または上流・既存実装で確認した内容
- **［導出］** = 仕様から論理的に導ける内容
- **［提案］** = 本ドキュメントの設計判断

---

## 1. 位置づけと命名

［事実］医事会計は実施記録ファースト(`docs/receipt-billing-design.md` §1)で、B 章の手技コードは章 → 区分で
130(C 章は 140)に振られる受け皿が既にある。足りなかったのは「カルテに記録する経路」だけ。

［提案］**部門オーダーの 17 番目の種別として足し、登録と同時に実施済にする。** 部門が受けて実施する種別ではなく、
医師が「この日に算定した」ことを記録するだけなので、Task・部門一覧・予約は持たない。種別として足すことで、
右ペインの登録・カルテのカード・DO・代行入力の来歴・削除・オーダーセットが既存の仕組みにそのまま乗る。

［事実］D-5 の案(ヘッダ無しの `Procedure` を医事送信モーダルのチェック欄で書く)は採らなかった。カルテの
タイムラインに 5 本目の読み込み元と非オーダーのカード一式が要り、上流の Procedure 検索に `department` が無いので
自科 / 個人の絞り込みも効かない。また会計の直前にしか入力できず、算定の根拠がカルテに残らない。

命名: 種別 `medical-management-order`、order-type `medical-management`、画面表記「指導・管理料」。
ファイル・関数は `medicalManagement` / `MedicalManagement`、項目マスタは `management_fee_items`。

## 2. 項目マスタ

［提案］施設が算定する管理料だけを、マスタメンテ > 医学管理 > 指導・管理料項目(`/management-fee-items`、
`master_management_fee_items`)に登録する。医科診療行為マスタの B 章 471 件(施設規模・情報通信機器・主病で
コードが分かれる)から毎回探させるのは現実的でないため。

| 列 | 意味 |
|---|---|
| `receipt_code` | レセ電算 診療行為コード(9 桁)。登録画面は診療行為マスタの B 章・C 章から選ぶ |
| `addition_codes` | 一緒に算定しうる加算のコード(jsonb 配列)。フォームで項目の下に候補として出す(初期値はチェック無し) |
| `inpatient` / `outpatient` | 入院・外来のどちらで算定できるか。フォームは入外区分でこれを絞る |
| `monthly_limit` | 1 か月の算定回数の上限。空なら見張らない(§5) |
| `active` / `display_order` | 選べる項目と並び |

［提案］名称・点数の正は診療行為マスタで、ここには写さない(一覧 API が LEFT JOIN で `receipt_procedure_name`・
`receipt_points`・`receipt_max_times` を添え、加算は `additions` に展開する)。改定で点数が変わっても直す場所が 1 つで済む。

## 3. FHIR の持ち方

```text
ServiceRequest (ヘッダ)  status = completed, category = order-type|medical-management + 入外区分
  code.text          = 項目名のまとめ(「特定疾患療養管理料 ほか1件」。履歴・会計の名称に使う)
  occurrenceDateTime = 算定日(日付のみ)
  note               = 備考 / reasonReference = 対象プロブレム / requester + 依頼科・病棟(applyOrderContext)
  ← basedOn ─ Procedure(ハブ。項目ごと)
                code = .../CodeSystem/medical-management-procedure-code|レセ電算コード
                performedDateTime = 算定日 / performer = 指示医師 / extension[order-department]
                ← partOf ─ Procedure(加算。basedOn もヘッダを指す)
```

- ［事実］会計は `{種別}-procedure-code` を読む(`OrderCatalog::Definition#procedure_code_system`)ので、この名前に
  しておけば会計側の対応表は要らない。
- ［提案］**備考はヘッダの `note` に置き、`Procedure.note` は使わない。** 実施記録の note は会計送信で
  フリーコメント(810000001)として日レセへ送られるため。
- ［提案］加算(子)にも `basedOn` を付ける。カルテ・詳細・削除・版の固定が `_revinclude=Procedure:based-on` 1 本で
  ハブと加算の両方を受け取れる(処置の実施記録と同じ)。
- ［提案］編集では同じコードの記録を使い回して PUT し(`withVersionLock` で版を添える)、外した項目・加算は
  同じ transaction で DELETE する(子 → ハブ)。送り直しで同じ剤の記録 id が変わらない。
- ［提案］削除は実施記録ごと消す。オーダー削除の共通処理(`api/queries/orderDelete.ts`)は「実施記録があれば
  削除させない」が、**Bundle 自身が同じ transaction で消す実施記録は数えない**という汎用の規則に直した
  (種別ごとの例外にはしない。他の種別の削除 Bundle は実施記録を含まないので挙動は変わらない)。

## 4. 画面

- カルテ右ペイン「指導・管理料」(登録・編集・DO)。フォームは算定項目(チェックリスト)・算定日・対象プロブレム・
  入外区分・備考。マスタから外れた項目(無効化・入外区分が合わない)でも、保存済みなら行として残す。
- カードは算定日に載り、項目と加算(字下げ)と備考を並べる。進捗は出さない(登録 = 実施済)。
- 外来一覧の当日オーダー列の印は「管」。オーダーセット・クリニカルパスのタスク雛形にも入る(セットの内容では
  算定日と対象プロブレムを持ち込まない)。

## 5. 前回算定日と上限の警告

［提案］フォームを開いたとき、その患者の指導・管理料の実施記録を 1 本で引き(`status=completed&_sort=-date`、
500 件まで。切れたらその旨を一言出す)、コードごとに前回算定日と算定日の月の回数を数えて項目の横に出す。
項目ごとに引くと開くたびに項目数ぶんの往復になる(レート制限 300 件/分)。編集中はそのオーダー自身の記録を数えない。

［事実］診療行為マスタの `max_times` は算定回数の上限だが、期間(月・週・初回のみ など)は項目ごとに違い、
このマスタだけでは決まらない。［提案］そこで項目マスタの `monthly_limit` を正とし(登録時に `max_times` を初期値に
入れ、施設が直せる)、「当月の回数 + 1 > 上限」なら共通の警告(`management-fee-limit`、表示のみ)を出す。
算定できるかの最終判断は日レセに任せる。

## 6. 会計連携

［事実］`OrderCatalog::ALL` に `order_type: "medical-management", source: :procedure, continuous: true` の 1 行、
`Orca::MedicalMessage::MEDICAL_CLASS` に 130 を足しただけで、ハブ 1 つ = 1 剤(加算は同じ剤の行)として送られる。
区分は手技の章から決まるので、B 章は 130・C 章は 140。`continuous` は「記録の無いヘッダを未実施と報告しない」ため
(登録と同時に記録を書くので通常は起きない)。

## 7. 残課題

- ［事実］薬剤情報提供料・手帳記載加算など日レセが自動発生させるコードは、送っても破棄される
  (`receipt-billing-backlog.md` B-14。`Medication_Import_Flg=yes` は未対応)。項目マスタに入れない。
- 特定疾患療養管理料など主病名が要件の算定は、カルテに主病名の概念が無いので日レセ側で付け直す(D-3)。
- 生活習慣病管理料の療養計画書(文書作成の様式)とオーダーの紐付けは無い。
- 上限の期間が月以外(週・初回のみ・6 か月に 1 回 など)の見張り、施設基準・届出の確認はしていない。
- 初・再診料は引き続き日レセの自動算定(B-10 の診察料の部分)。
