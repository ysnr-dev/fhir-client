# 病棟マップの設計

病棟の間取り(設備・病室・ベッド)を描いたレイアウトの上に、その日の入院患者を
ベッドごとに出す画面と、そのレイアウトを描くエディタ。入院患者一覧(表)の別の
見え方で、同じ `?ward=` と `?date=` を持つ。

実装日: 2026-09-09。

本文中の区別:
- **［事実］** = FHIR R4 / JP Core の仕様、または上流・既存実装で確認した内容
- **［導出］** = 仕様から論理的に導ける内容
- **［提案］** = 本ドキュメントの設計判断

---

## 1. レイアウトは backend に持つ(FHIR には置かない)

1. **［事実］設備は FHIR に置き場が無い。** ナースステーション・トイレ・階段は
   Location にできなくはないが、患者の所在(Encounter.location)に使わないものを
   Location に増やすと、病棟・病室・ベッドの階層(`fhir/wardHelpers.ts`)を読む
   側が全部それを除けて回ることになる。
2. **［事実］座標は Location の本来の情報ではない。** `location-display-order`
   拡張の前例はあるが、それは並び順 1 つで済む話で、間取り全体(キャンバスの大きさ、
   マス、設備、病室枠、ベッドの向き)を Location にばらして持つと一括で保存・
   復元できない。
3. **［提案］1 病棟 1 行の jsonb。** `master_ward_maps`(`ward_location_id` 一意、
   `ward_name` は表示用の写し、`layout` jsonb)。手術室ブロックが Location.id を
   文字列で持つのと同じで、FK は張らない。エディタはレイアウト全体を PATCH する。
4. **［提案］ベッドの実体は Location だけを正とする。** レイアウトは「その Location
   をどこに描くか」しか持たない。Location が消えたオブジェクトは欠番として赤枠で
   出し、エディタで「まとめて除く」。Location にあって置いていない病室・ベッドは
   「未配置」としてパレットに並ぶ。

### layout の形(座標・大きさはマス数の整数)

```
{ "schema_version": 1,
  "canvas": { "width": 60, "height": 40 }, "grid_size": 20,
  "objects": [
    { "id": "<uuid>", "type": "fixture", "kind": "nurse_station", "x": 0, "y": 0, "w": 8, "h": 4,
      "rotation": 0, "label": "NS", "color": "#aabbcc" },
    { "id": "<uuid>", "type": "room", "location_id": "<病室 Location.id>", "x": .., "y": .., "w": .., "h": .. },
    { "id": "<uuid>", "type": "bed", "location_id": "<ベッド Location.id>", "room_id": "<病室 Location.id>",
      "x": .., "y": .., "w": 6, "h": 6, "rotation": 0 } ] }
```

- 形は `Master::WardMap#layout_shape`(backend)と `normalizeLayout`(frontend、
  `fhir/wardMapHelpers.ts`)の両方が守る。backend は座標がキャンバス内か・
  location_id が type ごとに一意か・fixture の kind/rotation/color を見る。
  ベッドの大きさは frontend が固定値に矯正する(定数を二重に持たない)。
- `BaseController#record_params` は `permit(column_names)` で jsonb のネストを
  黙って落とすので、`WardMapsController` は `layout` だけ `to_unsafe_h` で受ける
  (オーダーセットと同じ)。

## 2. 描画は DOM、拡大縮小は transform

1. **［事実］fabric.js はシェーマ描画専用で、オブジェクトを永続化していない。**
   キャンバスに患者名・リンク・吹き出し・ケバブを載せるには DOM の方が素直で、
   ダークテーマの色もそのまま効く。
2. **［提案］オブジェクトは絶対配置、キャンバスは `scale()`。** 外側の要素に
   拡大後の大きさを持たせてスクロール範囲を正しくし、内側の要素だけ transform
   する。当たり判定は内側の `getBoundingClientRect`(scale 込み)から
   `clientToGrid` で解く。transform に平行移動を持たせない(rect と食い違う)。
3. **［提案］掴む操作は `useCardDrag`(Pointer Events)。** 手術カレンダーと同じ。
   ドラッグ像は作らず、元のカードを薄くして落とし先に点線枠を出す。編集では
   移動・リサイズの途中経過をレイアウトへ直接反映し(履歴には積まず)、離した
   ときに 1 手として記録する(`useUndoableState.commit`)。Escape で掴む前へ戻す。
4. 選択の優先はベッド > 病室 > 設備(病室の中を押せばベッド、無ければ病室)。
   病室を動かすと中のベッドも一緒に動く。リサイズは設備と病室だけで、病室は中の
   ベッドを外に出さない範囲まで。複製は設備だけ(同じ Location は 2 か所に置けない)。

## 3. 転床はドロップで書き込まない(移動プラン)

1. **［事実］転床は `buildBedTransferEncounter` で location[0] を差し替え、旧床を
   completed で後ろに残す。** これを 1 床ずつ書くと、A と B の入れ替えは「A を
   空床へ → B を A の床へ → A を B の床へ」の 3 回の書き込みになり、途中で
   やめると片方だけ動いた記録が残る。
2. **［提案］落とすたびに保留中の移動(`PendingMove`)を積み、転床日を決めて
   一括で確定する。** 入院 1 件につき最後の行き先だけ持つ(何度動かしても 1 手)。
   占有床へ落とせば入れ替え(相手は自分が居た場所へ)。確定は各 Encounter に
   `buildBedTransferEncounter` を当てて 1 つの transaction(`buildEncountersUpdateBundle`)。
3. **［提案］一時退避(ワークスペース)は「行き先未定」の状態。** 3 人以上の
   玉突きを組むための置き場で、退避のままでは確定できない(FHIR に床の無い入院を
   書かない)。
4. **［提案］確定の直前に入院を引き直す。** プランを組んでいる間に他の端末で入院が
   動いていれば、元の床か `meta.versionId` が変わっている(`findStaleMoves`)。
   その場合は書かずにプランを見直させる(キャッシュの Encounter を PUT しない)。
5. 今日以外の表示では掴めない(過去日の転床は入院患者一覧から)。病棟・日付を
   変えるとプランは捨てる(変える前に確認する)。病棟をまたぐ移動はマップ上に
   相手が無いので起きない(転科・転棟予定から)。

## 4. 入院予定の D&D と入院実施

- 当日の入院予定(この病棟宛て、または病棟未定)を横に並べ、空床へ落とすと
  `AdmissionExecuteModal` を床を選んだ状態で開く(`initialPlace`)。日付未定の
  予定(`period` 無し)も同じパネルに「日付未定」の見出しで並べ、日付を確定せずに
  そのまま入院実施できる(実施日時は実施時に入れる)。入院実施は
  即書き込みで別の Encounter を触るので転床プランとは独立させる。ただし保留中の
  移動先になっている床には落とせない(取り合わない)。
- 空床のケバブ「入院登録」は `AdmissionModal`、入院中のケバブは入院患者一覧と同じ
  モーダル(転室・転床 / 外出泊 / 転科・転棟予定 / 退院予定 / 退院)。

## 5. ベッドカードの情報

- 番号・患者番号・氏名(カルテへの Link、戻り先は `returnTo` で保つ)・性別・年齢・
  診療科 / 主治医・入院 n 日目・ピクトグラム(注意区分・アレルギー・感染症)・
  札(退院予定 M/D・転棟予定 M/D 病棟名・外出泊中)。
- **［提案］ピクトグラムは患者帯と同じ描画を使い、取得だけまとめる。**
  患者帯は 1 人ぶんを個別に引くが、マップは 40〜60 人並ぶので患者 id をカンマ OR で
  分割して引く(`useFlagsForPatients` ほか。`fetchByPatientChunks`)。描画は
  `components/PatientPictograms.tsx` に切り出して両方から使う。検査由来の感染症は
  塊ごとに新しい順で上限までしか見ないので、古い陽性は落ちることがある。

## 6. 残している論点

- 未保存のまま画面内リンクで離れるのは止められない(BrowserRouter のため
  `useBlocker` が使えない)。タブを閉じる・リロードだけ `beforeunload` で止める。
- 1 病棟 1 マップ。棟が分かれていて 1 枚に描けない病棟は、いまはキャンバスを
  広げて描く。
- 病室内の男女混在や、担当看護師での色分けはまだ無い(凡例の拡張で足せる)。
