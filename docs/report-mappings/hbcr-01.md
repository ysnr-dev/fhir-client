# 院内がん登録 標準登録様式 2016年版 テンプレート

国立がん研究センター「がん診療連携拠点病院等 院内がん登録 標準登録様式 2016 年版」
(https://ganjoho.jp/med_pro/cancer_control/can_reg/hospital/pdf/2016manual.pdf
第 1 版 更新日 2026/4、全 147 ページ) の標準登録項目 105 件をテンプレート化したもの。

| ファイル | 用途 |
|---|---|
| `hbcr-01.questionnaire.json` | テンプレート(Questionnaire)のエクスポートファイル。テンプレート一覧のインポートから取り込む(name: `HBCR_01`、`http://fhir-client.local/Questionnaire/hbcr-01\|2016.1`) |

レイアウト(`.tlf`)・マッピング定義は無し（帳票出力は対象外。登録・保管用のテンプレート）。

## 構成

登録様式の大項目をそのままトップレベルのグループにしている。項目は
`hbcr_<項目番号>` の linkId、質問文は `[項目番号] 項目名` の形。

| グループ | 項目 | 件数 |
|---|---|---|
| 基本情報 | [900]〜[199] | 8 |
| 腫瘍情報（診断情報／治療前（臨床）分類／術後病理学的分類） | [200]〜[699] | 33 |
| 初回治療情報（外科的・鏡視下・内視鏡的・放射線・化学・内分泌・その他／経過観察・症状緩和） | [700]〜[799] | 31 |
| 生存状況情報 | [800]〜[899] | 10 |
| 管理情報（紹介情報／届出・登録管理／最新住所／診療科・主治医／意思表示） | [910]〜[999] | 23 |

- 登録単位は様式どおり **1 腫瘍 1 登録**（[110] 重複番号で腫瘍を区別する）。
- 各項目の定義・判定ルールは `designNote` に入れてある（テンプレート編集画面の
  「設計メモ」で読める。回答フォームには出ない）。

## 様式との対応で判断したこと

- **必須の範囲**: 共通項目（■◆＝都道府県への届出項目）26 件のみ `required` に
  した。標準項目（●）・管理項目（◇）は任意。様式上は拠点病院等が●も必ず登録する
  ものとされているが、登録は診断直後から生存確認調査まで段階的に埋まるため、
  途中保存できるよう必須にしていない。運用に応じて編集画面で切り替えられる。
- **日付項目は `date` 型ではなく 8 桁の文字列**: 様式は日付を YYYYMMDD の数値型と
  定め、年不詳=9999 / 月・日不詳=99、該当せず・適用なし=77777777、全て不明=99999999
  という値を必須で使う。FHIR の `date` 型ではこれらを表現できないため、
  `string` + 正規表現 `^[0-9]{8}$` + `maxLength` 8 とした。既定値が定められている
  [810] 死亡日・[840]・[921]・[952]・[991]・[996] には `77777777` を初期値に入れてある。
- **病期関連コード**: [500][510][520][530][600][610][620][630] は
  [付録 3] TNM 分類等 病期関連コード表の亜分類まで全て選択肢にしている
  （例: [610] pT 分類は 99 個）。術後病理学的分類には「6610 手術なし」
  「6620 術前治療後」と、他施設の観血的治療に基づく 8000 台のコードも含む。
- **付加因子 [540][640]** は部位・臓器ごとに別々の因子（G 因子・S 因子・
  ホジキンリンパ腫の症状・GIST の核分裂像・甲状腺・胆道系亜部位・頭頸部）が
  1 項目に同居する様式のため、選択肢の表示名に対象部位を併記した
  （例: 「G1（骨・軟部組織・虫垂癌・前立腺）」）。
- **項目名は本文の項目定義ページに合わせた**。巻末一覧表では [830] の選択肢 30 が
  「全国がん登録情報」、[920] が「全国がん登録届出状況」等と表記が異なるが、
  本文側（「都道府県がん情報」「都道府県届出状況」）を採用している。
- **既定値のある選択肢**は `initialSelected` で初期選択している
  （[820] 生存状況=1 生存、[830] 生存確認調査方法=10 来院情報、
  [920] 都道府県届出状況=10 未届出、[990][995] 意思表示=00 オプトアウトなし）。
- **選択肢の描画形式**は選択肢 5 個以下をラジオボタン、6 個以上をドロップダウンにした。
- **選択肢コードに system は付けていない**（既存テンプレートと同様、コードと表示名のみ）。
- 拡張項目（△）は様式本体の範囲外（別添様式として随時提示される）のため含めていない。

## FHIR リソースからの自動取り込み

新規回答フォームを開いた時点で、患者の FHIR リソースから初期値が入る
（SDC `initialExpression`。値は編集可能）。

| 項目 (linkId) | 取り込み内容 |
|---|---|
| [100] 診療録番号 (`hbcr_100`) | Patient の identifier |
| [120] カナ氏名 (`hbcr_120`) | Patient のカナ名（`iso21090-EN-representation` = SYL）を「姓　名」で連結 |
| [130] 氏名 (`hbcr_130`) | Patient の漢字名（同 IDE）を「姓　名」で連結 |
| [140] 性別 (`hbcr_140`) | Patient.gender を male→1 / female→2 に変換して初期選択 |
| [150] 生年月日 (`hbcr_150`) | Patient.birthDate をハイフン除去して YYYYMMDD に変換 |
| [210] 診断時住所 (`hbcr_210`) | Patient の住所 |

加えて、ログイン中の医療従事者から自動入力される項目がある。

- [900] 病院等の名称 … 所属医療機関の名称（グループ見出しの「医療機関を選択」でも入る）
- [931] 登録者 … 医療従事者の氏名
- [922] 都道府県届出責任者・[941] 最新修正者 … 「医療従事者を選択」ボタンで入力（自動入力はしない）

## 検証済みの内容

- frontend の `parseQuestionnaireForm` + `validateQuestionnaireForm` を通過し、
  parse → build の往復で内容が変わらないこと（キー順・extension の並び順のみ差異）。
- 標準登録項目 105 件が漏れなく・重複なく含まれること、選択肢コードが項目内で
  一意であること。
- 上表の初期値式が fhirpath.js（本アプリと同じ実装）で意図した値を返すこと。
- 実機（回答フォーム・PDF 出力）での確認は未実施。
