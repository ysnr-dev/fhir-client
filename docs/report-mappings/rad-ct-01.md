# CT検査 特別指示テンプレート

放射線オーダーの GP 単位の欄「**特別指示**」に貼るテンプレート。CT は「撮影項目を選ぶだけでは
撮れない」検査で、造影の指示・前処置・搬送・読影の希望が毎回変わる。それを自由文で書くと
記載漏れと解釈違いが出るため、訊く項目を決めてテンプレートにした。

| ファイル | テンプレート | name / canonical |
|---|---|---|
| `rad-ct-01.questionnaire.json` | CT検査 特別指示 | `RAD_CT_01` / `http://fhir-client.local/Questionnaire/rad-ct-01\|1.0.0` |

レイアウト(`.tlf`)・マッピング定義は無し(帳票出力は対象外)。テンプレート一覧のインポートから
取り込む。カテゴリ **「検査」**(code `25675b10-0ef3-4425-83c4-c1f8c3015cca`)を拡張に持たせてある。

## 使い方: 放射線オーダーの「特別指示」に貼る

放射線オーダー画面(カルテ→放射線オーダー)の GP ごとの **特別指示** 欄で「テンプレート」を押し、
`検査` カテゴリから選ぶ。記入して反映すると、回答が平文になって特別指示欄に入る。

CT の撮影項目マスタ(`/rad-items` の編集モーダル「既定のテンプレート」→ 特別指示)にこの
テンプレートを設定しておけば、その項目を選んだ時点で選択済みになる。運用ではこちらを勧める
(依頼医がテンプレートを探さなくて済む)。

**記入しなかった項目は出力に現れない。** 当てはまる欄だけ埋めればよく、全部埋める前提の
帳票ではない。造影の欄と安全確認の欄は「造影あり」を選ぶまで表示されない。

出力例(造影腹部CT):

```
【撮影範囲・撮影条件】
  撮影範囲(開始): 横隔膜上
  撮影範囲(終了): 骨盤底
造影: 造影あり
  【造影の指示】
    撮影相: 単純(プレ)、動脈相、門脈相
    造影剤・ヨード濃度: イオパミロン300
    投与量: 100 mL
    注入速度: 3 mL/秒
    注入方法: インジェクタ使用、生食で後押し
    撮影開始のタイミング: bolus tracking
      【bolus tracking】
        監視ROIと閾値: 下行大動脈に ROI、100HU で開始
    投与経路・留置針: 右前腕 20G 留置済み
    【造影剤の安全確認】
      ヨード造影剤の副作用歴: なし
      eGFR: 68 mL/min/1.73m2
      eGFR の採血日: 2026-08-10
      ビグアナイド系(メトホルミン): 服用あり・休薬指示済
      造影剤使用の同意: 取得済
【前処置・患者準備】
  食事: 絶食
    【絶食】
      絶食の開始(検査の何時間前から): 6 時間前
  ルート確保: 病棟で確保
【患者状態・搬送】
  搬送方法: 車椅子
【読影・報告】
  読影: 至急読影
```

## 構成

| グループ | 項目 |
|---|---|
| 撮影範囲・撮影条件 | 撮影範囲(開始/終了) / 追加の再構成・後処理 / スライス厚・撮影条件の指定 / 装置・撮影室の指定 |
| 造影 (造影なし・造影あり) | ↓「造影あり」のときだけ開く |
| └ 造影の指示 | 撮影相(→遅延相なら注入後の分) / 造影剤・ヨード濃度 / 投与量 / 体重当たりの指示 / 注入速度 / 注入方法 / 撮影開始のタイミング(→固定delayなら秒、bolus tracking なら ROI と閾値) / 投与経路・留置針 / 併用薬の指示 / 撮影後の指示 |
| └└ 造影剤の安全確認 | ヨード造影剤の副作用歴 / 気管支喘息 / eGFR / eGFR の採血日 / 透析 / ビグアナイド系 / 妊娠の可能性 / 造影剤使用の同意 |
| 前処置・患者準備 | 食事(→絶食なら何時間前・飲水可否) / 休薬・当日内服の指示 / その他の前処置 / ルート確保 / 息止め |
| 患者状態・搬送 | 搬送方法 / 付き添い / 体重 / 意思疎通・体位保持 / 鎮静 / 体内金属・デバイス・ドレーン・酸素など / 体位・撮影の制限 / 感染対策の指定 |
| 読影・報告 | 読影 / 報告の希望日 / 比較したい過去検査 / 画像の出力 / 緊急時の連絡先 |
| (最後) | その他の申し送り |

- 各項目の意図は `designNote`(編集画面の「設計メモ」。回答フォームには出ない)に書いてある。
- 条件付きの枝は JASPEHR の制約(jsp-1 / jsp-9)どおり **選択肢項目の直下のグループ** で作って
  いる。造影の指示・安全確認は `造影 = 造影あり` の下、遅延相の分数は `撮影相` の遅延相の下、
  固定delay の秒数と bolus tracking の ROI は `撮影開始のタイミング` の下。
- **その他の申し送り**を最後に置いているのは、テンプレートから記載すると特別指示欄が直接編集
  不可になるため。自由文の逃げ場をテンプレート内に用意しておく必要がある。

## JJ1017 と重複させない線引き

撮影項目そのもの(モダリティ・手技・部位・左右・体位・入射方向)は項目マスタの 32桁コードが
持つので、テンプレートには置かない。テンプレートに入れたのは次の 3 種類。

1. **コードで表せないもの**: 造影剤の量・速度・撮影開始タイミング、搬送方法、患者状態、
   報告希望日。JJ1017 の詳細指示部にこれらに当たる要素は無い。
2. **コードでは 1 つしか持てないもの**: 別表6B(特殊指示)は 2桁 × 1 個で、「3D作成必要」と
   「心電図同期収集」と「空腹時実施」を同時に指定できない。項目マスタが 1 個を固定で持つ形
   でもあるので、依頼ごとに変わる後処理・前処置はテンプレート側で受ける。
3. **部位コードでは表せない範囲**: 部位(小部位)は 1 部位なので、「横隔膜上〜骨盤底」のような
   連続撮影の範囲は開始・終了のランドマークとして書く。

したがって「追加の再構成・後処理」は、項目の特殊指示に**含まれていない**ものを頼む欄になる。
項目側と二重に指定すると食い違うので、designNote にその旨を書いてある。

## 会計・保険区分を入れていない理由

保険/自費/健診の区分と加算(造影剤使用加算・冠動脈CT加算など)は、撮影する側への指示ではなく
会計側の属性で、算定はオーダーと実施記録から導く。特別指示の平文に混ぜると、算定の根拠が
自由文の中に埋もれてしまうため入れていない。

## 安全確認欄は暫定

`造影剤の安全確認` は依頼医が確認結果を書く欄として作ってある。本来はヨード造影剤の副作用歴
(AllergyIntolerance)・eGFR(検体検査結果)・メトホルミン(処方)・妊娠の可能性をカルテから
引いて、オーダー時に警告する方が確実で入力も要らない。その自動判定を実装したら、この
グループは「自動判定で拾えないもの(同意の取得、他院での副作用歴など)」だけに縮める。

## 項目コード(item.code)を入れていない理由

初期計画・家族歴と同じ理由。造影剤の注入速度や搬送方法に対応する確度の高い標準コードが
見当たらず、当てずっぽうのコードを入れる方が無コードより害が大きい。したがって「回答から
Observation を生成する」も無効のまま。

体重(`st-weight`)だけは LOINC 29463-7 があるが、体重はバイタル測定から Observation として
登録される値で、ここは「造影剤量を決めるために依頼時点で分かっている値」の転記にすぎない。
同じ意味のコードを付けて二重に Observation を作ると、どちらが測定値か分からなくなるため
付けていない。

## 将来の拡張

- MRI・血管撮影・核医学にも同じ考え方で別テンプレートを作れる。MRI は安全確認(体内金属・
  刺青・閉所恐怖)が主役になるので、CT の造影欄をそのまま流用はできない。
- 造影の指示値(造影剤・量・速度)は、実施入力の `MedicationAdministration`(実際に使った量)と
  対になる情報でもある。将来オーダー側に構造化して持たせるなら、この回答が移行元になる。
