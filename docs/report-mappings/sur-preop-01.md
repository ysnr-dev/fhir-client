# 術前指示テンプレート

手術オーダーの「**術前指示**」に貼るテンプレート。手術の申込内容(術式・麻酔・スタッフ)が
決まっても、病棟が手術前日〜当日に何をすればよいかは別に伝える必要がある。それを自由文で
書くと施設ごと・医師ごとに項目が抜け、絶飲食の開始時刻や抗血栓薬の休薬が伝わらないまま
当日を迎える(手術中止の主因)。訊く項目を決めてテンプレートにした。

| ファイル | テンプレート | name / canonical |
|---|---|---|
| `sur-preop-01.questionnaire.json` | 術前指示 | `SUR_PREOP_01` / `http://fhir-client.local/Questionnaire/sur-preop-01\|1.0.0` |

レイアウト(`.tlf`)・マッピング定義は無し(帳票出力は対象外)。テンプレート一覧のインポートから
取り込む。カテゴリ **「手術」**(code `9c4e1f37-8a52-4bd6-b071-3f8e2a5c9d14`)を拡張に持たせてある。

## 使い方: 手術オーダーの「術前指示」に貼る

手術申込フォーム(カルテ→手術)の **術前指示** 欄で「テンプレート」を押し、`手術` カテゴリから
選ぶ。記入して反映すると、回答が平文になって術前指示欄に入る。

術式マスタ(`/surgery-items` の編集モーダル「既定のテンプレート」→ 術前指示)にこのテンプレートを
設定しておけば、その術式を選んだ時点で選択済みになる。運用ではこちらを勧める(依頼医が
テンプレートを探さなくて済む)。既定は**主術式**の術式マスタから引く(1 オーダー = 1 手術で、
指示は手術全体に 1 つだから)。

**記入しなかった項目は出力に現れない。** 当てはまる欄だけ埋めればよく、全部埋める前提の
帳票ではない。条件付きの欄(休薬の内容・除毛の範囲 など)は、上の選択肢を選ぶまで表示されない。

出力例(腹腔鏡下胆嚢摘出術):

```
【絶飲食】
  固形物: 前日夕食後から絶食
  絶食の開始時刻: 前日21:00
  水分(清澄水): 手術2時間前まで可
【内服(休薬・当日内服)】
  抗血栓薬: 休薬を指示
    【抗血栓薬の指示】
      薬剤名: バイアスピリン 100mg
      最終内服日: 2026-08-22
      ヘパリン置換: なし
  当日朝に内服させる薬: アムロジピン 5mg(少量の水で)
【予防抗菌薬】
  予防抗菌薬: 必要
    【予防抗菌薬の指示】
      薬剤名・投与量: セファゾリン 2g
      初回投与: 執刀60分前
      投与場所: 手術室
      術中の追加投与: 3時間ごと
【術野・腸管の準備】
  除毛: 必要
    【除毛の指示】
      範囲: 臍周囲
      方法: 電動クリッパー
      実施の時期: 当日(手術室入室直前)
  前日の入浴・シャワー: シャワー
【病棟での準備】
  手術部位のマーキング: 不要
  末梢ルート: 病棟で確保
    【末梢ルートの指示】
      サイズ・部位: 右前腕 20G
  尿道カテーテル: 手術室で挿入
  静脈血栓塞栓症の予防: 弾性ストッキング、間欠的空気圧迫(IPC)
  入室前に外すもの: 義歯、装飾品、マニキュア・ジェルネイル
```

## 構成

| グループ | 項目 |
|---|---|
| 絶飲食 | 固形物 / 絶食の開始時刻 / 水分(清澄水) / 経口補水液の指示 |
| 内服(休薬・当日内服) | 抗血栓薬(→ 休薬なら薬剤名・最終内服日・ヘパリン置換) / 糖尿病薬 / 当日朝に内服させる薬 / その他の休薬 |
| 前投薬 | 前投薬(→ ありなら薬剤・投与時刻・経路) |
| 予防抗菌薬 | 予防抗菌薬(→ 必要なら薬剤・初回投与・投与場所・追加投与・アレルギー) |
| 術野・腸管の準備 | 除毛(→ 必要なら範囲・方法・時期) / 下剤(→ 薬剤・時刻) / 浣腸(→ 薬剤・時刻) / 前日の入浴 / 臍処置 |
| 病棟での準備 | マーキング / 末梢ルート(→ 病棟なら サイズ・部位) / 尿道カテーテル / 胃管 / VTE 予防 / 入室前に外すもの / 持参するもの |
| (最後) | 血糖・インスリンの指示 / 観察・報告の指示 / その他の指示 |

- 各項目の意図は `designNote`(編集画面の「設計メモ」。回答フォームには出ない)に書いてある。
  臨床上の理由(清澄水が 2 時間前まで可な理由、剃刀を使わない理由、SGLT2 阻害薬を早めに
  止める理由)はここに残してあり、指示を出す側が根拠を思い出せるようにしている。
- 条件付きの枝は JASPEHR の制約(jsp-1 / jsp-9)どおり **選択肢項目の直下のグループ** で
  作っている。
- ［実装］**下剤と浣腸は別々の選択肢**にした。1 つの選択肢に「下剤 + 浣腸」を混ぜると、
  併用を選んだときに開く枝が作れないため。
- ［実装］**絶食の開始時刻は枝の中ではなく常に出す**。「前日夕食後」「前日24時」の
  どれを選んでも具体的な時刻を足したいことがあり、枝にすると特定の選択肢でしか書けなくなる。
- **その他の指示**を最後に置いているのは、テンプレートから記載すると術前指示欄が直接編集
  不可になるため。自由文の逃げ場をテンプレート内に用意しておく必要がある(RAD_CT_01 と同じ)。

## 手術オーダーと重複させない線引き

手術そのものの内容は手術オーダーのヘッダが構造化して持つので、テンプレートには置かない。

| 手術オーダーが持つもの | ここに書かないこと |
|---|---|
| 術式・K コード・部位・左右・到達法(明細) | 手術の内容 |
| 麻酔方法・麻酔の管理区分(拡張) | 麻酔法の指定 |
| 手術体位・予定出血量・特殊機器(拡張) | 手術室側の準備 |
| 輸血準備(区分と単位数、拡張) | クロスマッチの指示 |
| 取得済み同意書(拡張) | 同意書のチェック |
| 特記・申し送り(`note`) | 手術部への申し送り |

テンプレートに入れたのは **「病棟が手術前日〜当日に実施する準備行為」だけ**。宛先が違う
(特記は手術部が読み、術前指示は病棟が読む)ので、欄も分けてある。

**予防抗菌薬は例外的に両方に出る**。実際の投与は注射オーダーで出し、実施記録も注射側に残る。
ここに書くのは「いつ・誰が投与するか」の段取りで、病棟が手術室へ送り出す前に投与するのか、
手術室で投与するのかを決めるためのもの。designNote にその旨を書いてある。

## ASA-PS・術前検査を入れていない理由

麻酔科の術前診察に属する評価(ASA-PS・気道評価)と、術前検査の指示(採血・心電図・胸部X線)は
入れていない。前者は麻酔科ワークフロー(`docs/surgery-order-design.md` で「今は持たない」と
決めたもの)の領分で、後者は検体検査・放射線オーダーとして出すもの。ここに書くと、オーダー
として出したのか指示を書いただけなのかが分からなくなる。

## 項目コード(item.code)を入れていない理由

CT特別指示・初期計画・家族歴と同じ理由。除毛の範囲や絶食の開始時刻に対応する確度の高い
標準コードが見当たらず、当てずっぽうのコードを入れる方が無コードより害が大きい。したがって
「回答から Observation を生成する」も無効のまま。

## 将来の拡張

- **チェックリスト化**: 今は主治医が書いた指示の平文で、病棟が実施したかどうかは残らない。
  実施の記録が要る運用になったら、各項目を Task にして病棟が消し込む形が要る。そのときは
  この回答が Task の生成元になる。
- **術式ごとのテンプレート分け**: 内視鏡の検査目的テンプレートが検査種別ごとに 4 本ある
  (`endoscopy-purpose.md`)のと同じく、大腸手術(腸管前処置が主役)・整形外科手術
  (抗血栓薬と部位マーキングが主役)で分けられる。術式マスタが 1 術式 1 テンプレートを
  持つ作りなので、テンプレートを足して割り当てるだけで足りる。
- **カルテからの自動取り込み**: 抗血栓薬・糖尿病薬の服用は処方から、アレルギーは
  AllergyIntolerance から引ける。`initialExpression`(`%prescriptions` / `%patient`)で
  初期値を出せば、休薬の指示忘れを減らせる。RAD_CT_01 の「安全確認欄は暫定」と同じ課題。
