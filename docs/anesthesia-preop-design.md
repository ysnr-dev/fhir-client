# 麻酔科術前診察の設計

`docs/functional-gap-backlog.md` §1 #14・§2.8 の「麻酔科術前診察ワークフロー」。手術の申込から麻酔記録までのあいだに
抜けていた、麻酔科医の評価と指示の記録を足す。

実装日: 2026-11-07。

- **［事実］** = FHIR R4・上流・このリポジトリの実装で確認した内容
- **［設計］** = 本ドキュメントの決めごと

## 1. 背景とスコープ

手術の申込は麻酔方法・管理区分を持つが、麻酔科医が患者を診て決めた評価(ASA-PS・気道)と指示は置き場が無かった。
麻酔記録 `SUR_ANES_01` と NCD の症例登録は ASA-PS を手で書き直しており、手術室と病棟には麻酔科の指示が届く経路が無かった。

含めるもの:

- 術前診察のテンプレート `SUR_ANESPRE_01`(評価・気道・手術室への指示・病棟への指示・説明)
- 手術オーダーと回答の結び付け、状況と評価を並べる一覧(部門業務 > 手術部門 > 麻酔科術前診察)
- 手術一覧の列とメニュー、手術カード・手術の詳細、麻酔チャートへの表示
- 麻酔記録・NCD 症例登録への ASA-PS の引き継ぎ

含めないもの(§7): 術前外来の予約枠、前投薬のオーダー化、看護ワークシートへの表示、術前診察が済んでいない手術の受付の制止。

## 2. データの持ち方

［設計］新しいリソースは作らない。術前診察は **QuestionnaireResponse 1 件 = 手術オーダー 1 件**。

| 要素 | 値 |
|---|---|
| `questionnaire` | 施設設定のテンプレートの canonical(既定 `SUR_ANESPRE_01`) |
| `subject` | 患者 |
| `basedOn` | **手術オーダーのヘッダ ServiceRequest**(実施記録がまだ無いので、NCD のように `partOf` で Procedure は指せない) |
| `status` | `in-progress`(記入中)/ `completed` `amended`(済) |

- ［事実］`QuestionnaireResponse.basedOn` は Reference(CarePlan | ServiceRequest)。上流は `based-on` 検索と
  `_revinclude=QuestionnaireResponse:based-on` に対応済みで、放射線治療の週次レビューと同じ持ち方。上流の変更は要らない。
- ［設計］**テンプレートは 1 本**。バックログの案は 3 本だったが、1 人が 1 回の診察で書くものなので、状態と記入者を 1 つにできる
  1 本にし、読む人ごとの区画はグループ(`grp-room` 手術室 / `grp-ward` 病棟)で分けた。
- ［設計］**読む側はテンプレートの url を見ず、`basedOn` で決める**(`anesthesiaPreopsByOrderId`)。施設設定でテンプレートを
  差し替えても過去の回答が読める。要点は linkId の約束で読むので、差し替えるテンプレートも次の linkId を持つ。

| linkId | 用途 |
|---|---|
| `anes_asa` `anes_asa-e` | ASA-PS(コード 1〜5)と緊急(yes / no) |
| `anes_nyha` `anes_mallampati` `anes_difficult-airway` | 一覧の列・手術カードの要点(`anes_difficult-airway` は yes / no) |
| `grp-room` | 手術室への指示。麻酔チャートと手術の詳細 |
| `grp-ward` | 病棟への指示。手術カードと手術の詳細 |

- ［設計］同じオーダーに回答が複数あるときは確定を優先し、同じ状態なら新しい方を採る(NCD と同じ)。誤記・中止の回答は数えない。

## 3. 書き始める

一覧の「記入」、手術一覧の行メニュー「術前診察」から、カルテを `?open=order-template:<オーダー id>@<テンプレートの url>` で開く。
右ペインの「テンプレート登録」にテンプレートを選択済み・`basedOn` を入れた状態で入る(NCD の `procedure-template` と同じ作り)。
記入中は編集の右ペイン、確定済みは回答の詳細を開く(`anesthesiaPreopKarteHref`)。

［設計］右ペインを使うのは、診察しながらカルテを読むため。カルテの「テンプレート」ボタンから直接書いた回答には `basedOn` が付かず、
手術には結び付かない。

初期値は手術予定日・予定術式・申込の麻酔方法(§6)、身長・体重・既往歴・アレルギー・内服薬。

## 4. 一覧(`/anesthesia-preop`、`pages/AnesthesiaPreopPage.tsx`)

- **対象**: 手術予定日が期間内(既定は今日から 14 日先まで)のオーダーと、日程未定のオーダー。中止は除く。
  並びは予定日時の順で、日程未定は末尾。
- **絞り込み**: 手術日、管理区分(既定は麻酔科管理)、麻酔科医、状況(未 / 記入中 / 済)。
  管理区分が空のオーダーは既定では出ないので、管理区分を「すべて」にして探す。
- **読み込み**: 手術一覧と同じ検索に `_revinclude=QuestionnaireResponse:based-on` を足した 1 本(`fetchSurgeryRows`)。
  行の予測困難気道「あり」は赤で出す。

## 5. 表示

| 場所 | 出すもの |
|---|---|
| 手術一覧の列「術前診察」 | 未 / 記入中 / ASA-PS。予定日別・日程未定の両方 |
| カルテの手術カード | 要点 1 行と病棟への指示の全文。術前指示と同じく畳まない |
| 手術の詳細 | 評価・手術室への指示・病棟への指示・診察日と記入者 |
| 麻酔チャート | 要点と手術室への指示の帯。予測困難気道ありなら赤い枠 |
| カルテの時系列 | 回答は診察した日のテンプレートカードとして残す |

- ［設計］他の手術の回答と違い、手術カードに畳み込まない。診察した日の記録として時系列で読めるようにする。
- ［事実］カルテのテンプレート回答は期間とページで区切って読むので、手術カードの回答はオーダーの検索に `_revinclude` で添える
  (`appendKarteOrderIncludes`)。
- ［設計］**術前診察が付いた手術オーダーはカルテから削除できない**(読影レポートと同じ)。回答が指す先が無くなるため。中止する。
  パスの取り消しによる削除はこの確認を通らない(§7)。

## 6. 初期値

変数一覧の「手術」に足した(`fhir/populateSurgery.ts`)。

| 変数 | 元 |
|---|---|
| `%plannedSurgeryDate` `%plannedProcedures` `%plannedAnesthesiaMethods` | 回答の `basedOn` が指す手術オーダー |
| `%preopAsa` `%preopAsaEmergency` | 対象の手術の申込を指す術前診察の回答(コード) |

- ［設計］既存の手術の変数は実施記録(ハブ Procedure)から読むので、手術の前には使えない。予定はオーダーから読む別の変数にした。
- `SUR_ANES_01` の `asa` `asa-e` と `NCD_CASE_01` の `ncd_asa` `ncd_asa-e` に `%preopAsa` `%preopAsaEmergency` を初期値として入れた。
  麻酔記録は患者の最新の手術、NCD は一覧から選んだ手術が対象。
- 麻酔法はオーダーとテンプレートで選択肢のコードが違うので、チェックボックスには流さず文字で見せる。

## 7. 申し送り

1. **術前診察の未了の扱い**: 手術一覧の列で見えるだけで、受付・入室は止めない。止めるなら `advisory-design.md` の器に載せる。
2. **前回の麻酔の引き継ぎ**: 前回の `SUR_ANES_01` の困難気道を麻酔歴の初期値にする変数は持っていない。
3. **病棟への指示の表示先**: 手術カードと詳細のみ。看護ワークシートと指示簿には出していない。前投薬もオーダーにはならない。
4. **パスの取り消し**: パスが発行した手術オーダーをまとめて消す経路は術前診察を確認しない。
5. **麻酔説明の同意**: 回答の「麻酔の説明」と申込の同意書の取得状況は連動しない。
6. **実装ガイド**: QuestionnaireResponse の `basedOn` の用途が増えた。`../fhir-ig` への反映は未実施。

## 8. 検証(開発環境、2026-11-07)

- 一覧の「記入」から右ペインが開き、予定・身体測定・既往歴・アレルギー・内服薬が初期値で入ること。保存した回答の `basedOn` が
  オーダーを指すこと。保存後の一覧・手術一覧・手術カード・手術の詳細・麻酔チャートに評価と指示が出ること。
- 記入中の回答が一覧で「記入中」になり、「開く」が編集を指すこと。行が無い手術の「記入」が `order-template` を指すこと。
- `SUR_ANES_01` と `NCD_CASE_01` の ASA-PS と緊急に、対象の手術の回答の値が入ること。
- 麻酔チャートの帯をライト・ダークで確認。`tsc -b`、lint、import 循環、`facility_settings_spec`。
