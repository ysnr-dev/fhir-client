# DPC 調査の D ファイル・入院 EF 統合ファイル(レセプト電算ファイルからの作成)

DPC 調査(退院患者調査)では、様式1(FF1。`docs/dpc-form1-design.md`)のほかに
**D ファイル(包括診療明細情報)**と**入院 EF 統合ファイル(出来高診療明細情報)**を提出する。
請求はレセコンが行うので、レセコンが出力した**レセプト電算処理ファイル(UKE)**を取り込み、
UKE に無い項目を上流 FHIR の入院・様式1 と突き合わせて補って、提出支援ツールに渡すファイルを作る。

調査日: 2026-10-10。**未実装**(設計のみ)。

- **［事実］** = 下記の仕様書、またはこのリポジトリ・上流の実装で確認した内容
- **［導出］** = 仕様・実装から論理的に導ける内容
- **［提案］** = 本ドキュメントの設計提案
- **［未確定］** = 仕様書に明記が無く、例示や他ファイルの規定からの読み。実装時に確かめる

---

## 1. スコープ

1. レセコンが出力した UKE を画面からアップロードし、レセプト単位の台帳として保存する
2. レセプトを上流の患者・入院・様式1 に突き合わせる。合わないものは画面で人が選び直す
3. 取込 1 件(診療月 1 か月分)から **D ファイル**と**入院 EF 統合ファイル**を出力する

読む UKE は**記録条件仕様どおりであればレセコンを問わない**。

- DPC レセプト(`RECEIPTD.UKE`。DPC レセプト・総括・総括対象 DPC・総括対象医科入院)
- 医科入院の出来高レセプト(`RECEIPTC.UKE`)。DPC 対象病院でも包括対象外の入院は出来高で請求され、
  D・EF の両方に載せる必要があるため

### 含めないもの

- **外来 EF 統合ファイル(EFg_)・H ファイル・様式4・K ファイル**。
- **請求そのもの**。点数の算定はレセコンの結果をそのまま使い、こちらで請求額を作り直さない
  (EF の出来高換算点数を除く。§5.4)。
- **レセコンとの直結**。UKE は人がアップロードする。日レセ API からの取得は日レセが DPC 請求を
  扱うようになってから検討する。
- **取込の非同期実行**。検査結果取込と同じく同期でよい(1 か月分で数百〜数千レセプト)。

## 3. UKE の読み方

### 3.1 ファイル

**［事実］** CSV(カンマ区切り)、Shift_JIS、1 行 1 レコード、改行 CRLF。先頭が IR(医療機関情報)、
末尾が GO(請求書)。末尾に EOF(0x1A)が付くことがある。

**［提案］** 文字コードは CP932 固定で読む(`LabImport::TextDecoder` の CP932 経路を使う)。
EOF は読み飛ばす。

### 3.2 レコードの並び

**［事実］** S2: DPC レセプト 1 件の並びは

    RE, HO, KO, (SN, JD, MF), GR, BU, SB, KK, SK, GA, HH, GT, SI/IY/TO/CO(出来高部分), SJ, CD

医科入院レセプト(S3)は RE, HO, KO, SY, SI/IY/TO/CO, … 。RE が来たら次のレセプトの始まり。

### 3.3 使うレコードと項目

| レコード | 項目(並び順) | 使い道 |
|---|---|---|
| IR | 審査支払機関, 都道府県, 点数表, 医療機関コード(7), 予備, 医療機関名称, 請求年月, マルチボリューム, 電話番号 | 施設コード(都道府県 2 + 医療機関コード 7)、請求年月 |
| RE | レセプト番号, レセプト種別, 診療年月, 氏名, 男女, 生年月日, 給付割合, 入院年月日, 病棟区分, 一部負担金区分, 特記事項, …, カルテ番号等, …, 診療科名, … | 患者の特定(カルテ番号)、レセプト種別、診療年月、病棟区分、レセプト科区分 |
| HO | 保険者番号(8、前スペース埋め), 記号, 番号, 診療実日数, 合計点数, … | 保険者番号 |
| GR | 医科点数表算定理由, DPC コード | D の 01 行(出来高の理由) |
| BU | 診断群分類番号(14), 今回入院年月日, 今回退院年月日, DPC 転帰区分, 死因 | 入退院日、分類番号 |
| KK | …, 前回退院日, 前回同一傷病, … | 7 日以内再入院の起算日 |
| GA | 診療年月, 請求調整区分, **外泊等(31 文字。1 文字が 1 日)**, 診断群分類番号, **医療機関別係数**, 翌月再入院予定 | 日ごとの在院・外泊、係数 |
| HH | 診療年月, 請求調整区分, 自他保険区分, 負担区分, 入院期間区分(1/2/3), **入院期間区分別点数(1 日あたり)**, 入院日数, 包括小計点数 | D の 93 行 |
| GT | 診療年月, 請求調整区分, …, 包括小計点数合算, 包括評価点数, **調整点数**, 今月包括合計点数, 診療識別(93), … | D の 94 行 |
| SI | 診療識別, 負担区分, 診療行為コード, 数量データ, 点数, 回数, (コメントコード, 文字データ)×3, **1〜31 日の回数** | 出来高部分の行為 |
| IY | 診療識別, 負担区分, 医薬品コード, 使用量, 点数, 回数, (コメント)×3, **1〜31 日** | 同(薬剤) |
| TO | 診療識別, 負担区分, 特定器材コード, 使用量, 点数, 回数, 単位コード, 単価, 予備, 商品名規格, (コメント)×3, **1〜31 日** | 同(材料) |
| CO | 診療識別, 負担区分, コメントコード, 文字データ | 退院時処方の判定 |
| CD | **実施年月日**, 診療識別, **順序番号**, **行為明細番号**, レセ電コード, 使用量, 数量データ, 単位コード, 回数 | EF(DPC 患者)の F 行 |

**［事実］**

- SI/IY/TO は**剤(算定単位)の最後のレコードにだけ点数**が入る。それより前のレコードは同じ剤の構成要素。
- **GA 外泊等**: 1 文字目が 1 日。`0` 通常、`9` 外泊、`8` 7 日以内再入院までの間、`7` 再転棟までの間、
  `3`〜`6` 地域包括ケア病棟関連。
- **請求調整区分**(GA/HH/GT): `1` 過去に請求済み、`2` 今月の請求、`3` 過去分の調整。
  月をまたぐ入院では、退院月に入院期間全体を再計算した結果が区分 1・3 として並ぶ。
- **CD には点数が無い**。また入院料・食事・生活療養・標準負担額は CD に含まれない。
- CD は S2 の表では「任意」の扱い。**［未確定］** DPC 病院のレセコンが実際に出力しているか。
  出していない UKE では EF(DPC 患者)を作れないので、取込時に「CD なし」を警告する。
- RE のカルテ番号等・診療科名は**任意項目**。

### 3.4 RE 病棟区分と EF/D の病棟区分

**［事実］** RE の病棟区分(別表 7: 01 精神、02 結核、07 療養 …、最大 4 つ)と、D/EF の病棟区分
(0 一般、1 一般以外、2 入院中の外来)は別のコード。
**［提案］** RE に 01/02/07 のいずれかがあれば 1、無ければ 0。入院中の外来(2)は §12 の後段。

### 4.2 行の種類と UKE からの組み立て

**［導出］** D は点数がすべてレセプトに載っているので、**UKE だけで行を作れる**(マスタでの計算が要らない)。
UKE に無いのはデータ識別番号・病棟コード・診療科区分・医師コード(・レセプト科区分)で、§6 で補う。

| データ区分 | 行 | UKE からの組み立て |
|---|---|---|
| 93 | 包括点数(在院日ごと) | 請求調整区分 2 の HH から入院期間区分ごとの 1 日点数を取り、GA 外泊等の `0` の日に順に割り当てる(期間Ⅰの日数ぶん → Ⅱ → Ⅲ)。外泊日(`9`)には行を作らない。回数 1 |
| 94 | 調整点数 | 請求調整区分 2 の GT 調整点数を、退院日に 1 行。未退院なら出さない |
| 01 | 出来高の理由 | GR があれば 1 行(810000001 / `GR0{理由}`、点数 0、回数 1)。理由 08〜11 は必須、01〜07 は任意 |
| 各診療識別 | 出来高部分(手術・麻酔・退院時処方・画像診断管理加算・病理診断料など) | DPC レセの SI/IY/TO を剤ごとに束ね、1〜31 日の回数がある日ごとに 1 行 |
| 92 | 特定入院料など | 同上(日ごとに 1 行) |

**［事実］** DPC で 0 点として包括される項目は出さなくてよい(0 点で出してもよい)。

**［未確定］**

- 外泊日の入院基本料減額(90)の行の符号と出し方。S1 の記載例から読み切れていない。
- GA 外泊等の `7`・`8`・`3`〜`6` の日の 93 行の扱い。

**［事実］** 7 日以内再入院・再転棟では、算定開始日と起算日は最初の入院日、終了日は最後の退院日(在院中は 00000000)。

### 4.3 順序番号

**［事実］**

- 順序番号は、データ識別番号 + 入院 + データ区分ごとに 0001 から振る。
- 実施日が違えば番号を分ける。
- 月をまたぐ入院は前月から続けるのが望ましいが、月ごとに振り直してもよい。
- D の番号は E/F と一致させなくてよい。

**［提案］** 月ごとに振り直す(前月の取込に依存しないため)。並びは実施年月日 → UKE の出現順。

### 5.2 E 行と F 行・点数の検算

**［事実］**

- **E 行の行為点数**: 剤の点数(手技 + 薬剤 + 材料)。DPC 患者は**出来高換算**の値。
- **F 行**: マスタの品目ごとに 1 行で、点数は品目ごとに持つ。
  - **% 加算・減算**(点数識別 5・6)の品目は、明細点数を 0 にし、加減の分は加算行の出来高実績点数に入れる。
  - **薬剤・材料の金額**は、計算単位の**最後の行**に載せる。
- **検算**(提出支援ツールが見る):
  - F の出来高実績点数の合計(行為明細区分情報 ②=0 かつ ⑥=0 の行)= E の行為点数
  - 薬剤行の合計 = 行為薬剤料
  - 材料行の合計 = 行為材料料
- **行為回数**: 同じ日の同じ行為は回数 1 にまとめる。分けられない場合だけ 2 以上。
- **円・点区分 1**: 食事(97)の E/F 行、金額(円)で持つ F 行、先進医療。

| ④ | 持参薬処方区分 | 0(後段) |
| ⑤ | DPC 適用区分 | 診療行為マスタ(`Master::MedicalProcedure` の DPC 適用区分)の値。薬剤・材料は 0 |
| ⑥ | 基本的検体検査実施料・基本的エックス線診断料に包括(1) | 診療行為マスタから判定できるものは 1、ほかは 0 |
| ⑦〜⑫ | 予備 | 0 |

### 5.4 DPC 患者の EF — CD から組み立てる

**［導出］** DPC レセプトの SI/IY/TO は**出来高部分だけ**で、包括部分の明細は CD にしか無い。
そこで DPC 患者の EF は CD から作る。CD の項目は EF の F 行にほぼ 1 対 1 で対応する:

- 実施年月日 → EF-24
- 診療識別 → EF-5
- 順序番号 → EF-6
- 行為明細番号 → EF-7
- コード → EF-9
- 使用量 → EF-12
- 回数 → EF-21

**CD には点数が無いので、出来高換算点数をマスタで計算する**(`PointCalculator`)。

| 種類 | 計算(［提案］) |
|---|---|
| 手技 | `Master::MedicalProcedure` の点数。点数識別 3(点数)はそのまま、5・6(% 加減算)は §5.2 のとおり、ほかの点数識別は 0 点にして警告 |
| 薬剤 | 同じ剤の薬剤の `Master::Medicine.price` × 使用量を合計し、15 円以下は 1 点、15 円を超える分は 10 円またはその端数ごとに 1 点を足す |
| 材料 | `Master::MedicalMaterial.price` × 使用量を合計し、10 円で割って四捨五入 |
| マスタに無いコード | 0 点にして警告 |

順序番号ごとに、F 行の合計から E 行(000)を作る。

**［未確定］** 計算に使うマスタの版。点数改定の月をまたいだ取込では、実施日に有効なマスタ行
(`valid_from` / `valid_to`)を使う必要がある。今のマスタは全件置き換えで旧版を持たないので、
改定月は警告を出し、旧版の点数は扱わない。

### 5.5 出来高レセプトの患者の EF — SI/IY/TO を日ごとに展開

**［導出］** 医科レセプトは点数がレセプトにあり、CD は無い。SI/IY/TO を剤(点数の付いた最終レコードまで)に束ね、
**1〜31 日の回数**がある日ごとに順序番号を 1 つ振って E 行と F 行を作る。

- E 行の行為点数は、レセプトの剤の点数。
- F 行の出来高実績点数は §5.4 と同じ計算で、剤の点数と合わなければ警告。

### 5.6 DPC 患者の入院料 — UKE だけでは作れない

**［事実］** EF は DPC 患者でも**出来高換算**で作り、包括される入院基本料・入院基本料等加算・個々の検査も出す
(行為明細区分情報 ② を 1 か 2 にし、出来高実績点数に出来高で算定した場合の点数を入れる)。
CD は入院料を含まないので、**UKE からは DPC 患者の入院料の行を作れない**。

**［提案］** 第 2 段階の後半で、病棟ごとに入院基本料・特定入院料のレセ電コードを施設設定に持ち、在院日ごとに
90/92 の行を生成する。入院期間に応じた加算(14 日以内加算など)の選び方もここで決める。
それまでは EF に入院料の行が無いことを取込画面に警告として出す。

## 6. FHIR との突合 — UKE に無い列を補う

**［事実］** 様式1 の施設コードは自院の保険医療機関番号 10 桁から点数表の桁を除いた 9 桁、
データ識別番号は患者番号の 10 桁前ゼロ埋め(`docs/dpc-form1-design.md` §2、`fhir/dpcForm1Draft.ts`)。
D・EF のデータ識別番号は様式1 と同じでなければならない。

**［提案］** レセプト 1 件を次の順で上流に当てる。

1. **患者**: RE カルテ番号 → Patient(identifier system `urn:oid:1.2.392.100495.20.3.51`)。
   カルテ番号が空なら氏名(カナ)と生年月日・性別で候補を出し、確定は人が行う。
2. **入院**: 患者の Encounter(class=IMP)で、入院日が BU 今回入院年月日(出来高レセは RE 入院年月日)と
   一致するもの。0 件なら `unmatched`、複数なら `ambiguous`。
3. **様式1**: 入院の QuestionnaireResponse(`DpcForm1Export::QUESTIONNAIRE_URL`)から dataId・施設コード・
   診療科コードを読む。無ければ dataId は患者番号の 10 桁前ゼロ埋めで作り、警告(様式1 未作成)。

上流への問い合わせは、取込 1 件の全レセプトをまとめて行う。患者はカンマ OR、入院と様式1 は
`_revinclude` で引き、レセプトごとの read は足さない。

補う列:

| 列 | 元(［提案］) |
|---|---|
| データ識別番号 | 様式1 の dataId |
| 病棟コード | Encounter.location の履歴(`period`)から実施日にいた病床 → 病棟 Location の identifier(無ければ id)。施設内で 10 桁以内に収まる値 |
| 医師コード | Encounter の主治医(participant type ATND)の Practitioner identifier(無ければ id)。実施日に主治医が替わっていれば実施日のもの |
| 診療科区分 | 様式1 の診療科コード(3 桁)。転科は様式1 の値しか持たないので、入院を通して同じ値(§12) |
| レセプト科区分 | RE 診療科名。無ければ空にして警告 |

**［提案］** 突合の状態は `matched` / `unmatched` / `ambiguous` / `manual`(人が選び直した)。
`matched` と `manual` 以外のレセプトは出力から除外し、件数を警告に出す。

## 12. 段階分け

**［提案］**

| 段階 | 内容 | 理由 |
|---|---|---|

## 14. 検証方法

- **rspec**
  - Parser: 手書きの UKE フィクスチャを読む
    - DPC: 7 日以内再入院を含む、外泊あり
    - 医科入院の出来高
    - 月遅れのレセプト
    - CD なし
  - DFileBuilder:
    - 93 行の数 = 在院日数 − 外泊日数
    - 94 行は退院日に 1 行
    - 01 行の有無
    - 前ゼロ・保険者番号の空白埋め
  - EfFileBuilder: 各順序番号で、F の出来高実績点数の合計 = E の行為点数
  - EncounterMatcher: FhirStore のスタブで matched / unmatched / ambiguous
  - request spec: 取込・再突合・手動指定・ファイル取得

  ```bash
  docker compose exec -e RAILS_ENV=test -e ADMIN_TOKEN= backend bundle exec rspec spec/services/uke_import spec/requests/master/receipt_imports_spec.rb
  ```

- **画面**
  - 開発環境の入院(テスト太郎・大腸太郎)に合わせて DPC の UKE を手書きし、取り込んで突合済みになることを確かめる。
  - D・EF をダウンロードして、列数・前ゼロ・Shift_JIS・CRLF を確かめる。
  - 日レセ(`../weborca-dev`)で入院出来高の RECEIPTC.UKE を作れればそれも取り込む。
- **提出支援ツール**: 使える環境があれば、出力した D・EF をツールに通してエラーが出ないことを確かめる
  (最終的な正否はツールのチェックで判断する)。
