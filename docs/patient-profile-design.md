# 患者プロファイル情報の設計(項目の検討)

**状態: 第 1 段階の一部を実装(2026-09-05)。** 診療上の注意(`Flag`)+注意区分マスタ+
カルテの「プロファイル」タブ(注意・基本情報・身体の区画)+患者帯のピクトグラム、
`Patient` の拡張(旧姓・通称名・死亡日・使用言語/通訳・連絡先・かかりつけ医)、
**血液型・妊娠/授乳**まで。残りの第 1 段階(感染症・読み取り専用の区画)と
第 2/3 段階は未着手(§5)。

「患者プロファイル」を **患者に紐づく「現在の状態」で、診療のたびに誰もが最初に見返すもの**
と定義し、項目・置き場所(FHIR リソース)・表示場所を整理する。
本文中の区別は他の設計書と同じ(［事実］/［導出］/［提案］)。

---

## 1. 既にある情報との線引き

［事実］患者に紐づく情報はすでに次の 4 経路に分かれて存在する。

| 経路 | 内容 | 置き場所 |
|---|---|---|
| 患者登録(`PatientForm`) | 患者番号・氏名・カナ・性別・生年月日・住所・電話・メール | `Patient` |
| 病名タブ | プロブレム・既往歴・保険病名 | `Condition`(区分) |
| アレルギータブ | J-FAGY コード付きアレルギー | `AllergyIntolerance` |
| 基礎データ(テンプレート) | 社会歴(喫煙・飲酒・職業・渡航歴)・家族歴・ROS | `QuestionnaireResponse` + 社会歴は `Observation` |

さらに身長・体重はバイタル(`Observation`)、血液型は輸血オーダー(`ServiceRequest`)にだけ載っている。

［導出］プロファイルは「新しい入力経路を増やす」より、**散らばっている「現在の状態」を
1 か所で読める画面**と、**まだ置き場所が無い項目の追加**の 2 つに分けて考える。
同じ情報を 2 経路に持たない(基礎データの既往歴を `Condition` 側に寄せたのと同じ方針)。

［導出］「時系列に積み上がるもの」はプロファイルに入れない。基礎データの回答は
タイムラインにカードとして積み上がる既知の制約があるが、プロファイルは **最新値だけを見る画面**
なので、積み上がる情報はそこから「最新値を引いて表示する」に留める。

### 1.1 整理の軸: 電子カルテ情報共有サービス(eCS)の 6 情報

［事実］eCS の共有対象は 傷病名・アレルギー・薬剤禁忌・感染症・検査結果・処方 の 6 つで、
このうち **薬剤禁忌と感染症** だけまだ登録経路が無い。薬剤禁忌は eCS 上
`AllergyIntolerance`(category=medication)で表し、感染症は検査結果の `Observation` で表す。

［導出］新設する項目は eCS の表現に合わせておくと、後で eCS 連携(診療情報提供)に
そのまま乗る。感染症を `Condition`(病名)で持つ選択肢もあるが、検査結果からの自動反映と
eCS の表現の両方で `Observation` の方が素直なので、Observation を採る(§3.3)。

## 2. 項目の候補と置き場所

### 2.1 基本情報の拡張(`Patient` の中で足せるもの)

| 項目 | 置き場所 | 用途 | 優先 |
|---|---|---|---|
| 旧姓・通称名 | `name`(use=maiden / nickname) | 保険証との照合・名寄せ | **実装済** |
| ローマ字氏名 | `name`(use=official, extension iso21090-EN-representation=ABC) | 外国人・パスポート照合 | 低 |
| 死亡日時 | `deceasedDateTime` | 一覧表示・死亡後のオーダー抑止 | **実装済**(表示のみ) |
| 使用言語・通訳要否 | `communication.language` / `preferred` | 外国人患者の受付・説明 | **実装済** |
| 緊急連絡先・キーパーソン・保証人 | `contact[]`(relationship / name / telecom / address) | 入院時・急変時 | **実装済** |
| かかりつけ医・紹介元 | `generalPractitioner`(Practitioner / Organization) | 連携先マスタ(既存)を参照 | **実装済** |
| 婚姻状況 | `maritalStatus` | ほぼ使わない | 低(見送り) |
| 職業 | — | **社会歴(MD0012810)に既にある**。二重化しない | 対象外 |

［事実］実装時の決定(2026-09-05):

- **旧姓の use は `maiden`**(FHIR の標準コード)。設計時に書いた `old` は「以前の名前」
  一般を指すコードで、旧姓に限らない。通称名は `nickname` の `text` に入れる。
- 旧姓・通称は漢字名・カナ名の**後ろ**に置く。上流は `use="official"` が無いとき
  先頭の `name` を検索用の family/given に採るため、本名を先頭に保つ必要がある。
- **連絡先は `Patient.contact`**。`name` が 0..1 でカナ名を別に持てないので、
  連絡先の氏名は漢字だけにした(本人の氏名は漢字・カナを別の `HumanName` に分ける)。
  カナが要るようになったら `RelatedPerson` に切り出す。
- 続柄は **v2-0131 の複数選択**(`C` 緊急連絡先 / `N` 近親者 / `BP` 支払・保証人 /
  `E` 勤務先 / `U` 不明)。「キーパーソン」に当たる単独のコードが無く、近親者かつ
  緊急連絡先のように重なるため。「長女」のような続柄の補足は標準コードで表せないので、
  コードを持たない `text` だけの concept として同じ `relationship` に添える。
- **死亡は `deceasedDateTime` だけを使う**(`deceasedBoolean` と併記すると上流が弾く)。
  死亡後のオーダー抑止は入れていない(表示のみ。抑止は各オーダー画面の判断)。
- 通訳要否は `communication.preferred`。言語が未指定でも通訳の印だけを残せるよう、
  その場合の `language` は `und`(不明)にする(`communication.language` は 1..1 のため)。

［導出］連絡先は `RelatedPerson` リソースを立てず `Patient.contact` で持つ。続柄・氏名・電話
だけで足り、本人と同じ画面で編集できる方が窓口の手間が少ない。`RelatedPerson` は
「代理入力する家族がログインする」ような要件が出たときに切り出す。

［事実］新患登録(`validateNewPatientForm`)は氏名・カナ・性別・生年月日だけを必須にしている。
上の項目はすべて任意で、患者登録画面から後で埋める。

### 2.2 診療上の注意(アラート)

［提案］`Flag` リソースを新設し、**注意区分マスタ**(backend)でコードを管理する。

| 区分(category) | 例 |
|---|---|
| 安全(safety) | 転倒リスク・暴力/粗暴歴・離院リスク・自殺念慮 |
| 臨床(clinical) | ペースメーカー等の体内金属(MRI 禁忌)・造影剤注意・抗凝固薬内服・認知症/せん妄・視覚/聴覚障害・車椅子 |
| 意思(advance-directive) | DNAR・輸血拒否(宗教上)・病名告知の制限 |
| 事務(administrative) | 未収金・同姓同名注意・要配慮(職員・個人情報制限) |

```text
Flag
  status   = active / inactive
  category = 上の区分(ローカル CodeSystem)
  code     = 注意区分マスタのコード + 自由記載(text)
  subject  = Patient
  period   = 開始日 〜 終了日(任意。妊娠のような時限の注意に使う)
  author   = 登録者(Practitioner)
```

注意区分マスタの列: コード / 表示名 / 区分 / **ピクトグラム** / 並び順。
ピクトグラムは固定セット(§4.2)からの選択式で、**空なら帯に出さない**(常設帯に全部を出すと
溢れるため。「帯に出すか」の真偽値を別に持たず、アイコンの有無で兼ねる)。

［導出］「輸血拒否」「DNAR」は本来 `Consent` の領域だが、最初は Flag で「注意として見せる」
ことに留める。同意書そのものの管理(§2.6)は別段階。

### 2.3 身体の基本値

| 項目 | 置き場所 | 備考 |
|---|---|---|
| 血液型(ABO / RhD) | `Observation`(LOINC 883-9 ABO / 10331-7 Rh) | **実装済**。輸血オーダーの初期値にする。情報源は `method` で区別 |
| 身長・体重・BMI | バイタルの `Observation` の最新値 | **表示のみ**。測定日を併記(小児は変わる) |
| 妊娠・授乳 | `Observation`(LOINC 82810-3 妊娠状態 / 63895-7 授乳状態) | **実装済**。処方・放射線検査の注意に使う。Flag ではなく Observation にするのは「いつ確認したか」が要るため |
| 腎機能(eGFR / CCr) | 検査結果の最新値 | **表示のみ**。薬剤の用量調整の参考 |

［事実］血液型は以前、輸血オーダーに「何型を出すか」として載っているだけで、患者側には無かった
(`transfusionOrderHelpers.ts` の設計)。オーダーごとに手入力しており、患者の血液型を
プロファイルに持てばそこから初期値を引ける。オーダー側の項目は残す(確定した型を出す依頼の
中身なので、プロファイルと食い違いうる)。

［事実］実装時の決定(2026-09-05):

- **ABO と RhD は Observation を 1 件ずつ分ける**。LOINC も別項目で、「ABO は分かっているが
  RhD はこれから」がありうるため(輸血オーダーが拡張を 2 つに分けているのと同じ理由)。
  保存は片方だけ書かれる状態を作らないよう transaction でまとめて送る。
- **コードの値集合は輸血オーダーと共有**(`ABO_SYSTEM` / `RHD_SYSTEM`)。同じ「A 型」を
  2 か所で別のコードにしないため。
- **情報源は `Observation.method`**(検査確定 / 本人・家族の申告 / 他院からの情報)。
  申告のままの型で製剤は出せないので、値と並べて必ず出す(検査確定でなければ「検査未確定」の印)。
- **輸血オーダーの初期値に入れるのは検査確定の型だけ**。申告値を黙って入れると、その型で
  製剤が払い出されうるため。申告値は参照として並べるに留める。初期値を入れるのは新規登録の
  ときだけで(`prefillBloodType`)、編集や DO で写った型は上書きしない。
- **患者の型とオーダーの型が食い違うときは赤字で知らせる**。選択は妨げない(意図して別の型を
  出すことがあるため)。

［事実］妊娠・授乳の実装時の決定(2026-09-05):

- **妊娠状態と授乳状態も Observation を 1 件ずつ分ける**(LOINC が別項目で、妊娠していないが
  授乳中という状態がありうる)。作りは血液型と同じで、保存は transaction。
- 値は **SNOMED CT**(妊娠中 77386006 / 妊娠していない 60001007 / 不明 261665006、
  授乳中 413712001 / 授乳していない 169750002)。LOINC 82810-3 の推奨値集合に合わせた。
  「不明」を残すのは、確認したが分からなかったことと、まだ聞いていないこと
  (Observation 自体が無い)を区別するため。
- `category` は **survey**。問診・観察で得る情報で、検体検査の結果一覧に混ざらないようにする。
- **分娩予定日は妊娠状態の component**(LOINC 11778-8)。妊娠中のときだけ入力欄を出し、
  他の状態を選んだときは保存しない。
- **確認日は必須**。いつ時点の状態かが分からないと使えないため(状態が変わる情報なので、
  画面は常に確認日の新しいものを出す)。
- **処方・放射線検査のオーダー画面に注意を出す**(`PregnancyNotice`)。妊娠中・授乳中の
  ときだけ出し、そうでなければ何も出さない(常に出すと読み飛ばされる)。オーダーは妨げない
  (妊婦にも必要な検査・薬はあり、判断は医師のもの)。

### 2.4 感染症

| 項目 | 内容 |
|---|---|
| 種類 | HBs 抗原 / HCV 抗体 / HIV / 梅毒(TPHA・RPR)/ HTLV-1 / MRSA / 結核 / その他(自由記載) |
| 結果 | 陽性 / 陰性 / 未検 |
| 確認日 | 検査日または申告日 |
| 情報源 | 検査結果(自動) / 本人申告・他院情報(手入力) |

［提案］置き場所は `Observation`。検査結果(検体検査の `Observation`)が入れば自動で反映し、
検査していない項目は手入力の `Observation` を作る。両方あるときは検査結果を優先し、
確認日の新しい方を出す。

- 検査項目マスタ側に「感染症の種類」を対応づける列を足す(どの検査項目が HBs 抗原かを
  マスタで決める)。
- 手入力分は `category=laboratory` ではなく `category=exam`(または `survey`)にして、
  検査結果と混ざらないようにする。

### 2.5 生活・社会的情報

| 項目 | 置き場所 | 扱い |
|---|---|---|
| 喫煙・飲酒 | 社会歴の `Observation` 最新値 | **表示のみ**(基礎データが本体) |
| 同居家族・家族構成 | 家族歴テンプレート | **表示のみ**。連絡先とは分ける |
| 介護保険(要介護度)・障害者手帳・難病/公費 | `Coverage`(§2.6)または `Patient` 拡張 | 保険と一緒に第 2 段階 |
| ADL | 看護側の評価 | **対象外**(看護記録の領域) |
| 宗教 | `Patient` 拡張(patient-religion) | 輸血拒否は Flag。宗教自体は食事の禁忌(ハラル等)が要件になったとき |

### 2.6 保険・公費(`Coverage`)と同意(`Consent`)

| 項目 | 内容 |
|---|---|
| 保険 | 保険種別・保険者番号・記号/番号/枝番・本人家族・負担割合・有効期間・限度額認定 |
| 公費 | 法別番号・受給者番号・負担上限 |
| 同意 | 輸血同意/拒否・ACP/DNAR・臓器提供・病名告知の範囲・個人情報の第三者提供(eCS 同意) |

［導出］保険はレセプトと不可分で、資格確認(オンライン資格確認)の要件も絡むため、
プロファイル画面では **登録済み保険の要約表示**に留め、登録・編集は別の設計書に切り出す。
JP Core には `JP_Coverage` があるので表現はそれに合わせる。同意も同様に第 3 段階とし、
それまでは Flag と診療記録で代替する。

## 3. FHIR の構造(まとめ)

```text
Patient                     基本情報 + contact(連絡先) + communication + deceased + generalPractitioner
  ←subject── Flag           診療上の注意(注意区分マスタ)
  ←subject── Observation    血液型 / 妊娠・授乳 / 感染症(手入力分)
  ←subject── Observation    身長・体重・腎機能・社会歴(既存。最新値を引くだけ)
  ←patient── AllergyIntolerance(既存)   ※薬剤禁忌は category=medication で表せる
  ←subject── Condition(既存)
  ←beneficiary── Coverage   保険・公費(第 2 段階)
  ←patient── Consent        同意(第 3 段階)
```

［事実］**`Flag` は上流に実装済み(2026-09-05)**。JP Core に Flag のプロファイルが無いため、
`Group` と同じく HL7 の基本定義(`http://hl7.org/fhir/StructureDefinition/Flag`)で登録し、
手書きの `FlagValidator` だけで検証する。検索は `status` / `category` / `code` /
`subject`(別名 `patient`)/ `encounter` / `author` / `date`(period)。`subject` が
Patient を指す単一列参照なので、患者コンパートメント(`Patient/$everything`)にも自動で入る。

［要確認］`Coverage` / `Consent` の扱いは未確認(それぞれ第 2 / 第 3 段階で確認する)。

## 4. 画面

### 4.1 カルテの「プロファイル」タブ

［提案］`KARTE_OTHER_TABS` に「プロファイル」を足す。時系列ではなく **区画ごとの最新値**。

| 区画 | 内容 | 編集 |
|---|---|---|
| 基本 | 氏名・カナ・旧姓・通称名・性別・生年月日(年齢)・死亡・言語 | タブ内で編集(**実装済**) |
| 連絡先 | 住所・電話・緊急連絡先・キーパーソン | タブ内で編集(**実装済**) |
| 注意 | Flag の一覧(区分ごと) | **ここで追加・終了** |
| 身体 | 血液型・身長/体重(測定日)・妊娠/授乳・腎機能 | 血液型・妊娠/授乳はタブ内で編集(**実装済**)。身長体重はバイタルへ |
| 感染症 | 種類 × 結果 × 確認日 × 情報源 | 手入力分はここで |
| アレルギー・薬剤禁忌 | 最新の一覧(要約) | アレルギータブへ |
| 生活 | 喫煙・飲酒・職業(社会歴の最新値) | 基礎データへ |
| かかりつけ・紹介元 | generalPractitioner | タブ内で編集(**実装済**) |
| 保険 | 要約(第 2 段階) | — |

［導出］編集先が散らばるのは、各情報の本体を動かさない方針(§1)の帰結。

［事実］ただし **`Patient` 本体の編集(基本・連絡先・かかりつけ)は、患者編集画面へ遷移せず
タブの中で開く**(2026-09-05)。別ページへ飛ぶとカルテに戻る手段が無く、見ていた場所を
見失うため。フォームは患者登録・編集画面と同じ `PatientForm` を使い、楽観ロックと競合時の
扱いも同じ。他の区画(バイタル・基礎データなど)は本体の画面へ送る。

### 4.2 患者帯(`PatientHeader`)

［事実］帯は患者番号・氏名・カナ・生年月日・性別・入院先の 1 行で、常設帯に行を増やさない
ルールがある。既存画面のアイコンはライブラリを使わず手書きのインライン SVG
(`KarteSidePane.tsx` などの 16px `viewBox="0 0 16 16"`)。

［提案］帯には **文字のバッジではなくピクトグラムのアイコン**を並べる。文言を出さないので
1 行に収まり、離れた席からでも「何に気を付ける患者か」が形で分かる。

**アイコンの出どころ**

| 情報 | アイコン | 出す条件 |
|---|---|---|
| 診療上の注意(Flag) | 注意区分マスタで選んだピクトグラム | status=active で、マスタにピクトグラムが付いている |
| アレルギー | 固定(注射器 + 禁止記号) | active な `AllergyIntolerance` が 1 件以上 |
| 薬剤禁忌 | 固定(錠剤 + 禁止記号) | category=medication のアレルギーが 1 件以上(アレルギーと別に出す) |
| 感染症 | 固定(バイオハザード) | いずれかの種類が陽性 |
| 妊娠・授乳 | 固定(妊婦) | 妊娠状態の Observation が有効期間内 |
| 血液型 | 固定(血液滴の中に型を文字で入れる。例「A+」) | 血液型の Observation がある |

**ピクトグラムの固定セット**(注意区分マスタの選択肢。初期案)

| キー | 図柄 | 想定する注意 |
|---|---|---|
| `fall` | 転倒する人 | 転倒リスク |
| `wheelchair` | 車椅子 | 車椅子・移動介助 |
| `hearing` | 耳 + 斜線 | 聴覚障害 |
| `vision` | 目 + 斜線 | 視覚障害 |
| `cognition` | 頭部 + 渦 | 認知症・せん妄 |
| `implant` | 磁石 + 禁止記号 | 体内金属・ペースメーカー(MRI 禁忌) |
| `contrast` | 点滴 + 感嘆符 | 造影剤注意 |
| `anticoagulant` | 血液滴 + 時計 | 抗凝固薬内服 |
| `dnar` | 心電図波形 + 斜線 | DNAR |
| `no-transfusion` | 輸血バッグ + 禁止記号 | 輸血拒否 |
| `violence` | 手のひら | 暴力・粗暴歴 |
| `elopement` | 開いたドア + 人 | 離院リスク |
| `unpaid` | 硬貨 + 感嘆符 | 未収金 |
| `privacy` | 鍵 | 要配慮(個人情報制限・職員) |
| `alert` | 三角の感嘆符 | 上のどれにも当たらない注意(汎用) |

- 図柄は 1 色の線画で統一し、色は区分ごと(安全=赤 / 臨床=橙 / 意思=紫 / 事務=灰)に
  分ける。固定アイコン(アレルギー・感染症など)は臨床の色。
- **ホバーで表示名と内容**(Flag の text)をツールチップで出す。`aria-label` にも同じ文言を
  入れ、`title` 属性で代用しない(スクリーンリーダーと自動化で読めるようにするため)。
- **クリックでプロファイルタブ**へ飛ぶ(該当区画までスクロール)。
- 同じピクトグラムの Flag が複数あれば 1 つにまとめ、右肩に件数を添える。並びはマスタの順。
- マスタに無いキーが来たら `alert` にフォールバックし、黙って消さない。
- 高さは帯の文字行高に合わせ(16px)、帯の高さを変えない。

［事実］実装時の決定(2026-09-05):

- **ツールチップはネイティブの `title`**(同じ文言を `aria-label` にも入れる)。専用の
  吹き出し部品は作らない。既存画面のアイコンボタンと同じ流儀で、部品を増やさずに済むため。
- SVG は **1 モジュール** `frontend/src/components/icons/cautionPictograms.tsx` に
  キーの一覧・図柄の説明・描画をまとめた。キーごとにファイルを分けると、選択肢の一覧と
  未知キーのフォールバックのためにどのみち一覧が要るため。注意区分マスタの選択肢は
  このキー一覧から作る。backend にも同じ一覧を検証用に持つ(打ち間違いを弾くためで、
  正は TS 側。両方のファイルにその旨を書いてある)。
- 帯に出すかどうかは**マスタの `pictogram` が空かどうか**で決める(真偽値の列は持たない)。
- マスタに無いコードの注意は帯に出さない(プロファイルタブには出る)。マスタにあるが
  未知のキーが入っている場合は汎用の三角(`alert`)で描く。

## 6. 見送った項目と理由

- **職業・喫煙・飲酒・渡航歴**: 社会歴テンプレートが本体。表示のみ。
- **既往歴**: 病名タブの区分が本体(`docs/report-mappings/basic-data.md`)。
- **身長・体重**: バイタルが本体。表示のみ。
- **ADL・褥瘡リスク**: 看護評価の領域で、看護記録側で扱う。
- **婚姻状況・宗教(単独)**: 使い道が具体化していない。要件が出たときに `Patient` 側に足す。
