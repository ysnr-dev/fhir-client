# DPC 診断群分類(14 桁)のコーディング

入院 1 件ごとに、診断群分類(DPC コード 14 桁)を判定して決める。カルテ右ペインの「DPC」の
「診断群分類」タブで判定・上書き・決定し、データ > DPC患者(`/dpc-patients`)で入院を横断して
決定の状況と期間Ⅱの超過を見る。様式1 は `docs/dpc-form1-design.md`。

- **［事実］** = 令和8年度版の DPC 電子点数表・ツリー図、留意事項通知(令和8年3月18日 保医発0318第4号)、
  疑義解釈、このリポジトリで確かめた内容
- **［推測・要確認］** = 配布資料に明記が無く、表の並びからの読み。spec で固定してあり、資料で確かめたら直す

## 1. 範囲

- 14 桁の判定(医療資源病名 → 上 6 桁 → 分岐ごとの値 → 変換テーブル)、同じ分類の候補と点数・推定包括額、
  決定の記録(DPC 歴)、DPC 患者一覧。
- **包括請求は対象外**(日レセへの送信・EF ファイル・包括/出来高の振り分け)。日レセ連携は外来だけ
  (`docs/receipt-billing-design.md` §6)。
- 決定の承認(医師が決め、医事が承認する二段階)は持たない。決定者と日時だけを残す。

## 2. マスタ(DPC 電子点数表)

厚生労働省の DPC 電子点数表(Excel)を、マスタ取込の「DPC 電子点数表」で**全シートまとめて**取り込む
(`MasterImport::DpcTableImporter`)。

| シート | テーブル | 中身 |
|---|---|---|
| １）ＭＤＣ名称・２）分類名称 | `master_dpc_classifications` | MDC(2 桁)・分類(6 桁)の名称 |
| ３）病態等分類・５）年齢、出生時体重等・10－1〜10－4）重症度等 | `master_dpc_conditions` | 条件区分ごとの範囲(以上〜未満)・選択肢・区分 |
| ４）ＩＣＤ | `master_dpc_icd_codes`(既存) | ICD-10 → 上 6 桁 |
| ６）手術 | `master_dpc_surgeries` | 手術フラグ・対応コード・手術1〜5 の点数表コード |
| ７）手術・処置等１・８）手術・処置等２ | `master_dpc_procedures` | 処置フラグ・対応コード・手術との組み合わせ条件・コード |
| ９）定義副傷病名 | `master_dpc_comorbidities` | 副傷病フラグ(1 共通 / 2 手術なし / 3 手術あり)と ICD |
| 11）診断群分類点数表 | `master_dpc_points` | 入院日Ⅰ〜Ⅲ・点数(「-」と空欄は null) |
| 12）変換テーブル | `master_dpc_conversions` | 分岐の値の組 → 14 桁・包括フラグ(分岐は jsonb) |
| 13)出来高算定手術等コード | `master_dpc_fee_for_service_codes` | 手術・検査・患者・薬剤の区分ごと |
| 14）CCPM対応 | `master_dpc_ccpms` | 14 桁 → CCPM 支払分類 |
| ダミーコード一覧 | `master_dpc_dummy_codes` | 化学療法・全身麻酔などの区分、薬剤の組 |

- **版**(`edition`)は改定の開始日(１）の有効期間開始日の最小値、令和8年度版は `20260601`)。取込は**同じ版の
  行だけ**を入れ替え、別の版は残す(改定をまたぐ入院を退院日の版で判定するため)。取り込んだ版は
  `master_dpc_editions` に件数と一緒に残し、マスタメンテ > DPC > DPC 電子点数表(`/dpc-tables`)で見る。
- 版の中でも行ごとに有効期間が違う(月々の見直しで足された行。令和8年度版は 20260715 の追加あり)。
  基準日の版のうち、基準日に有効な行だけを使う(`Master::DpcEditionScoped#in_edition`)。
- 列の位置は前提条件シートの書式に従って決め打ちし、変更区分・有効期間の列と変換テーブルの分岐の列だけは
  見出しから引く(見出しが変われば取込を止める)。11）は B 列から始まるので、表の左端からの列番号で扱う。
- 件数(令和8年度版): MDC 18 / 分類 504 / ICD 5,898 / 手術 8,621 / 処置等1 2,943 / 処置等2 2,778 /
  副傷病 1,376 / 重症度等 232 / 点数表 3,267 / 変換テーブル 9,248。
- spec の fixture(`backend/spec/fixtures/files/dpc_tables_sample.xlsx`)は実ファイルからいくつかの分類だけを
  抜き出したもの。作り直すときは `backend/script/make_dpc_tables_sample.rb`(roo で読み、rubyzip で書く)。

## 3. 判定(`backend/app/services/dpc/`)

`Dpc::Grouper` は DB の表(`Dpc::Tables`)と入力(`Dpc::Input`)だけで決める(FHIR を触らない)。

1. 医療資源病名の ICD-10 → 上 6 桁(４）。基準日の版で引く)。
2. その分類の変換テーブルで値を持つ分岐を並べる。全行が「a」の分岐は対象外。
3. 分岐ごとに自動の値と根拠を決める(下表)。人の上書きがあればそれを使い、自動の値も返す。
4. 変換テーブルと照合する。「a」・空欄・値の決まらない分岐は問わない。当たった 14 桁が 1 つなら確定、
   複数なら候補として返す。
   - ［事実］「a」と空欄を問わないと読めば、同じ分類で 2 行に同時に当たる組は無い(全行で確認)。
   - ［事実］14 桁の「x」(分岐しない桁)は、変換テーブルでは値ごとの行に展開されている。

| 分岐 | 自動の値の元 |
|---|---|
| 病態等(肺炎) | 年齢と、様式1 の肺炎の重症度分類の院内/市中(3/5/8) |
| 年齢・出生時体重等 | 入院時の満年齢・月齢、様式1 の JCS・出生時体重・Burn Index・GAF・妊娠週数・分娩時出血量 |
| 手術 | 実施した点数表コードがすべてそろう行のうち**対応コードが最小**(97 は個別の値より後)。定義に無い手術の K コードだけなら 97、無ければ 99 |
| 手術・処置等1 | そろう行(手術との組み合わせ条件の手術も実施)のうち**対応コードが最大** |
| 手術・処置等2 | 同じく対応コードが最大。薬剤・ダミーコードは §4 |
| 定義副傷病 | 様式1 の併存症・続発症の ICD-10(フラグ 2 は手術なし、3 は手術ありのときだけ数える)。当たる病名が複数なら対応コードが最大 |
| 重症度等 | 10－1 年齢・JCS、10－2 片眼/両眼・片側/両側・一側/両側(様式1 の手術側数が左右)・初回/再手術(手術回数)・リハビリ(実施記録)・転院(入院経路 4)、10－3 急性膵炎(予後因子 A の範囲で条件区分 9/10、造影 CT の B で値)、10－4 脳卒中の発症時期・A-DROP・Child-Pugh の合計点 |

- ［事実］複数の値に当たるときは、手術・手術・処置等1・2・定義副傷病のどれも「ツリー図で下に掲げる
  DPC コードを優先」(留意事項通知 第2の1(5))。令和8年度版のツリー図では全分類で、上から手術が
  99 → 97 → 値の大きい順 → 01、処置等1・2・定義副傷病が値の小さい順(0〜9 の後に A〜E)に並ぶので、
  対応コードの大小で選ぶ。手術フラグ・処置フラグは定義テーブルの行の番号で、ツリー図の並びとは一致しない
  (例: 010060 は手術フラグ 01 が対応コード 02、フラグ 03 が 01)。
- ［事実］手術あり・なしの「手術」は医科点数表 第10部 手術(K000〜K939)のうち、手術等管理料(第13款。
  マスタでは K914〜K917 の各管理料)と輸血管理料(K920-2)を除いたもの(留意事項通知 第2の3(8)、
  疑義解釈 問3-2-4・3-2-5)。輸血だけでも「手術あり」。
- ［事実］年齢は診断群分類区分が適用される入院時の年齢(同 第2の3(3))。A-DROP の年齢の点は男性 70 歳以上・
  女性 75 歳以上(同 第2の3(15)、実施説明資料 M040020)。
- 包括の対象外になる手術・検査(13）を実施していれば警告する(包括/出来高の振り分けはしない)。

## 4. 実施記録・薬剤・ダミーコード

**実施記録**(`Dpc::PerformedItems`): 入院日〜基準日の Procedure を患者 + 日付で 1 本の検索で引き、
`_revinclude` で子の手技と MedicationAdministration を添える。

- 手技は診療行為コード(`…/CodeSystem/{種別}-procedure-code`)を `Master::MedicalProcedure#k_code` で
  点数表コード(`K6722` / `J0451` / `G005` / `J0453ｲ`)に引き直す。電子点数表の表記と一致するので正規化しない。
- 注射の手技が中心静脈(JAMI 31)なら `G005`。放射線治療・リハビリは診療行為コードを持たないので
  「実施あり」の印だけにする。麻酔チャートの薬剤は数えない。
- 様式1 の手術情報(点数表コード)も手術の根拠にする。人工呼吸(J045)の実施記録を作る機能は無いので、
  画面の「コード」から足す。

**薬剤**(`Dpc::DrugMatcher`): 点数表の薬剤(4 桁の独自コード + 一般名)と医薬品コードの対応表は配布されて
いないので、投与した薬剤の一般名・基本名称・名称に点数表の名前が含まれるかで**候補**を出す。塩・水和物を
外した名前、名前で当たった薬と YJ 先頭 7 桁が同じ薬も候補にする(先発の商品名を拾うため)。但し書きのうち
「注射薬に限る」「内服薬」「外用薬を除く」は剤形で絞り、それ以外は注記に残す。

**ダミーコード**(`Dpc::DummyRules`):

| コード | 導き方 |
|---|---|
| 0006 全身麻酔 | L008 の実施 |
| 0007 リハビリテーション | H 章の実施、またはリハビリの実施記録 |
| 0008 放射線療法 | M 章の実施、または放射線治療の実施記録 |
| 0014 精神科専門療法 | I 章の実施 |
| 0005 化学療法 | YJ の先頭が 42(腫瘍用薬)の投与 → 候補 |
| 0046〜0048 | 化学療法・放射線療法の有無の組 |
| 「A＋Bあり」「AありかつBあり」 | 構成する薬剤・療法がすべて採用済み |
| それ以外(酵素補充療法・大量療法・加算など) | 人が「コード」から足す |

- 候補(`suggested`)は判定には仮に数え、**確定・除外するまで決定できない**。除外したコードは実施記録に
  あっても数えない。
- ［事実］「化学療法」は悪性腫瘍に対する抗腫瘍用薬・ホルモン療法・免疫療法等の抗腫瘍効果を有する薬剤の
  使用で、当該入院中に処方されたものに限り、手術中の使用と外来・退院時の処方を含まない。抗生剤・G-CSF・
  鎮吐剤のみは含まない(留意事項通知 第2の3(5)①)。抗腫瘍効果を目的とした使用に限る(疑義解釈 問3-3-9)。
  使用の目的は記録から分からないので、0005 は腫瘍用薬(YJ 42)の投与から**候補**として出し、人が確定する。
  YJ 42 以外のホルモン療法の薬(LH-RH 誘導体など)は候補に出ないので人が足す。
- ［事実］手術の実施記録の薬剤(手術中の使用)は、化学療法にも薬剤名の分岐にも数えない(疑義解釈 問3-3-6・
  3-3-7)。投与の実施記録(MedicationAdministration)だけを見るので、外来・退院時の処方は入らない。
- 商品名だけの薬(例: 先発のバイオ医薬品で一般名の無いもの)は当たらないことがある。人が確定した対応を
  覚えるテーブルは持っていない(残課題)。

## 5. API(`/master/dpc/…`)

- `POST /master/dpc/coding` `{ encounter_id, inputs, overrides }` → 判定結果(副作用なし)。
  `inputs` は様式1 の値を意味のある形にしたもの(`frontend/src/fhir/dpcCodingHelpers.ts` の
  `dpcCodingInputsFromForm1`。backend は様式1 の定義表を知らない)。`overrides` は分岐の値・
  採用(`accepted`)・除外(`rejected`)するコード。
- 応答は分岐(値・自動の値・状態・選択肢・根拠)、手術・処置等の候補、14 桁の候補、結果(包括フラグ・
  入院日Ⅰ〜Ⅲ・点数・期間の末日・推定包括点数・CCPM)、同じ分類の全 14 桁(シミュレーション)、
  在院日数、医療機関別係数。
- 基準日は退院日(入院中は今日)。在院日数は入院日を 1 日目として基準日まで。推定包括点数は期間ごとの
  日の点数を在院日数ぶん足し、期間Ⅲを超えた日は出来高なので数えない。
- `GET /master/dpc/classifications?q=&mdc6=&on=` は分類の検索と、選んだ分類の 14 桁・点数(閲覧画面)。
- `/master` 配下なので vite の proxy・render.yaml の rewrite は変えていない。

医療機関別係数は施設設定 `dpc_coefficients`(`{ 適用開始日 => "1.2345" }`)。管理 > 施設設定の
「DPC の医療機関別係数」で編集し、基準日に有効なものを使う。未設定なら金額は出さず点数だけ。

## 6. 決定の記録(DPC 歴)

上流の `QuestionnaireResponse`(`questionnaire` = `http://fhir-client.local/Questionnaire/dpc-coding`、
`encounter` = 入院)。1 決定 = 1 件の追記型で、取消は `entered-in-error`(ETag 付き PUT)。有効なもののうち
`authored` が最新を今の分類とする。様式1 と同じく JASPEHR の QuestionnaireResponse(報告単位 ID の
`identifier`・決定者は contained の Practitioner)で、`encounter` を持つのでカルテの時系列には出ない。

| linkId | 値 |
|---|---|
| `dpc-code` | valueCoding(`…/CodeSystem/dpc-code`、display は名称) |
| `edition` | 版 |
| `timing` | 入院時 / 転棟時 / 月末 / 退院時 / その他 |
| `icd10` | 医療資源病名 |
| `bundled` | 包括対象 |
| `days` / `points` | 決定時点の入院日Ⅰ〜Ⅲ・点数の写し(一覧がマスタを引かずに期間Ⅱの末日を出すため) |
| `branch`(group) | 分岐ごとの key・名前・値・状態(自動 / 上書き / 未確定)・根拠の文字列 |
| `note` | コメント |

Claim や Encounter の拡張に載せる案は採らなかった(日本の DPC に当てはまるプロファイルが無く、様式1 と
同じ器のほうが検索・履歴の扱いがそろう)。

## 7. 画面

- **カルテ右ペインの「DPC」**: 「様式1 / 診断群分類」のタブ(`DpcForm1Panels.tsx`)。両方を出したままにし、
  診断群分類は入力中の様式1 の値(保存前も)で判定する。判定はタブを開いているときだけ、入力が落ち着いて
  から引く。様式1 が未作成でも、集めた初期値で判定・決定できる。
- **診断群分類タブ**(`DpcCodingView.tsx`): 医療資源病名・分類・版・在院日数、結果(14 桁・包括/出来高・
  期間Ⅰ〜Ⅲの日数・末日・点数・推定包括点数と金額・期間Ⅲ超え)、分岐の表(自動の値と根拠、select で上書き)、
  手術・処置等の候補(確定・除外・戻す)とコードの追加、同じ分類の候補(判定と合わない行は薄く、今の結果を
  強調)、時点とコメントで「決定」、DPC 歴(取消)。
- **DPC患者**(`/dpc-patients`、データ > DPC患者): 入院中か退院月で、患者・病棟・診療科・入院日・在院日数・
  様式1 の状態・今の診断群分類・期間Ⅱの末日(超過日数・末日まで 2 日以内の印)。病棟・未決定・期間Ⅱ超え・
  様式1 未確定で絞り、CSV。行の「DPC」でカルテを `?open=dpc-coding:<入院>` で開く。
- **DPC 電子点数表**(`/dpc-tables`): 取り込んだ版と、分類を選んだときの 14 桁・入院日・点数。

## 8. 残っていること

- 人工呼吸の実施記録が無い。加算のダミー(KK03・KK04・DD01・DD02・EE01)・心臓電気生理学的検査(0063)・
  大量療法などは人が足す。
- 人が確定した薬剤の対応を覚える仕組み(商品名だけの薬の取りこぼし)。
- 転棟時・月末の再判定の督促、決定の承認、入院患者一覧への列の追加。
- 包括請求(包括/出来高の振り分け、EF ファイル、日レセ送信)。
