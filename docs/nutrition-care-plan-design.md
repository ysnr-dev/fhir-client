# 栄養管理計画書の設計

**状態: 実装済(2026-10-29)。** 入院時の栄養スクリーニング(MUST・GLIM 基準・SGA)と、特別な栄養管理が要る入院の
栄養管理計画書(別紙23 相当)を、テンプレートと入退院文書の一覧で回す。

## 1. 背景

- **［事実］** 栄養管理体制は入院基本料の算定要件(2012 年改定で旧栄養管理実施加算を包括)。入院時に栄養状態を確認し、
  特別な栄養管理が必要と判断した患者に、医師・管理栄養士・看護師などが共同で栄養管理計画を作り、定期的に評価する。
  全入院患者が対象になる。
- **［事実］** 2024 年改定で、栄養状態の評価に GLIM 基準を使うことが望ましいとされた。
- **［事実］** 入院診療計画書(別紙2)に「特別な栄養管理の必要性 有・無」の欄があり、同梱の `ADM_PLAN_01` は
  linkId `nutrition_need`(01 = 有 / 02 = 無)で持っている。
- **［事実］** 既存の土台: テンプレート(Questionnaire、初期値式・計算式・Observation 生成)、帳票(ThinReports)、
  入退院文書の一覧(`/admission-documents`、`docs/bed-management-design.md` §4)、食事オーダーの栄養量の目安。

## 2. 形

- **［設計］** 専用の画面・リソースは作らず、入院診療計画書と同じ「施設設定のテンプレート + 入退院文書の列」にする。
  様式は施設ごとに違うので、テンプレートを差し替えれば済む形にする。
- **［設計］** 同梱のテンプレートは 2 本(`docs/report-mappings/`)。
  - `NUT_SCREEN_01` 栄養スクリーニング: 身体計測(身長・体重は最新値、BMI・体重減少率は計算)、MUST(合計とリスク)、
    GLIM 基準(判定は計算)、SGA、判定(特別な栄養管理の必要性)。MUST の合計・SGA・必要性は Observation を生成する。
  - `NUT_PLAN_01` 栄養管理計画書: 別紙23 の欄立て。病棟・担当医師・担当管理栄養士(作成者)・入院日は初期値。帳票あり。
- **［設計］** 回答は入院(`QuestionnaireResponse.encounter`)に紐付ける。一覧のセルから書き始めると入院を持つ
  (カルテの `?open=encounter-template:<入院>@<テンプレートの url>`、右ペインの `qr-create` に `encounterId`)。

## 3. 一覧での判定(`fhir/admissionDocumentHelpers.ts`)

| 列 | 状態 | 期限 |
|---|---|---|
| 栄養スクリーニング | 回答が完了 → 作成済、入力中 → 作成中、無ければ未作成 | 入院日 + `nutrition_screening_days`(既定 3) |
| 栄養管理計画書 | 必要性が有のときだけ未作成。無だけなら「不要」、未回答なら「判定前」 | 入院日 + `nutrition_plan_days`(既定 7) |

- **［設計］** 必要性は、完了した入院診療計画書と栄養スクリーニングの `nutrition_need` で決める。どれかが 01(有)なら有、
  02(無)だけなら無。両方の様式で同じ linkId とコードにそろえてあるので、どちらで判定しても効く。
- **［設計］** 再評価: 作成済でも、最新の完了した計画書の `reassess_date`(栄養状態の再評価の時期)を過ぎて在院していれば、
  セルを「再評価」にして期限超過として数える。押すと新しい計画書を書き始める(前回値複写が使える)。退院後は出さない。
- **［設計］** 書きかけ(入力中)の計画書は、必要性が未定でも「作成中」で出す(書き始めた事実を隠さない)。
- **［設計］** 回答は `item` まで取る(必要性・再評価日を読むため)。
- 施設設定: `admission_documents` に `nutrition_screening_template` / `nutrition_screening_days` /
  `nutrition_plan_template` / `nutrition_plan_days`。テンプレートが空なら列を出さない(既定は空)。

## 4. テンプレートの式で気をつけたこと

- **［事実］** 回答フォームの式は入力された回答だけからなる QuestionnaireResponse で評価され、計算項目の値は入っていない。
  計算項目の値を別の式で読むと空になる。MUST の各点と合計は変数(`%nutBmi` → `%nutMustBmi` / `%nutMustLoss` → `%nutMust`)で
  組み、項目はその変数を出すだけにしている。
- **［事実］** FHIRPath の空の `sum()` は空になる。MUST の合計は「急性疾患の影響」まで答えたときに入る。
- **［事実］** 上流(JASPEHR)は group 以外の `repeats` を弾くので、栄養補給方法は `repeats` を持たないチェックボックスにした
  (既存の `sur-preop-01` などと同じ)。

## 5. 上流 fhir-server の追加

**不要**。`QuestionnaireResponse` の `questionnaire` / `patient` 検索と `Observation` の生成は既存の経路。

## 6. 残っていること

- 栄養管理計画書への初期値の流し込み(スクリーニングの結果、食事オーダーの食種・栄養量の目安)。
- 摂取栄養量(喫食量 × 食種成分、経腸栄養・輸液の合算)の経過表の行(`functional-gap-backlog.md` §2.5)。
- 栄養管理患者の一覧(栄養部門のワークリスト)と、低栄養率などの指標。
- ICU の早期栄養介入管理加算、NST への依頼との連携。
