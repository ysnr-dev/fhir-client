# 褥瘡対策に関する診療計画書の設計

**状態: 実装済(2026-10-29)。** 入院時の褥瘡リスク評価と、計画が要る入院の褥瘡対策に関する診療計画書(別紙3 相当)を、
栄養管理計画書(`docs/nutrition-care-plan-design.md`)と同じくテンプレートと入退院文書の一覧で回す。

## 1. 背景

- **［事実］** 褥瘡対策は入院基本料の算定要件。日常生活の自立度が低い入院患者に危険因子を評価し、危険因子のある患者と
  既に褥瘡のある患者に、医師・看護師などが褥瘡対策の診療計画を作り、実施し、評価する。
- **［要確認］** 別紙3 の記載上の注意にある「日常生活自立度が J1〜A2 の患者は計画書の作成を要しない」の扱い。
  褥瘡が既にある患者は自立度によらず対象にしている(§3)。告示・通知の最新版で確かめる。
- **［事実］** 既存の土台:
  - 看護プロファイルの区画「褥瘡リスク」(`NP_PU_01`): 日常生活自立度・危険因子 8 項目・現在の褥瘡。入院に結び付く。
  - 褥瘡 DESIGN-R 評価(`PU_DESIGNR_01`)と褥瘡管理(`docs/care-team-design.md` §6)。
  - 入退院文書の一覧と、テンプレートで書く文書の列(施設設定 `admission_documents`)。

## 2. 形

- **［設計］** 専用の画面・リソースは作らない。入退院文書に 2 列を足す。
  - **褥瘡リスク評価**: 施設設定のテンプレートへの回答。既定の雛形は看護プロファイルの「褥瘡リスク」(`NP_PU_01`)。
    一覧から書き始めた回答は入院を持つので、看護プロファイルの区画としてもそのまま見える。
  - **褥瘡対策計画書**: 同梱テンプレート `PU_PLAN_01`(`docs/report-mappings/pressure-ulcer-plan-01.*`)。別紙3 の欄立てで帳票あり。
- **［設計］** 計画書は、褥瘡の有無・日常生活自立度・危険因子を同じ入院の褥瘡リスクの回答から写す。
  初期値の変数 `%admissionAnswers`(入院に結び付いた確定済みの回答の項目を linkId ごとに最新の値で持つ)を足し、
  `%admissionAnswers.where(linkId = 'pu_risk_turn').value` のように引く。両テンプレートで linkId と選択肢のコード
  (「あり・できない」が 1)をそろえてある。
- **［設計］** DESIGN-R は「現在 あり」の下に置く(条件表示は選択肢の子にしか付けられない)。選択肢と合計の式は `PU_DESIGNR_01`
  と同じ。計画書の DESIGN-R は Observation を作らない(経過は褥瘡管理の DESIGN-R 評価で追う)。

## 3. 一覧での判定(`fhir/admissionDocumentHelpers.ts`)

| 列 | 状態 | 期限 |
|---|---|---|
| 褥瘡リスク評価 | 回答が完了 → 作成済、入力中 → 作成中、無ければ未作成 | 入院日 + `pressure_ulcer_risk_days`(既定 1) |
| 褥瘡対策計画書 | 計画が要るときだけ未作成。要らなければ「不要」、判定できなければ「判定前」 | 入院日 + `pressure_ulcer_plan_days`(既定 7) |

- **［設計］** 計画が要るか(`pressureUlcerPlanNeed`)は、確定した最新の褥瘡リスク評価で決める。
  1. 現在の褥瘡(`pu_present`)がありなら要。
  2. 日常生活自立度(`pu_bedridden_level`)が J・A なら不要。
  3. それ以外(B・C か未回答)は、危険因子(`pu_risk_*`)が 1 つでもあり・できないなら要、どれも無ければ不要。
  4. 危険因子も褥瘡の有無も答えていなければ判定前。
  テンプレートの計算項目「看護計画の立案」(`NP_PU_01` と `PU_PLAN_01` の変数 `%puNeed`)も同じ規則。
- **［設計］** 再評価は栄養管理計画書と共通(`REASSESS_LINK_ID` = `reassess_date`)。最新の確定した計画書の「評価の予定日」を
  過ぎて在院していれば「再評価」で期限超過、押すと新しい計画書を書き始める(前回値複写が使える)。
- **［設計］** テンプレートで書く文書の作成済・作成中のセルは、その回答を右ペインで開く(`?open=questionnaire-response:<id>`)。
  入院に結び付いた回答はカルテの時系列に出ない(`encounter:missing=true`)ため。

## 4. 上流 fhir-server の追加

**不要**。`QuestionnaireResponse` の `encounter` / `status` 検索は既存。

## 5. 残っていること

- 褥瘡ハイリスク患者ケア加算の計画書、褥瘡の部位図(シェーマ)。
- 計画書の DESIGN-R を、同じ入院の DESIGN-R 評価(`PU_DESIGNR_01`、入院に結び付かない)から写す。
- `%admissionAnswers` は確定済みの回答だけを読む。入力中の看護プロファイルは写らない。
