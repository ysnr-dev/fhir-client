# 地域連携(紹介の台帳・返書管理)

`docs/functional-gap-backlog.md` §1 #11・§2.7「地域連携(紹介患者登録・紹介患者一覧・紹介状受取・他院紹介一覧)」。
**状態: 第 1 段階を実装済み(2026-11-18)。** 開発環境で §6 の検証を通した。

- **［事実］** = FHIR R4・上流・このリポジトリの実装で確認した内容
- **［設計］** = 本ドキュメントの決めごと

## 1. 背景とスコープ

連携先(他院)のマスタと診療情報提供書のテンプレートはあるが、「誰がどこから紹介されて来たか」「どこへ紹介したか」
「返書を出したか・受け取ったか」を追う台帳が無かった。返書の出し忘れは紹介元との関係を損ね、紹介率・逆紹介率は
地域医療支援病院や紹介受診重点医療機関の要件になる。

含めるもの:

- 他院から受けた紹介(紹介受)の登録、受診の記録、紹介元への返書(受診報告・中間報告・最終報告)の記録
- 他院へ出した紹介(紹介・逆紹介・転院)の登録、紹介先からの返書の受領の記録
- 紹介状・診療情報提供書・返書の文書(患者のファイル)との結び付け
- 一覧画面(部門業務 > 地域連携部門 > 地域連携)、カルテのプロファイルタブの区画「紹介」
- 期間内の件数、紹介率・逆紹介率・返書率、連携先ごとの内訳

含めないもの(§7): 予約との連動、返書の督促通知、送付状・宛名ラベル、初診患者数の自動集計、データ抽出の列。

## 2. データの持ち方

［設計］紹介 1 件を `ServiceRequest` 1 件で持つ(`fhir/referralHelpers.ts`)。進捗の Task は作らない
(受診と返書は台帳そのものの属性で、宛先を持つ作業ではないため)。

| 要素 | 紹介受(inbound) | 紹介(outbound) |
|---|---|---|
| `category` | `order-type|referral`、`referral-direction|inbound`、`referral-kind`(visit 診察 / admission 入院 / exam 検査) | `order-type|referral`、`referral-direction|outbound`、`referral-kind`(referral 紹介 / counter-referral 逆紹介 / transfer 転院) |
| `status` | `active` 進行中 / `completed` 完了 / `revoked` 取消 | 同左 |
| `subject` | 患者 | 患者 |
| `authoredOn` | 紹介日(紹介状の日付・申込日。その日の 0 時をオフセット付きで) | 紹介日 |
| `occurrenceDateTime` | 受診予定日(任意) | 紹介先の受診予定日(任意) |
| `requester` | 紹介元の医療機関(Organization、display に名称) | 自院の担当医(Practitioner) |
| `performer` | 自院の担当医(Practitioner) | 紹介先の医療機関(Organization) |
| `reasonCode[0].text` | 紹介目的 | 紹介目的 |
| `supportingInfo[0]` | 紹介状(DocumentReference) | 診療情報提供書(DocumentReference) |
| `note[0].text` | コメント | コメント |

拡張(いずれも `http://fhir-client.local/StructureDefinition/` 配下):

| 拡張 | 型 | 内容 |
|---|---|---|
| `order-department` | valueReference | 自院の診療科(オーダーと同じ拡張。上流の `department` 検索で引ける) |
| `referral-partner-practitioner` | valueString | 紹介元・紹介先の医師名 |
| `referral-visit-date` | valueDate | 受診日(紹介受のみ) |
| `referral-reply`(繰り返し) | 子拡張 `date` valueDate / `kind` valueCode / `note` valueString / `recorder` valueReference(Practitioner)/ `document` valueReference(DocumentReference) | 返書 1 通 |

- ［設計］画面の状態は `status` と拡張から決める。**受診待ち**(紹介受で受診日なし)→ **返書待ち** → **完了** / **取消**。
  紹介は登録した時点で返書待ち。
- ［設計］返書の区分は、紹介受が `visit-report` 受診報告 / `interim-report` 中間報告 / `final-report` 最終報告、
  紹介が `received` 返書受領 / `interim-received` 経過報告受領。**最終報告・返書受領を記録すると `completed`** にする。
  返書を出さずに終える場合(紹介先から返書が来ない、来院しなかった)は行のメニューの「完了」「取消」。
- ［設計］医師名を文字列で持つのは、紹介元の医師が連携先医師マスタに居るとは限らないため。
- ［事実］部門オーダーではないので `fhir/orderKinds.ts` には入れない。カルテのタイムラインはどの種別にも当たらない
  ServiceRequest をカードにしない。カルテのオーダー検索(`karteOrderParams`、診療日ペイン・カルテ印刷も共用)は
  `category:not` で看護指示と一緒に外す(外さないと紹介しか無い日が空の日として並ぶ)。
- ［事実］上流の ServiceRequest 検索は `category`(複数指定は AND)・`authoredon`・`status`・`requester`・`performer`・
  `department` を持つ。`requester=Organization/<id>` のように型を付ければ医療機関でも引ける。strict で通ることを確認した。

## 3. 画面

### 3.1 地域連携(`/referrals`、部門業務 > 地域連携部門)

タブは 3 つ。

- **紹介受** / **紹介**: 紹介日の期間(既定は 3 か月前から今日)・状態(既定は進行中)・診療科・連携先で絞り、紹介日の新しい順。
  絞り込みはすべて上流の検索条件。
  - 「登録」は患者を検索して選び、区分・紹介日・受診予定日・連携先(連携先医療機関から選ぶ)・医師名・診療科・担当医・
    紹介目的・文書・コメントを入れる。診療科と担当医の既定はヘッダーの依頼科・依頼医師。
  - 行の操作: 「カルテ」、受診待ちは「受診」(受診日)、返書待ちは「返書」(区分・日付・文書・メモ)。
    メニューに「編集」「受診日変更」「返書取消」(最後の 1 通を外し、完了なら進行中に戻す)「完了」「進行中に戻す」「取消」。
  - 返書待ちのまま 14 日を超えると状態の横に日数を赤で出す(起点は紹介受が受診日、紹介が紹介日。途中の返書があればその日)。
- **集計**: 期間(既定は当月)と診療科で、紹介受・紹介・うち逆紹介の件数、返書率(受診済みの紹介受のうち返書を
  1 通以上出した割合)、返書待ち 14 日超の件数、連携先ごとの内訳(紹介受の多い順)。取消は数えない。
  「初診患者数」を入れると紹介率(紹介受 ÷ 初診患者数)と逆紹介率(逆紹介 ÷ 初診患者数)を出す。

### 3.2 カルテのプロファイルタブ「紹介」

患者の紹介受・紹介を新しい順に並べる。「紹介受登録」「紹介登録」と、行を押しての編集。受診・返書の記録は一覧画面で行う。

## 5. 採らなかった案

- **backend のテーブルに持つ**: 患者と連携先(どちらも上流のリソース)を指す診療の記録で、SS-MIX2・電子カルテ情報共有サービスへ
  出す材料にもなる。FHIR の紹介は ServiceRequest が標準の置き場。
- **進捗を Task で持つ(他科依頼と同じ形)**: 宛先のある作業ではなく、状態は 3 つで足りる。書き込みが 2 リソースになるだけ損。
- **部門オーダーの種別に足す**: カルテのカード・右ペイン・医事送信の対応表を埋めることになるが、紹介は自院の部門へ出す依頼ではない。
- **初診患者数を予約から数える**: 初再診は Appointment の拡張で上流に検索が無く、期間の全予約を読むことになる。
  紹介率の分母は救急搬送・休日夜間の除外など届出側の定義で決まるので、数は入力に任せる。

## 6. 検証(2026-11-18、開発環境・医師 一郎でログイン)

- 紹介受を登録(テスト太郎、紹介元 Smoke Hospital)→ 「受診待ち」。受診を記録 → 「返書待ち」。受診報告 → 返書欄に出る。
  編集してコメントを足しても受診日と返書が残る。最終報告 → `completed` になり進行中の一覧から消える。
- 紹介(逆紹介 11-10・紹介 10-20)を登録 → 紹介タブに並び、10-20 は「返書待ち 29 日」が赤で出る。
- 集計(当月): 紹介受 1・紹介 1・うち逆紹介 1・返書率 100.0%、連携先の内訳 1 行。
- プロファイルタブ「紹介」に 3 件。カルテのオーダー検索は `category:not` で紹介を含まない(日付未定の検索で 3 件 → 0 件)。

## 7. 残り

- 予約との連動(紹介受の受診予定日から予約を取る、受付で受診日を自動で入れる)
- 返書待ちの督促(通知・ホームのカード・未完了記録一覧)
- 文書作成から診療情報提供書を作ったときの紹介の自動登録、送付状・宛名ラベル
- 初診患者数の自動集計、データ抽出の列、月次推移
- 連携先医師マスタからの医師の選択
