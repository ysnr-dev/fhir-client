# カルテ画面

## カルテ画面

患者一覧の「カルテ」ボタンから患者ごとのカルテ(`/patients/:id/karte`)を開きます。左ペインで登録済みの
診療情報を参照し、右ペインで登録・編集する 2 ペイン構成です(この画面だけ `#root` の幅制限を外すため、
`KartePage` が `body.karte-wide` を付け外しします)。

- **見出しの診察ボタン**: 外来で診察中なら「診察終了」、診察前で今日の受付済の予約(検査予約を除く)があれば
  「診察開始」を患者情報の右に出します。外来一覧と同じく今日の受付済の予約とその診察から判定するので、
  過去の日に閉じ忘れた診察は見出しに出ません。どちらも外来一覧の同じ操作と同じ書き込みで、診察開始はカルテに
  留まったまま、診察終了は会計送信(連携が有効なとき)を経て外来一覧へ戻ります。
  診察日に未実施(依頼・受付の段階)の検査オーダー(検体・細菌・病理・放射線・生理・内視鏡)があると、診察終了で
  「一時終了」「診察終了」を選ばせます。一時終了は Encounter を `onleave` にし(予約は受付済のまま、過ぎた期間は
  `statusHistory` に積む)、外来一覧へ戻ります。一時終了の間は見出しと外来一覧に「診察再開」を出し、外来一覧の
  状態は「一時終了」になります。外来一覧の診察再開は、診察開始と同じくそのままカルテを開きます。

- **食物アレルギーと食事**: アレルギータブで食物アレルギーを登録・有効化すると、進行中の食事オーダーに
  写っていなければ、オーダーの依頼医あての通知「食事のアレルギー確認」を同じ transaction で作ります。
  食事タブは暦の上に未反映・解消済みの注意を出し、食事オーダーの登録・編集でその時点の有効な食物アレルギーを
  オーダーに写します(`docs/meal-order-design.md` §2.12)。
- **食事の栄養量の目安**: 食事オーダーの食種選択の表に、患者の身長・体重・BMI と、標準体重から出した
  熱量・蛋白質の目安を出します。選んだ食種が目安を外れると「目安未満」「目安超」の印が付き、食種選択の表では
  目安に収まる値を強調します(`docs/meal-order-design.md` §3.6)。
- **左ペインのタブ**: 「カルテ」「病名」「患者情報」(プロファイル・アレルギー・持参薬・口腔診査情報)「診療情報」
  (投薬歴・注射カレンダー・化学療法・クリニカルパス・食事・マルチチャート)「経過表」「検査結果」(検体検査・
  検体検査時系列・細菌検査・病理検査・放射線検査・生理検査・内視鏡)「看護」(看護プロファイル・指示簿・看護計画)
  「予約」「ファイル」「その他」(カルテ印刷・診療ダッシュボード・DICOMビューア・SMARTアプリ)。括弧の中は 1 つのドロップダウンにまとめたタブで、まとめ方は
  `karteUrl.ts` の `KARTE_TAB_GROUPS` です。タブの定義は `KARTE_TABS` 1 か所で、足すときはここと
  `components/KarteTabPanel.tsx` に 1 行ずつ加えます(タブ表示・上下分割の下ペイン・診療ダッシュボードのカードが同じ部品で描きます)。病名・アレルギー・検査結果・ファイルは一覧・
  表示・登録・編集・削除がタブ内で完結します。テーブル(`components/*Table.tsx`)は `onView` / `onEdit` を
  受け取り、ページ遷移せずタブ内で表示を切り替えます。内容表示は `components/*DetailPanel.tsx`、
  検査結果タブにはさらに「時系列表示」(`components/LabResultTimelinePanel.tsx`)も置いてあります。
  時系列表示は項目にチェックを入れて「グラフ表示」でモーダルにグラフを出します。操作行右端のアイコンで
  表とグラフを上下に分割でき、分割中はチェックした項目のグラフを下側にそのまま出します(分割の有無と
  高さはブラウザに保存)。グラフの上のアイコンで、マルチチャートと同じく全項目を 1 つのグラフに重ねる表示
  (各項目を自分の範囲で上下いっぱいにそろえ、単位と範囲は凡例で読む。凡例を押すと一時的に隠せる)と、
  点の上に数値を出す表示(判定 H/L は表と同じ色)に切り替えられます。1 グラフあたりの高さも同じ場所の
  アイコンで 5 段階(標準の 0.5〜2 倍)に変えられます(切り替えと高さもブラウザに保存)。
- **予約タブ**: その患者の予約(`Appointment`)を新しい順に一覧し、取消・日時変更(右ペイン)・問診 QR を出します。
  見出しの右で表示期間を「全期間」「期間指定」から選びます。既定は期間指定で、開始日が今日の 1 か月前・終了日は空
  (無期限)。期間は予約の開始日(`date=ge…&date=le…`、両端を含む)で上流に絞らせます。
- **カルテタブ**: 診療記録(`Composition`)・処方(`ServiceRequest` + `MedicationRequest`)・単独登録の
  テンプレート回答(`QuestionnaireResponse`)を診療日ごとにまとめた時系列表示です。診療日の見出しには
  曜日を添えます(`2026-09-01 (火)`)。診療記録のセクションから
  参照されている回答は記録カードの本文として描画済みなので、単独カードには出しません。カードは高さを
  制限して折りたたみ、溢れる場合だけ「続き表示」を出します。
  新しい日が上(日付未定・先の予定・本日・過去の順)なので、本日のカルテのペインを出していないときは、
  開いた時点と、タブ表示で他のタブからカルテタブに切り替えた時点で、本日(本日の項目が無ければ本日より前で
  最も新しい日)の位置までスクロールしておきます(先読みの日付未定・先の予定と最初のページが揃ってから合わせます)。
  同じ日の中のカードの並びは施設設定「カルテカードの並び順」(`karte_card_order`)で選びます。「時系列」は
  新しい順、「種別順」は設定した種別の順に並べ、同じ種別の中は新しい順にします(`fhir/karteCardOrderHelpers.ts`)。
  種別の順は全種別を並べて保存し、後から足した種別は既定の順(`KARTE_KIND_LABELS` の定義順)で後ろに付きます。
  カルテ印刷も同じ設定に従います(日時は古い順)。
- **カードの見出しの診療科**: オーダーは依頼科・依頼医師を、診療記録・テンプレート回答・バイタル・
  パス評価は記録した診療科と記入者を見出しに出します。診療科はどれもオーダーの依頼科と同じローカル拡張
  (`…/order-department`)に、新規登録の時点でヘッダーの依頼科を焼き付けます(編集では保存済みの科を
  引き継ぐ)。拡張を持たない既存の記録には出ません。
- **無限スクロール**: 3 リソースをそれぞれ `_count=20` のオフセットページングで読み(`useKarte*Infinite`)、
  表示側(`fhir/karteTimeline.ts`)がマージします。まだ次ページがあるリソースの「読み込み済みで最も古い
  診療日」を安全カットオフとし、それより新しい診療日のグループだけを描画します(後からグループが歯抜けで
  増えるのを防ぐため、カットオフ当日も出しません)。末尾のセンチネルが見えている間、カットオフを押し
  下げているリソースだけ次ページを読みます。
- **左ペイン(診療日 / 種別)**: 左端のペインは 2 つの探し方を切り替えて使います
  (`components/KarteSidePane.tsx`。モードは localStorage に保存。ペインは 160px しかないので、
  切替のラベルはスクロールバーが出ても表示切替アイコンが隠れない長さに保ちます)。
  - **診療日**: データが存在する診療日をツリー表示し(既定は閉じた状態)、クリックでタイムラインの
    該当位置までスクロールします。タイムラインの先頭に見えている日の行に色を付けます(スクロールに
    合わせて動き、いまどの日を読んでいるかが分かる)。
  - **種別**: 情報の種別(診療記録・処方・注射・検体検査・細菌検査・放射線検査・生理検査・内視鏡・処置・テンプレート)を
    並べ、選ぶとタイムラインがその種別のカードだけになります。テンプレートは 1 種別しか無いので、
    展開してテンプレート名まで選べます(テンプレートカテゴリの見出し付き。一覧はテンプレート検索から
    作るので、タイムラインを読み進んでも選択肢は増減しません)。「社会歴」を選べば最新が先頭に来て、
    そのまま過去の回答も時系列で追えます。
  - 絞り込みの対象は URL の `?card=<種別>`(テンプレートを 1 つに絞るときは `?card=qr:<テンプレートの url>`)に
    載せるので共有・復元できます。**テンプレートはバージョンを見ず url で一致**させるため、
    テンプレートを改版しても過去の回答が絞り込みから外れません。
  - プロブレムの絞り込みと併用でき、両方選べば**両方を満たすカードだけ**が残ります。
  - **絞り込み中は必ず「種別」が表示されます**。診療日へ切り替えると絞り込みは解除され、
    絞り込み付きの URL で開いたときは(保存されたモードが診療日でも)種別が開きます。
    絞り込みの操作はこのペインだけで完結するので、タイムライン側には見出しを出しません
    (見えないところで絞り込みが効いたままにならないようにするため)。
  - **全て / 自科 / 個人**: ペイン上端の表示切替アイコンの左にあるケバブで、タイムラインに出す記録を
    選びます(診療日・種別のどちらを出していても効き、選択は localStorage に保存。既定は全て)。
    「全て」以外を選んでいる間はケバブを強調表示します。
    - **自科**: ヘッダーで選択中の診療科と、カードの診療科(オーダーは依頼科、診療記録・テンプレート・
      バイタル・パス評価は記録した科)が一致するものだけ。診療科を持たない記録は出ません。
      上流の `department` 検索(4 リソース共通の `order-department` 拡張)で絞るので、診療日ペインにも
      自科の記録がある日だけが並びます。
    - **個人**: ログイン中の医療従事者が記録したものだけ(オーダーは依頼医師、診療記録は記載者、
      パス評価は記録者)。テンプレートの記入者は実参照を持たないので名前(空白の有無は無視)で
      突き合わせます。バイタルは記録者を持たないので出ません。これも上流の検索で絞ります
      (診療記録は `author`、オーダーは `requester`、テンプレートは記入者名の `author-name`)。
    - 種別・プロブレムの絞り込みと併用できます。自科・個人はサーバー検索で絞るので、本日のカルテの
      ペインにも効きます(種別は効きません)。
- **プロブレムリスト(POMR)**: カルテタブの上に常時表示する横帯です(`components/KarteProblemList.tsx`)。
  問題志向型医療記録の「プロブレムリスト」にあたり、プロブレム・既往歴・保険病名は同じ `Condition` を
  `category` で区分します([patient-profile.md](patient-profile.md)「病名の区分」)。`category` の無い既存データは
  保険病名として扱い(移行不要)、編集保存された時点で明示的な区分が付きます。帯に出すのは
  プロブレムだけで、既往歴は出しません(現在の問題ではないため)。プロブレム番号(#1, #2...)は
  アプリローカル拡張 `http://fhir-client.local/StructureDefinition/problem-number` に永続化します
  (表示順から動的に採番すると削除や日付修正で番号がずれ、過去の記録が指すプロブレムが変わってしまうため)。
  登録・編集は「病名」タブの区分ラジオで行います。プロブレムの絞り込みは上流が `category` 検索を
  サポートしない可能性があるため、全件取得してクライアント側で振り分けます(`splitConditions`)。
  取得は `-onset-date` 順ですが、帯とフォームの候補は常に**番号順**に並べ替えます(番号を永続化して
  いるのに表示が発症日順では番号の意味が薄れるため)。番号の無い旧データは末尾に回します。
  継続(active)以外のプロブレムは既定で畳み、「解決済み N 件表示」で開きます(帯の幅を継続中の
  プロブレムに使うため。開閉状態は localStorage に保存)。ただし選択中のプロブレムは、畳んだ状態でも
  タイムラインの減光・絞り込みの理由が分かるように残します。
  各種一覧の行を押して開く患者ドロワーにも同じ帯を出します(読むだけで、チップの選択と表示設定は
  ありません。帯は畳まずに常に出し、解決済みの開閉はカルテと同じ設定を使います)。ドロワーでは帯が高く
  ならないようチップを 1 行に収め、あふれたときは「他 N 件」で展開します(患者を替えると畳んだ状態に戻ります)。
- **プロブレム間の関連(統合・分割・親子)**: 症状名で立てたプロブレムが 1 つの診断にまとまったり
  (統合)、1 つが複数に分かれたり(分割)、下位のプロブレムがぶら下がったりします。「病名」タブの
  プロブレム編集で設定します。
  - **統合と分割は「引き継ぎ先」1 つで表します**(アプリローカル拡張
    `…/problem-succeeded-by`、0..*)。複数の旧プロブレムが同じ先を指せば統合、1 つが複数を指せば
    分割で、関係の向きが違うだけなので拡張を分けていません。引き継ぎ先を指定すると転帰を
    「中止」にして閉じ(画面の転帰欄も変わるので、閉じられたことが見えます)、帯では解決済みに
    畳まれて「→ #1 ２型糖尿病」のように行き先を併記します。
  - **下位プロブレム**は `…/problem-parent`(0..1)で親を指します。親子とも継続したまま併存し、
    帯では親の直後に破線のチップで並べます。
  - FHIR R4 には Condition 同士の型付き関連が無い(標準の `condition-related` 拡張は「関係がある」
    としか言えず統合と親子を区別できない)ため、プロブレム番号と同じくローカル拡張で持ちます。
  - **親を選んで絞り込むと、下位プロブレムに紐付く情報も含めて表示します**(合併症を含めた経過を
    1 つの軸で追えるようにするため)。サマリーヘッダに「下位プロブレム N 件の記録も含めて表示して
    います」と出ます。減光も同じ範囲で効きます。参照が輪になっていても辿り直さないので止まります。
  - 親の候補からは自分自身と自分の配下を除きます(選ぶと参照が輪になるため)。
- **プロブレム単位の経過表示**: プロブレムを選んだときのタイムラインの見せ方は、帯の右端の
  ケバブメニューで「関連しない記録を減光」(既定)と「関連する記録のみ表示」を切り替えます
  (帯の行を増やさないためのケバブです。設定は localStorage に保存)。後者は POMR の
  「各 Problem の経過を縦に読む」読み方にあたり、絞り込み中はタイムラインの上に見出し
  (`components/KarteProblemSummary.tsx`)を出して、#番号・病名・発症日・転帰と、直近の記録の
  評価と計画(A/P)の抜粋を添えます(プロブレムリスト自体は「今どうなっているか」を持たないため)。
  絞り込みの対象は URL の `?problem=<Condition の id>` に載せるので共有・復元できます
  (減光だけの選択は一時的な状態なので載せません)。
  - **絞り込みはサーバー検索で行います**。4 系統の無限クエリにそれぞれ
    `Composition?entry=` / `ServiceRequest?reason-reference=` / `QuestionnaireResponse?problem=` /
    `Observation?problem=`
    を付け、対象の Condition id をクエリキーにも入れます(絞り込みごとに別のページング列に
    なるので、切り替えると先頭ページから読み直します)。親プロブレムを選んだときは下位
    プロブレムの id もカンマ区切りで並べます(参照検索のカンマは OR)。
  - 下位プロブレムを含めるにはプロブレム一覧が要るので、**その取得が終わるまで
    タイムラインの取得を始めません**(絞り込み前の並びが一瞬見えたり、直後に読み直しに
    なったりしないように)。
  - 自科・個人も同じくサーバー検索で、キーに含めて別のページング列にします(`api/queries/karte.ts` の
    `KarteScope`)。自科は `department=Organization/{id}`。個人は診療記録が `author=Practitioner/{id}`、
    オーダーが `requester=Practitioner/{id}`、テンプレートが `author-name:exact={氏名}`(上流が空白を
    除いて比べる)で、記録者を持たないバイタルは検索しません。個人は**ログイン中の医療従事者を
    読み終えるまで取得を始めません**(プロブレムと同じ理由)。
  - クライアント側に残る絞り込みは種別(`?card=`)と、全件読んであるパス評価の自科・個人で、こちらは
    `buildKarteTimeline` の**後**で行います(`filterKarteGroupsByCard` / `filterKarteGroupsByScope`)。安全カットオフと
    次ページの要否は読み込み済みの全データで決まるので、件数が減ってもページングは
    壊れません。
- **バイタル**: 右ペインの「バイタル」から体温・血圧・意識(JCS)・脈拍・SpO2・酸素流量・呼吸数・身長・体重を 1 画面で
  入力します(`components/VitalForm.tsx`、組み立ては `fhir/vitalHelpers.ts`)。
  - 意識(JCS)は選択肢で、LOINC に JCS が無いので MEDIS 看護観察 31001657 とローカルの項目コードを併記します。
    酸素流量は LOINC 3151-8(L/分、0 は室内気)。
  - **早期警告スコア**(施設設定で有効なとき): 入力中に NEWS2 と qSOFA をフォームの下に出し、保存では
    同じ transaction に NEWS2 の Observation と、入院中で区分が下限以上なら主治医あての通知(`ews-alert`)を
    積みます。カードからの削除は NEWS2 も消し、未対応の通知を取り下げます(`docs/early-warning-design.md`)。
  - **1 項目 = 1 Observation**(category `vital-signs`、コードは LOINC、単位は UCUM)。ただし
    **血圧だけは 85354-9 の Observation 1 件に収縮期(8480-6)と拡張期(8462-4)を component として
    入れます**。別々の Observation にすると「そのときの血圧」として組にして読めないためで、
    JP Core の `JP_Observation_BloodPressure` と同じ構造です。片方だけの入力は登録時に弾きます。
  - **BMI(39156-5)は身長・体重から自動計算**して一緒に残します。入力欄は持ちません(同じ測定の
    身長・体重から一意に決まる値なので、経過表で並べて追えるように保存しています)。
  - 空欄の項目は Observation を作りません(値 0 の Observation を残すと「測って 0 だった」と
    読めてしまうため)。
  - **1 回の測定は identifier(`http://fhir-client.local/vital-entry` + UUID)で束ねます**。
    タイムラインではこの単位で 1 枚のカードにし、編集・削除もまとめて行います。測定日時で
    束ねないのは、同じ時刻に別の担当者が入れた測定と混ざりうるためです。
  - 更新は「前回の測定を全部消して作り直す」方式です(入力欄を空にした項目の削除や血圧の追加で、
    項目と Observation の対応が崩れるため)。
  - 対象プロブレムはローカル拡張 `…/observation-problem` に持ちます(Observation には理由を表す
    標準要素が無いため)。上流には `Observation?problem=` を追加済みで、プロブレムの絞り込みにも
    乗ります。
  - タイムラインの取得では `derived-from:missing=true` を付けて、テンプレート回答から抽出した
    Observation を除きます(そちらは回答のカードとして既に出るため)。
- **経過表(フローシート)**: POMR 5 要素の 1 つで、「経過表」タブに出します
  (`components/VitalFlowsheetPanel.tsx`)。入院患者の 1 週間を 1 枚で読む画面で、上から
  イベントの帯・温度板グラフ・測定項目・食事摂取量・インスリン・水分出納・注射・内服・看護・検査を同じ
  横軸に並べます。カルテ以外のタブ
  なので、上下分割にすると**上にカルテ、下に経過表**を並べて「SOAP を書きながら推移を見る」
  読み方ができます。**設計は `docs/flowsheet-design.md`**。
  - **横軸は基準日までの期間**(1 週間・2 週間・1 か月から選択。左が古く、右端が基準日で、
    紙の温度板と同じ向き)。「◀ ▶」は期間ぶん送ります。
    測定の無い日も 1 列置き、1 日の中は測定ごとに列が分かれます。日付の見出しは
    `MM/DD(曜)` で、列幅はパネルの幅を使い切ります。**日付を押すとその日の 24 時間表示**に
    切り替わり(枠が 1 日から 1 時間に変わるだけで作りは同じ)、もう一度押すと元の週に戻ります。
    持続点滴は 24 時間表示だと開始〜終了がバーで出ます。
  - **行は測定項目**。手入力のバイタル・テンプレート抽出・看護観察を同じ表に載せます
    (検査値は合流させません。検査結果タブに表・グラフがあるため)。**読み取り専用**で、
    編集はカルテのバイタルカードから行います。
  - **異常値**は施設設定「バイタルの異常値」のしきい値で色付けします。判定は表示時に行い
    `Observation.interpretation` には書かないので、しきい値を変えれば過去の測定にも効きます。
  - **注射**は薬剤の組ごとの行で、予定を空丸・実施を塗り丸で出します。印を選ぶと一覧が開き、
    「詳細」でオーダー詳細、「実施入力」でカルテと同じ実施入力モーダルへ飛べます。
  - **内服**は薬剤の組(RP)ごとの行で、与薬の予定を空丸・与薬を塗り丸・与薬せずを丸+×で
    出します。処方は「1日3回・食後」までしか持たないので、**用法コード(16桁)を復号して**
    施設の食事時刻からの前後(施設設定「内服の与薬の時刻」)で予定時刻を出します。頓用や
    「決まった時刻に」など時刻が決まらない用法は予定を出しません。印を選ぶと押した枠の
    一覧が開き、「与薬入力」でその枠を記録、記録済みなら「与薬取消」ができます。対象は
    入院処方だけで、進捗 Task(薬剤部の調剤)は動かしません。**設計は
    `docs/prescription-order-design.md`**。
  - **看護観察・看護行為**は指示ごとの行で、欄を分けて出します。印を選ぶと一覧が開き、
    「実施入力」から指示簿と同じ実施入力モーダルへ飛べます(押した指示 1 件だけが出て、
    押した印の日時が記録日時の初期値になります。指示簿から開くとラウンド用に全指示が出ます)。指示は日時ではなく期間と
    頻度で持つので、予定の印は表示している日ごとに頻度から時刻を展開して作ります
    (指示簿の実施入力と同じ設定)。頻度が自由記載の指示は予定を出しません。
  - **食事摂取量**は主食・副食の行で、日の枠の中に朝・昼・夕を並べます(24 時間表示では
    08/12/18 の枠に落ちます)。値は割(0〜10)で、押すとその食事の主食・副食だけの入力が
    開きます。記録は**食事オーダーの実施**(`basedOn` がその食事を出しているオーダー)に
    するので、摂取量の指示を別に立てる必要はありません。オーダーの無い日・食止め・欠食の
    食事は枠を出しません。カルテのカードには出しません(継続オーダーなので「実施済」が
    定まらないため)。
  - **水分出納**は枠ごとの IN・OUT・バランスの合計(mL)です。どの看護観察を IN / OUT に
    数えるかは施設設定で選びます(同じ名前で単位違いの項目があるため MEDIS の管理番号で
    持ちます)。注射は投与量換算マスタで mL に直して IN に足し、換算できない薬剤があれば
    見出しに印を出します。選んでいなければ欄ごと出ません。
  - **検査**は放射線・内視鏡・生理の種別ごとの行です(検体系は出しません)。注射と同じ印で
    予定を空丸・実施済を塗り丸にし、実施した日に置きます。
  - **病日・術後日数**を日付の下に出します。入院日が 1 日目、手術当日が「当日」です。
  - 基準日と全画面は URL の `view` に載るので、リロードしても戻らず、特定の週をリンクで
    共有できます。手入力のバイタルは時刻の見出しからバイタル編集(右ペイン)を開けます。
- **診療記録とプロブレムの紐付け**: POMR は「各 Problem に対して SOAP 形式で経過を記録する」ため、
  紐付けは**診療記録 1 件に対して 1 プロブレム**です(複数のプロブレムを扱うときは記録を分けて
  登録します)。**参考にしている C-CDA on FHIR の Progress Note には、S/O/A/P と並ぶ
  `problems_section`(LOINC 11450-4)が定義されている**ので、対象プロブレムはそのセクションを
  1 つ持たせて `section.entry` で `Condition` を参照します。ローカル拡張ではなく標準要素なので、
  絞り込みが **R4 標準の検索パラメータ `entry`** に乗ります(上流の標準外パラメータが 1 つ減ります)。
  セクションの `text` は entry から導出した要約なので `status` は `generated` です。
  なお `section.focus` は使いません。あれが表すのは「composition の subject ではない、subject に
  関連する人・物(配偶者・胎児・ドナー等)」で、記述の主題を表す要素ではないためです。
  `entry` の `display` には保存時点の「#番号 名称」を入れておくので参照解決なしでも描画できます。
  表示側は現在のプロブレムから名称を引き直すため、病名を編集しても過去の記録に古い名前は残りません。
  参照先が削除済みの場合は保存済みの表示名 +「(削除済み)」でフォールバックします。プロブレムのチップを
  選ぶと、そのプロブレムに紐付かないカードを減光します(件数が減るとページングの判定が動くため、隠さず
  減光にとどめています)。プロブレムを選んだ状態で「診療記録」から新規登録すると、そのプロブレムを対象の
  初期値にします(登録ボタンを押した時点の選択を `KartePaneState` に載せるので、選択を変えただけで
  入力中のフォームが作り直されることはありません)。プロブレムセクションは本文ではないので、編集欄・
  カード・詳細表示・一覧のセクション要約からは `noteBodySections` で除きます。
- **テンプレート回答とプロブレムの紐付け**: 単独登録のテンプレート回答(`QuestionnaireResponse`)も
  診療記録と同じく**回答 1 件に対して 1 プロブレム**を紐付けられます。ただし
  `QuestionnaireResponse` には診療記録の `problems_section` にあたる標準の受け皿が無いため、
  こちらはアプリローカル拡張
  `http://fhir-client.local/StructureDefinition/questionnaire-response-problem` の `valueReference`
  に持たせます(`display` の扱い・削除済みのフォールバックは診療記録と同じ)。初期計画(Dx/Rx/Ex)の
  ように「どのプロブレムに対する記載か」が要になるテンプレートを、診療記録に貼らず単独で残せる
  ようにするためです。プロブレムを選んだ状態で「テンプレート」から登録すればそのプロブレムが
  初期値になり、絞り込み表示にも乗ります。
- **クエリキー**: `["<型>", "search", "karte", patientId]`。既存の作成・更新・削除が無効化する
  `["<型>", "search"]` の配下に置いてあるので、右ペインでの保存後にタイムラインが自動で再取得されます。
- **右ペインの登録・編集**: 登録・編集 UI はパネル(`components/*Panels.tsx`)に切り出してあります。
  各フォームは初期値をマウント時にしか読まないため、対象の切り替えでは `key` でフォームを作り直します。
- **確定(署名)と変更履歴**: 診療記録のステータスを「確定」にして保存すると、**署名**として
  `Composition.attester` にログイン中の医療従事者を記録します(`mode` は `legal` = 内容に法的責任を
  負う者、`time` は確定日時)。ステータスだけでは「確定した」事実しか残らず、真正性の根拠に
  ならないためです。詳細表示に「確定者 児玉 義憲 (2026-08-15 07:48)」の形で出ます。
  - `attester` は 0..* ですが**最後に確定した 1 件だけ**を持ちます。過去の署名は版履歴に残るので
    二重に持たず、「今この記録に責任を負っているのは誰か」を一意に読めるようにするためです。
  - 確定済みの記録を修正すると `amended` になり、**署名も修正した本人に更新**します(作成者
    `author` は最初の記録者のまま)。医療従事者が紐付いていないアカウント(administrator 等)が
    修正した場合は、既存の署名をそのまま残します(空にすると誰も責任を負っていない確定記録に
    なってしまうため)。下書きに戻した場合は署名を外します。
  - **変更履歴**はカードのケバブ「変更履歴」から開きます。上流の `_history` で版の一覧を取り、
    版を選ぶとその時点の内容をそのまま表示します(現在の記録と同じ描画を使います)。版ごとに
    更新日時・ステータス・確定者が並ぶので、「いつ誰が何を直したか」を辿れます。
    上流・backend プロキシとも対応済みで、サーバー側の変更は不要です。
- **カードの操作**: タイムラインの各カードはケバブメニューに「詳細表示」「変更履歴」「FHIR JSON 表示」「編集」
  「削除」(テンプレートは「平文表示」も)を畳んでいます。DO(処方)と PDF(テンプレート)だけは 1 行に
  出します。詳細表示は各リソースの詳細パネルをモーダルで開くので、処方の添付文書(DI)リンクや
  テンプレートのシェーマ画像もここで参照できます。
- **変更履歴の差分**: 変更履歴(診療記録・カードとも)の「差分」で、選んだ版と 1 つ前の版を比べます。
  消えた行は赤、増えた行は緑で示し、書き換えた行は行の中の変わった文字だけを濃く塗って取り消し線を付けます
  (日本語は単語の区切りが無いので文字単位。行ごと消えた行は行全体に取り消し線)。変わらない行は薄く描きます。
  - 比べるのは画面に表示される文字で、2 つの版をいつもの描き方で画面外に描き、描かれた要素を行に起こして
    比べます(`lib/renderedLines.ts`。種類ごとに比較用の文字起こしを持たない)。「ラベル」と「値」(dl の dt/dd)は
    「ラベル: 値」の 1 行にまとめ、見出し(h1〜h6・legend)と太字の行は太字のまま、横に並んだ要素(薬剤名と量など)は
    1 行にまとめ、字下げは描画位置から段に直します。画面に出ない項目(extension の内部値など)だけが
    変わった版は「表示上の差分はありません」になります。
  - 既定の「変更箇所のみ」では、変わった行の前後 2 行と、そのかたまりが属する見出しだけを残し、間は
    「…」に畳みます。外すと全文を出します。「変更 1/3」の「前へ」「次へ」で変わった箇所を順に送ります
    (送り先の行は左に印が付きます)。
  - 「差分」と「変更箇所のみ」の切り替えは版を選び直しても保つので、版を順に送りながら変更を追えます。
- **カードの変更履歴**: 診療記録以外のカード(処方・注射・部門オーダー・バイタル・テンプレート・パス評価)も
  ケバブ「変更履歴」で、編集ごとの版を一覧し、選んだ版の内容をカードの本文と同じ描き方で表示します。
  オーダーはヘッダと明細(MedicationRequest・明細の ServiceRequest。検体検査などは構成項目まで)、
  バイタルは 1 回ぶんの Observation 群をまとめて組み直すので、明細の追加・削除も版に表れます。
  - 版は上流の `_history` から集めます。ヘッダ(本体)はインスタンス履歴、明細は型レベル履歴を
    検索条件で絞る形(`ServiceRequest/_history?based-on=ServiceRequest/X`、バイタルは `identifier`)で
    引きます。この形は削除済みのリソースの版も返すので、後から消した明細も過去の版に出ます。
  - 1 回の登録・編集(transaction)の書き込みは時刻がミリ秒単位でずれるので、間が 2 秒以内の
    書き込みを 1 つの版にまとめます。内容が前の版と同じ保存は版に数えません。
  - 版はオーダー内容の版で、実施記録・照射記録は出しません。進捗・レポートの有無は現在の値です。
    カードの見出し(診療日・表題・依頼科・依頼医・プロブレム・パス)は版の値で本文の前に並べます。
- **診療ダッシュボード**: 「その他」→「診療ダッシュボード」で、左ペインのタブ(「カルテ」のタイムラインを含む。カルテ印刷・SMARTアプリを除く)を
  カードとして横 12 列のマス目に並べ、1 画面で読みます。設計は `docs/clinical-dashboard-design.md`。
  - **カード**: 中身はそのタブと同じ部品で、タブの中でできる操作(経過表の測定から右ペインのバイタル編集、検査結果の詳細、
    カルテのカードの編集・DO など)はカードの中でも同じです。表示状態(見ている週・開いているレポート)はカードごとに持ちます。
  - **基準日**: 上部の基準日(既定は今日)を変えると、全カードを作り直して基準日をその日にそろえます。経過表・マルチチャート・投薬歴は
    その日を右端(基準日)に、注射カレンダーはその日が見える開始日に、食事・化学療法はその月に、検体検査・細菌検査・病理検査・
    放射線検査・生理検査・内視鏡はその日以前で最新のレポートに、指示簿・看護計画はその日に有効なものに、予約はその日の 1 か月前からに、
    カルテのタイムラインはその日(無ければそれより前で最も新しい診療日)の位置にします。病名・プロファイル・アレルギー・持参薬・
    口腔診査情報・看護プロファイル・ファイル・DICOM・検体検査時系列は基準日の影響を受けません。
  - **タイトル行**: マルチチャートと同じ並びで、ダッシュボードの選択、基準日(前の日 / 日付 / 次の日 / 今日)、「編集」「削除」「全画面」。
    全画面は患者情報の下に広げ、「全画面終了」か Escape で戻ります。
  - **編集・保存**: 「編集」でカード追加(種別・タイトル)、見出しを掴んで動かす、右下の角で大きさを変える、ゴミ箱で削除、元に戻す / やり直す。
    保存先は院内共通 / 診療科 / 自分(院内共通・診療科は医師だけ)。選択中のダッシュボードは `?view=<id>` に載せ、前回選んだものは
    ブラウザに覚えて次に開いたときの初期選択にします。backend は `/master/clinical_dashboards`(`clinical_dashboards` 表、`Master::ScopedDefinitions`)。
- **SMARTアプリ**: 「その他」→「SMARTアプリ」で、管理画面「SMART アプリ」に登録した外部アプリ(SMART on FHIR の EHR launch)を
  開いている患者・ログイン中の医療者・外来の診察中の受診を文脈にして起動し、枠内(iframe)に出します
  (`docs/smart-app-launch-design.md`)。アプリは `/fhir` を通らず上流に直接認可されるので、見える範囲は
  OAuth クライアントに登録したスコープ(`user/` は施設内の全患者、`patient/` は開いている患者だけ)で決まります。
  選択中のアプリは `?view=<アプリ id>`。患者を切り替えると起動し直します。起動のたびに 5 分・単回の launch トークンを
  発行するので、アプリ側で再読込すると認可に失敗します -- そのときは「再起動」。「別ウィンドウ」のアプリは
  「開く」で新しいウィンドウに出します。紐づく医療者が無いログイン(`administrator`、認証なし)では起動できません。
- **カルテ印刷**: 「その他」→「カルテ印刷」で期間(開始日・終了日)と「履歴を印刷」を選び、「印刷」で
  別タブ(`/karte-print/:patientId?from&to&history`)に A4 のカルテ 2 号用紙を開いてブラウザで印刷します
  (PDF 保存もブラウザの印刷から)。
  - 日付の古い順に、左段「既往症・原因・主要症状・経過等」(診療記録・テンプレート・バイタル・パス評価)、
    右段「処方・手術・処置等」(処方・注射・部門オーダー)を並べます。対象はタイムラインと同じ全種別で、
    日付未定・日付なしの日は出しません。患者・期間・印刷日時の見出しは各ページに繰り返し、ページ番号を下に付けます。
  - カードの本文はタイムラインと同じ描き方なので、文字の色・大きさ、本文に貼った画像、シェーマもそのまま印字されます。
    ThinReports(1 項目 1 書式・固定位置の画像)では本文の装飾と差分の印を表せないので、帳票ではなく
    印刷用のページ(`pages/KartePrintPage.tsx`)と `window.print` で出しています。紙面はダークテーマでも白地で描きます。
  - 読み込みはタイムラインと同じ検索条件(`api/queries/karte.ts` の `karte*Params`)を期間で切って全件読み、
    `buildKarteTimeline` でカードにします(`api/queries/kartePrint.ts`)。上限で欠けたときは欠けていることを出します。
  - 「履歴を印刷」では、編集された記録の下に新しい編集から順に「第n版 → 第m版 日時」と 1 つ前の版との差分を添えます
    (変更履歴の差分と同じ比べ方。変わった行の前後 1 行と見出しだけを残し、間は「…」に畳みます)。白黒でも分かるよう、
    消えた行は取り消し線、増えた行は下線、変わった文字は太字です。版は 1 件ずつではなく型レベルの `_history` を
    `_id` / `based-on` / `identifier` のカンマ区切りでまとめて引き、カードごとに振り分けます(`groupCardVersions`)。
  - 上流は検索条件付きの型レベル履歴に対応済み(未対応パラメータは 400、患者トークンでは
    コンパートメント内に限る)。本番は fhir-server を先にデプロイしてください。
- **セクション間の移動**: 診療記録(退院時サマリー・看護サマリーも)の本文で Tab を押すと次のセクションの
  エディタへ、Shift+Tab で前のセクションへカーソルが移ります(移った先では文末)。テンプレート由来で
  直接編集できないセクションは飛ばします。セクションの操作バー(種別・装飾・画像・テンプレート・シェーマ・
  並べ替え・削除)は Tab の巡回に入れないので、前の入力欄からの Tab も本文に入ります。箇条書きの中では字下げ・字上げになり、最後の
  セクションの Tab はフォームの次の入力欄へ進みます(`RichTextEditor` の `TabToSiblingEditor`)。
- **診療記録へのリンク貼り付け**: オーダー・検査結果・各種レポート・ファイル・DICOM を、診療記録
  (退院時サマリーも)の本文からリンクで参照できます。
  - **取得**: 次の場所のケバブにある「リンク取得」を押すと、リンクがクリップボードにコピーされます。
    - カルテのカード(バイタル・パス評価を除く)
    - 検体検査・細菌検査・病理・読影・生理検査・内視鏡の各タブ(ボタン群の右端)。検体検査は
      結果表示のケバブ(変更履歴・FHIR JSON)を同じケバブにまとめ、詳細モーダルでは結果表の上に出します。
    - ファイル・DICOM の表示画面(ボタン群の右端)

    エディタに貼るとリンクになり、他所へ貼ると文字になります(`text/html` と `text/plain` の両方を載せるため)。
  - **開き方**: カードや詳細表示でリンクを押すと、オーダー・結果・レポートは詳細モーダル(`?detail=`)で
    開きます。詳細モーダルの無いファイル・DICOM はそのタブ(`?tab=file|imaging&view=<ID>`)で開きます。
  - **保存形式**: `section.text.div` に `<a href="DiagnosticReport/<id>" data-karte-link="lab-result">表示名</a>`
    の形で入ります。`href` はアプリの URL ではなく FHIR の相対参照で、`data-karte-link` は開き方です
    (詳細モーダルの種別か `file` / `imaging`)。
  - **制限**: リンクにできるのは、この形の参照だけです。
    - 外部 URL や形の崩れたリンクは、貼り付け時・表示時に文字だけになります。
    - 別の患者のカルテでコピーしたリンクも、貼り付け時に文字だけになります。クリップボードには
      患者 ID を添えますが、本文には残しません。
- **URL パラメータ**: 「どのタブで何を開いているか」は URL に載せます(`src/karteUrl.ts`)。
  `?tab=<karte|condition|allergy|lab>`、`?view=<ID or timeline>`、`?detail=<種別>:<ID>`、
  `?problem=<ID>`(プロブレムでの絞り込み)、`?card=<種別>`(情報の種別での絞り込み)の 5 つ
  (と、右ペインを特定の対象で始める一回限りの `?open=`。退院時サマリー・Web 問診の取込)で、
  個別の記録をリンクで共有でき、ブラウザの戻るも画面内の操作に効きます。詳細モーダルはタイムラインの
  読み込み位置に依存しないよう ID から引き直し、別患者の ID を指す URL では内容を出しません。
  入力途中のフォーム(タブの登録・編集、右ペイン)は URL に載せません(復元しても入力内容は戻らず、
  空のフォームだけが開く中途半端な状態になるため)。

診療記録・処方・病名・アレルギー・検査結果・テンプレート回答は、患者ごとの一覧ページを持たずカルテ画面で
扱います(患者一覧にあった「リスト」メニューと、その先の一覧・詳細・登録・編集ページは廃止しました)。

### 退院時サマリー(退院時要約)と文書作成の督促

右ペインの「退院時サマリー」から、**入院 1 件に 1 つ**の退院時サマリーを書きます(設計は
`docs/discharge-summary-design.md`)。診療記録と同じ `Composition` の器で、type は LOINC `18842-5`、
`encounter` に対象の入院を持ちます。対象は入院中・退院済のどちらでも選べ(退院前に用意する運用のため)、
選んだ入院に既にサマリーがあれば編集に切り替わります。

- **セクションは固定の 8 つ**(C-CDA on FHIR Discharge Summary のコード)。退院時診断・手術処置・退院時処方・
  アレルギーは候補のチェックリストで、選んだものを `section.entry` に参照として持ち、`text` はその表示名から
  生成します。入院経過・主な検査所見・退院時の状態・退院後の方針は診療記録と同じリッチテキストで、
  テンプレート記入・シェーマも同じ機構で使えます(施設独自の項目はテンプレートの埋め込みで吸収します)。
- **下書きは入院期間のデータから自動で集めます**。オーダーは入院(`Encounter`)を参照していないので、
  経過表と同じく患者 + 入院期間の日付範囲で引きます(病名・手術・処置・検査・退院処方(区分「退院」)・
  アレルギー・入院イベント)。「再収集」で候補だけを集め直し、書いた本文と選択は残ります。
- **転帰(退院先)**は標準要素 `Encounter.hospitalization.dischargeDisposition` に持ち、退院モーダルの
  任意欄とサマリーの転帰欄のどちらからも書けます(サマリーの保存で変えたときは同じ transaction で
  `Encounter` を PUT します)。
- 確定・署名・修正済み・変更履歴・削除は診療記録と同じです。カードのバッジは「退院時サマリー」、
  左ペインの種別では「診療記録」と分けて選べます(`?card=note:discharge-summary`)。退院時診断の
  `entry` が標準の `entry` 検索に乗るので、プロブレムの絞り込みにもそのまま出ます。
- **文書作成の督促**: 退院の transaction で期限付きの通知 Task(`document-due`)を主治医あてに作ります
  (期限 = 退院日 + 施設設定「文書作成の督促」の日数、既定 14 日。`Task.restriction.period.end`)。
  定期実行の主体がシステムに無いので、N 日後にサーバーが作るのではなく退院の時点で作り、**期限超過は
  通知一覧の表示時に判定**します。サマリーを確定で保存すると同じ transaction で対応済みになり、
  退院取消で取り下げます。確定済みのサマリーがある入院と、未対応の督促が残っている入院には作りません。
  通知の「カルテ」は `?open=discharge-summary:<入院の id>` でカルテを開き、右ペインをその入院の
  サマリーで始めます(一回限りの引数で、読んだら URL から消します)。入院患者一覧の退院患者の
  操作メニューにも同じ入口があります。

### Web 問診の取込

患者が自分の端末で回答した問診(`docs/web-intake-design.md`)は backend の DB に留まり、職員が右ペインの
「問診取込」で確認して保存したときに初めて QuestionnaireResponse になります。

- 取込待ちの回答があると患者帯に「用紙にチェック」のピクトグラム(アクセント色)が出ます。吹き出しの
  「問診を取り込む(回答日時)」で右ペインが開きます(`?open=intake:<回答の id>`。一回限りの引数)。
- 右ペインは「テンプレート回答の登録」と同じフォームに患者の回答を初期値として入れたものです。職員が
  直してから「登録」すると、通常の保存経路(Observation 生成・帳票も効く)で書き、QR には拡張
  `http://fhir-client.local/StructureDefinition/intake-source`(`valueCode` = `patient`)と、`authored` に
  患者が送信した日時が付きます。author は取り込んだ職員です。保存後に回答は「取込済」になり、
  「破棄」はカルテに書かずに閉じます。
- 回答した時点と取込の時点でテンプレートの版が違っても、回答は送信時の版(`url|version`)で開きます。

## ファイル取込（カルテの「ファイル」タブ）

患者ごとに任意のファイル(他院の紹介状・同意書・持参の検査結果・説明書のスキャンなど)を取り込みます。
設計の経緯は `docs/patient-file-design.md`。

- **保存先は上流の `DocumentReference` + `Binary`**。1 ファイルにつき本体を `Binary`、診療日・カテゴリ・
  表示名を `DocumentReference` に持ち、**1 本の transaction Bundle** で保存します(`fhir/patientFileHelpers.ts`。
  Bundle 内の参照は `urn:uuid` のプレースホルダで、上流が実 ID に書き換えるため孤児 `Binary` が生まれません)。
- **取込**は「取込」ボタンから。ファイル選択(複数可)とドラッグ&ドロップの 2 経路で積み、行ごとに表示名を
  直せます。診療日とカテゴリはフォーム 1 つぶんだけ持ちます(同じ日に受け取った同じ分類の書類をまとめて
  入れる使い方が中心のため)。
- **1 ファイルの上限は 7MB**。上流が本文 10MB で 413 を返し、base64 で約 4/3 倍になるためです。画像は
  `normalizeImageFile` で長辺 1600px に縮小してから数え、それ以外は無加工です。**複数ファイルは 1 ファイル
  1 Bundle で順に送る**ので、1 件が弾かれても他は残ります(「N 件を登録しました。◯◯は…」と返し、
  失敗したファイルだけがフォームに残ります)。
- **診療日は `DocumentReference.date`** に、その日の 0 時をローカルのオフセット付き(`2026-09-19T00:00:00+09:00`)で
  入れます。上流が索引している日付が `date` だけで、一覧の並び(`_sort=-date`)と期間検索を診療日で行うためです。
  登録・更新の時刻は `meta.lastUpdated` が持ちます。
- **カテゴリ**は `DocumentReference.category` に `http://fhir-client.local/CodeSystem/file-category` の code で
  入れ、`display` にカテゴリ名も焼き込みます(カテゴリを消しても取り込み済みのファイルの表示名は変わりません)。
  絞り込みは上流の `category` 検索で行うので、ページングと両立します。
- **カテゴリの管理**は「ファイル」タブの「カテゴリ管理」ボタンから、追加・改名・並べ替え・削除を行います
  (backend DB の `file_categories`。テンプレートカテゴリと同じ作りで、`code` は UUID を自動採番)。
- **一覧はどちらの見せ方でも診療日で区切ります**(見出しはグループの上端に貼り付きます)。カルテの
  タイムラインと同じ読み方に揃えるためで、表からは重複する診療日の列を落としています。日付を持たない
  ファイルは末尾に回します。
- **一覧は表とサムネイルを切り替え**られます(ヘッダのアイコン。選んだ側は localStorage に残します)。
  サムネイルで中身を読むのは画像だけで、PDF や Office は MIME ごとのアイコン(書類・表・スライド・
  書庫・音声・動画)を出します(1 ページ目を描くには別のレンダラが要るため)。
- **表示**は種類で出し分けます(画像は `<img>`、PDF は `<object>`、テキストは整形表示、それ以外は
  ダウンロードのみ)。中身は `Accept: application/octet-stream` を付けた `GET /fhir/Binary/<id>` で blob として
  取り、object URL にして描きます(`hooks/useObjectUrl.ts`)。
- **編集**できるのは表示名・診療日・カテゴリだけです。ファイル本体の差し替えはしません(消して入れ直します)。
  **削除は `DocumentReference` だけ**で、`Binary` は消しません(旧バージョンが参照しているため)。
- **タイムラインには出しません**。診療の経過そのものではなく「患者に付いている書類の束」なので、
  予約・指示簿と同じくタブでのみ見ます。
