# 検体検査・所見レポート

## 検体検査の結果項目マスタ

検査結果の項目は、施設の**結果項目マスタ**(`master_lab_result_items`、「マスタメンテ > 検体検査 > 検査結果項目」)で
持ちます。オーダー項目(頼む単位)とは別のテーブルで、データ型(数値 / コード / 順序コード / 文字列)・単位・
選択肢・材料を持ち、JLAC11 / JLAC10 / LOINC は任意の属性です。配布の共有項目JLACコードマスタ(`master_jlac_items`)は
取込のたびに全件洗い替えになる参照テーブルなので結果項目の本体にはせず、「配布JLACマスタから引き当て」で
属性を写す元として使います。設計の経緯は `docs/lab-backlog.md` §1。

- **オーダー項目 → 結果項目の対応**(`master_lab_order_item_results`、1:N)は検査オーダー項目マスタの編集画面の
  「返す結果項目」で決めます。結果登録画面はこの対応表でオーダーの検査項目を結果の行に展開します
  (血液ガス分析 1 件 → pH・PCO2… のように分かれる項目もここで表します)。パネルは構成項目がそれぞれ結果項目に
  対応するので、対応づけるのは単項目だけです。対応の無いオーダー項目は「展開していません」と名前を挙げます。
- **セットの中のパネル**(生化学セットの中の「ナトリウム及びクロール」など)はオーダーの明細に展開されないため、
  対応が無い項目は**パネル構成をたどって**結果項目まで解決します(`expand_panels=true`)。入れ子の深さは問いません。
- **初期投入**は単項目オーダー項目 1 件につき同じコードの結果項目を 1 件作って 1:1 で対応づけます
  (`Master::LabResultItemDerivation`。migration と `db:seed` の両方から呼び、既存行は上書きしません)。
  単項目なのに複数の結果を返す 6 件(尿沈渣・蛋白分画・血液ガス分析・精液一般・髄液一般)は分解した結果項目を
  `db/seed_data/lab_result_items.csv` / `lab_order_item_results.csv` で同梱しています。オーダー項目に JLAC11 があれば
  配布マスタからデータ型・単位・選択肢を写します。新しいオーダー項目には「結果項目作成」の導線があります。
- **測定法**(`method_name`)は試薬・機器の名称で、結果登録時に `Observation.method` へ写します
  (「配布JLACマスタから引き当て」で配布マスタの測定法名称が入ります)。
- **`Observation.code` の coding** は 施設の結果項目コード(`lab-result-item`)→ JLAC11 → JLAC10 → 略称 の順です。
  読み出し・時系列の行まとめ・検査分野のグルーピングは施設コードをキーにします。
- **結果項目マスタ導入前の検査結果**(施設コード無し、JLAC11 だけ)は読み出し側で読み替えます。保存済みの 17 桁は
  試薬・機器単位でマスタの代表コードと下 5 桁が違うため、測定物・識別・材料の **12 桁**で結果項目を引き当て、
  時系列では同じ行に合流させます(材料コードまで違う旧結果は別行のままです)。編集して保存し直すと施設コードが付きます。
- 感染症・腎機能・レジメンの検査値チェックは従来どおり JLAC11 の分析物コード(先頭 5 桁)で突き合わせます。
  結果項目に JLAC11 があれば coding に併記されるので動作は変わりません。

### パニック値(緊急異常値)の通知

パニック値を外れた結果を登録すると、**依頼医あての通知**(`Task`、`code = task-code|lab-panic`、
`focus` = その検査結果、`priority = stat`)が未確認の状態で作られます。宛先は紐付けたオーダーの
依頼医です。オーダーに紐付かない結果には宛先が付きません。

- **診療業務 > 通知**(`/notifications`)の種別「緊急異常値」で未確認のものを見ます(一覧の作りと
  自分あての絞り込みは[通知(Task)](notifications.md))。内容の列には項目・値・単位・判定(HH / LL の色付き)を
  分けて出します。1 件の通知に複数の項目が入るので、その中身は `Task.input` に構造化して持たせています
  (`Task.description` は Task をそのまま読む相手への説明として同じ内容を文にしたものです)。
- 行から**カルテ**(その検査結果を開く)と**確認**ができます。確認すると通知が完了になり、
  誰がいつ確認したかが `Task.note` に残ります。結果が最終報告なら、**検査結果の既読(来歴)も同時に残します**
  (次の節の「緊急の通知と検査結果確認は 1 件にまとめる」)。
- **訂正に追随します**。値を直してパニック値でなくなれば通知を取り下げ(`cancelled`)、訂正でまたパニック値に
  なれば同じ通知を書き換えて未確認に戻します(内容が変わったので改めて見てもらうためです)。
- 部門の進捗(受付・到着)の Task とは別物です。あちらは焦点がオーダーで宛先を持たず、こちらは焦点が
  検査結果で宛先と未確認・確認済みを持ちます(`fhir/labPanicHelpers.ts`)。

### 検査結果の確認(既読)

**最終報告**になった検査結果に、依頼医あての通知(`Task`、`code = task-code|result-review`、強度は
**お知らせ**)が未確認の状態で作られます。対象は検体検査・細菌検査・病理・放射線(読影レポート)・
生理検査と内視鏡(所見レポート)の 6 種別です。確認はカルテの「検査結果」配下の各タブ(またはカードから開く
レポートの詳細モーダル)で行い、通知の「カルテ」はそのタブをそのレポートを選んだ状態で開きます。

- **確認の記録は来歴**(`Provenance`)が正本です。`target` がそのレポート、`agent.type = verifier`、
  `signature` は代行入力の承認と同じ ASTM E1762 の Verification Signature で、「誰がいつ読んだか」を
  残します(`fhir/provenanceHelpers.ts` の `buildReviewProvenance`)。通知は宛先と未確認・確認済みだけを
  持ちます。確認すると、来歴の作成と通知を確認済みにする PUT を 1 つの transaction で送ります。
- **確認できるのは誰でも**です(緊急異常値と同じ)。宛先は依頼医ですが、当直医や主治医が先に読むことが
  あるので限りません。記録には確認した本人が残ります。
- **緊急の通知と検査結果確認は 1 件にまとめます**。同じ結果に緊急異常値(検体検査)・重要所見(読影・所見レポート)の
  通知が未確認で出ている間は、検査結果確認の通知を作らず、未確認のものがあれば取り下げます。宛先が同じ
  依頼医で、2 回確認させないためです。
  - 緊急の通知を**確認すると、最終報告なら既読の来歴も同時に残します**(未確認の検査結果確認があれば
    対応済みにします)。中間報告(暫定報告)のうちは既読を残さず、後で最終報告にしたときに検査結果確認を
    改めて作ります。
  - 逆に、カルテで結果を**確認すると、未確認の緊急の通知も一緒に対応済みにします**(結果を読めば
    緊急の内容も読んだことになるため)。
  - 確認済みの後に訂正して、緊急の通知が未確認に戻れば 1 件(緊急の通知)、戻らなければ 1 件
    (検査結果確認)が出ます。
- **中間報告のうちは通知も確認もできません**。値が変わりうるものを読ませても確認にならないためです。
  確定した後に**訂正すると未確認に戻ります**(通知は同じものを書き換え、画面は確認済みの印を外して
  「確認」に戻します)。判定は確認の時刻とレポートの最終更新(`meta.lastUpdated`)の前後で行います。
- **画面**は 3 か所です。診療業務 > 通知の種別「検査結果確認」、カルテの検体採取日ペイン(未確認の
  結果に小さな印)、確認の操作(3 種別ともカルテタブの見出し行の左端。登録・編集のボタンとは性質が
  違うので間を空けます)。**確認者と確認日時は印のツールチップ**で読みます(検査項目が見える領域を
  行で減らさないためです)。
- オーダーに紐付かない結果は宛先が決まりません(緊急異常値と同じで、一覧の「自分あてのみ」を外すと出ます)。
- 通知を作るのは**この仕組みを入れた後に登録・確定した結果から**です。過去の結果に遡って通知は作りません
  (未確認として一気に溜まると、いま出た結果が埋もれるためです)。過去の結果もカルテから確認はできます。

### 基準値と H/L の自動判定

数値型の結果項目には**基準値**(`master_lab_reference_ranges`)を性別・年齢帯ごとに複数行持てます
(結果項目マスタの編集画面の「基準値」)。適用する行は、性別が一致(または共通)し、検体採取日の満年齢が
年齢帯に入る行のうち表示順で先のものです。男女別の行と共通の行を混ぜるときは並びで優先を決めます。

- **結果登録画面**は結果値を入れた時点で基準値と突き合わせ、H/L のプルダウンに自動で入れます(下限未満 = L、
  上限超 = H)。手で直せます。基準値の列も並べて出します。基準値の列を足したぶん、登録フォームと内容表示の
  検査項目は**略称だけ**にし(略称が無ければ名称)、正式名称と長い材料名はツールチップで読みます。
  カルテの左ペインでも行が折り返さない幅に収めるためです。
- **保存時**に適用した基準値を `Observation.referenceRange`(`low` / `high`、`type = normal`)に写します。
  内容表示と時系列表示の「基準値」列はこの保存値を読むので、後でマスタを変えても過去の結果の基準値は
  変わりません(時系列は並びが先の結果、つまり最新の基準値を出します)。
- 患者の性別・生年月日が無いときは、性別・年齢帯の指定が無い行だけが当たります。基準値の無い項目や
  文字列・コード型の項目は従来どおり手で選びます。
- **パニック値(緊急異常値)**も同じ行に持ちます(下・上)。外れると H/L ではなく **HH / LL** と判定し、
  結果値を反転表示にしたうえで、依頼医あての通知を作ります(次の節)。
- **初期値**を `db/seed_data/lab_reference_ranges.csv` に同梱し、`db:seed` で入れます(148 行 / 128 項目)。
  パニック値は代表的な 13 件(白血球数・ヘモグロビン・血小板数・Na・K・Ca・血糖・血液ガス 3 件・
  PT-INR・フィブリノゲン)に入れてあります。
  出どころは行の備考に書いてあり、JCCLS 共用基準範囲・代表的なカットオフ値(腫瘍マーカー・BNP・D ダイマー
  など上限だけのもの)・参考値の 3 通りです。**migration からは入れません**。基準値は施設の測定系・試薬で
  決まる値なので、運用前に画面で確認・修正する前提です(ALP は IFCC 法、凝固系は試薬依存、蛋白分画は
  セルロースアセテート膜法の値です)。
- 基準値を入れる項目のうち、配布マスタに JLAC が無くて単位が入らなかったものは
  `db/seed_data/lab_result_item_units.csv` で単位を補います(未設定のときだけ入れます)。

### 報告区分(中間・最終・訂正)

結果登録画面の**報告区分**で 中間報告(`preliminary`)/ 最終報告(`final`)を選びます。確定した結果を
編集して保存すると**訂正報告**(`corrected`)に変わります(遷移は保存時に決まるので、確定済みの結果を
開いたときは選択欄ではなく「訂正報告」と出ます。診療記録・病理と同じ規約です)。病理の「修正報告」が
`amended` なのに対し検体検査で `corrected` を使うのは、値を直したという意味のコードで、
JAHIS 臨床検査データ交換規約(HL7 v2 の OBX-11 = "C" 訂正)に対応するのがこちらだからです。

- `DiagnosticReport.status` と `Observation.status` の**双方に同じ値**を書きます(項目だけ中間・
  レポートだけ確定という状態を作らないためです)。
- 印は 3 か所: 内容表示の「報告区分」(中間・訂正はバッジ)、カルテのカードのバッジ、
  累積表のセルの右肩(**◦ 中間報告 / ▴ 訂正報告**。列を増やさないための印で、凡例を表の上に出します)。
- **旧値**は上流のバージョン履歴(`_history`)に残ります。内容表示で項目にチェックを付け、
  ケバブの「選択項目の変更履歴」から 版 × 値・判定・基準値・コメント の表で読めます。
  履歴の照会は 1 項目 1 リクエストなので、選んだ項目だけを引きます。
- 中間報告でも**パニック値の通知は出します**(値が危険なことは確定前でも変わりません)。

### 結果に付随する情報

- **項目ごとのコメント**(`Observation.note`): 溶血・乳び・再検などの但し書き。登録画面は行末の
  アイコンで開く 1 行の入力欄、内容表示は行の右端のアイコン(押すと吹き出しで中身が出ます)。
  入る項目が限られるので、どちらも列を増やさない形にしています。
- **総合所見**(`DiagnosticReport.conclusion`): 検査室から結果全体に添える文。登録画面は検査項目の
  下に畳んであり(「＋総合所見」で開く)、内容表示は検査項目の表の下に枠で出します。
- **実施施設・実施者**(`DiagnosticReport.performer`): 自院(管理 > 施設設定)とログインユーザーを
  保存時に焼き付けます。入力欄は出さず、内容表示で読むだけです。編集しても最初に登録した実施者が
  残ります。外注(`docs/lab-backlog.md` B-2)が入るまで実施施設は自院固定です。
- **報告日時**(`DiagnosticReport.issued`): 保存のたびに更新するので、訂正した時刻が残ります。
  採取日(`effectiveDateTime`)とは別物です。
- **測定法**(`Observation.method`): 結果項目マスタの**測定法**(`method_name`)を写します。配布の
  共有項目JLACコードマスタの測定法名称(試薬・機器の製品名)から「配布JLACマスタから引き当て」で
  入り、手でも直せます。JLAC11 の測定法コード 3 桁は単独で引ける表が無いので、コードではなく
  名称を `text` に入れています。内容表示では検査項目名のツールチップに添えます。

### 検査結果の印刷

内容表示の「印刷」で、その 1 件の**検査結果報告書**(A4 縦の PDF)を新規タブで開きます。
`GET /reports/lab_results/:report_id/pdf`(`LabResultReport` → `Reports::LabResultRenderer`、
レイアウトは同梱の `backend/lib/report_layouts/lab_result.tlf`)。

- 頭に自院名・患者(患者番号・氏名・生年月日・性別)・印刷日時と、検体採取日・入外区分・診療科・報告区分・報告日時。
- 検査項目は**1 ページ 2 段**(左右に list を 1 本ずつ)。内容表示と同じ検査分野ごとに、左段を下まで埋めてから
  右段 → 次ページの順に流します(N 字)。
  列は 検査項目(略称)・結果値・判定・単位・基準値で、**材料は刷りません**。
- 段の頭が分野の途中なら「〜(続き)」の見出しを補い、段の最終行に見出しだけが残るときは次の段へ送ります。
- 判定のある結果値は太字にして右に H / L / HH / LL を出します。項目のコメントは項目の下に字下げした行で、
  総合所見は最後の分野の後ろに「総合所見」の見出しで続けます。

## 検体検査結果の取込

検査室の分析装置・LIS・外注ラボから受け取ったファイルを読み込み、手入力と同じ形で結果を登録します。
入口は**部門業務 > 臨床検査部門 > 検査結果取込**。対応形式は JAHIS 臨床検査データ交換規約
(HL7 v2.5)の **ORU^R01**(ファイル転送型の正式形)と **OUL^R22**(会話型)です。設計は
`docs/lab-result-import-design.md`。

- **文字コード**は自動で判定します(BOM → ESC シーケンス → MSH-18 の宣言 → UTF-8 として妥当か →
  CP932 の順)。判定に使った根拠を詳細画面に出すので、化けたときに原因を追えます。外れるファイルは
  取込画面で UTF-8 / Shift_JIS / ISO-2022-JP を指定できます。宣言と中身が食い違うファイルは
  取り込まずに指定を促します。
- **結果項目の引き当ては JLAC10 / JLAC11 が正本**です。完全一致 → 17 桁の先頭 12 桁
  (測定物・識別・材料)の前方一致の順で引きます。複数当たった行・当たらなかった行は**保留**に
  なり、詳細画面で結果項目を選びます。そのとき「結果項目マスタに JLAC を書き込む」(既定 ON)で
  選んだ項目の空の JLAC を埋めると、次回からは自動で当たります。取込元ごとのコード対応表は
  持たず、**結果項目マスタの JLAC を育てる**形です。このため運用前に結果項目マスタの JLAC を
  入れておくほど手間が減ります。
- **値も検証します**。コード型(CD / CO)の値が選択肢に無い行、数値型(PQ)に `<5` のような
  数値でない値が来た行は保留になり、画面でその場で選び直す / 打ち直せます。
- **候補**(HL7 の ORC・OBR 群)1 件が検査結果 1 件になります。患者とオーダーは
  ①人が選んだオーダー → ②検体ラベル番号 → ③患者番号 + 採取日 の順で決めます。ラベル番号から
  引いた管がファイルの患者と違うときは採らず、患者番号で照合し直します。採取日のオーダーが
  無ければ「オーダーに紐付けずに登録」、複数あれば画面で選びます。
- **H/L は施設の基準値で付け直します**。基準値を持たない項目だけファイルの異常フラグ(OBX-8)を
  写します。ファイルの基準範囲(OBX-7)は画面に参考として出すだけで保存しません。
- **登録**は手入力と同じ道(`useCreateLabResult` / `useUpdateLabResult`)を通るので、パニック値の
  通知・結果確認の通知・報告区分の遷移がそのまま効きます。既に結果があるオーダーに取り込むと
  既存のレポートへの追記になり、確定済みなら**訂正報告**になります。報告区分はファイルの
  OBR-25 から決めます(`P` → 中間報告、`F` / `C` → 最終報告)。
- OBX-11 が `X`(結果なし)・`D`(削除)の行と、SPM 直下の OBX(検体の状態)は取り込みません。
- 同じメッセージ ID のファイルを取り込むと詳細画面で知らせますが、取込は止めません
  (訂正版が同じ ID で来ることがあるためです)。二重登録は「既に結果があるオーダーは追記になる」
  ことで防ぎます。

## 放射線検査の読影レポート

放射線検査のオーダーに 1 件ずつ、読影レポート(`DiagnosticReport`)を付けます。設計は
`docs/rad-report-design.md`。

- **入口**は 2 つで、同じモーダルが開きます。**部門業務 > 放射線検査一覧**の実施済の行の「読影」
  (登録済みなら「読影編集」)と、カルテの放射線カードのメニュー「読影レポート登録 / 編集」。
  モーダルの上には依頼内容と実施情報(撮影日時・造影剤・被曝線量)を畳んで出します。
- **入力**は報告区分(暫定 / 最終)・所見・診断・重要所見・画像。最終報告は診断が必須です。
  確定済みのレポートを直すと**訂正報告**(`amended`)になり、保存ボタンが「訂正報告として更新」に変わります。
  所見・診断はテンプレートからも記入でき、撮影項目マスタの「既定のテンプレート > 読影所見」で
  所見の既定を決められます。読影医(`resultsInterpreter`)と発行施設(`performer`)は保存時に
  ログイン中の医療従事者と自院を焼き付けます。
- **画像**はいくつでも添付でき、ファイル選択(複数可)・画像欄へのドラッグ&ドロップ・貼り付けの
  3 通りで足します。CT・MR の濃淡画像なので長辺 1600px の JPEG にします。1 枚ずつキャプションを付け、
  上下で並べ替えられます。サムネイルを押すと拡大表示(前後の送り、描き込みと元画像の切り替え)。
- **描き込み**は元画像を書き換えず、合成画像を別の `Binary` に持ちます
  (`extension[rad-report-image]` の `source` と `annotated`)。「描き足す」「描き直し」
  「描き込み削除」ができます。暗い画像の上で見えるよう、色は黄・赤・水色・白です。
- **1 回の保存で新しく送る画像の量に上限**があります(base64 で 7MB)。上流が本文 10MB で打ち切るためで、
  超えたら「いったん保存してから追加してください」と出ます。保存済みの画像は再送しないので、分けて
  保存すれば枚数の制限にはなりません。
- **重要所見**をチェックして要点を書くと、依頼医あてに**アラート**の通知を出します(暫定報告でも出します)。
  要点を書き換えると未確認に戻り、チェックを外すと未確認の通知は取り下げます。重要所見が未確認の間は
  検査結果確認の通知を出さず、重要所見を確認すると最終報告なら既読も残ります(「検査結果の確認(既読)」)。
- **カルテ**の放射線カードには暫定・訂正のバッジを出し、メニューの「読影レポート表示」で内容を開きます。
- 読影レポートのあるオーダーは、**実施の取消とオーダーの削除ができません**(レポートの根拠が消えるため)。
  先にレポートを削除します。レポートを削除すると、所見・テンプレートの記入内容を消し、未確認の通知を
  取り下げます。画像の `Binary` は消しません(旧版が参照するため)。

## 生理検査・内視鏡の所見レポート

生理検査と内視鏡のオーダーに 1 件ずつ、所見レポート(`DiagnosticReport`)を付けます。読影レポートと
同じ部品(`fhir/examReportHelpers.ts`・`components/ExamReport*.tsx`)を種別の設定だけ変えて使うので、
入力・画像・描き込み・報告区分・重要所見・既読・取消と削除の制限は読影レポートと同じ振る舞いです。
設計は `docs/exam-report-design.md`。

- **入口**: **部門業務 > 生理検査一覧 / 内視鏡一覧**の実施済の行の「所見」(登録済みなら「所見編集」)と、
  カルテの生理検査・内視鏡カードのメニュー「所見レポート登録 / 編集」。一覧には「所見」列(未 / 暫定 / 最終 / 訂正)。
- **入力の違い**: 記載医(`resultsInterpreter`)を保存時に焼き付けます。生理検査は「診断」を「判定」と呼びます。
  描き込みの色は、内視鏡が放射線と同じ明るい色、生理検査(白地の波形)は既定の色です。
- **既定テンプレート**: 検査項目マスタの「既定のテンプレート > 所見」。`docs/report-mappings/` に
  心電図(`PHY_ECG_RPT_01`)・上部内視鏡(`END_EGD_RPT_01`)・大腸内視鏡(`END_CS_RPT_01`)を用意してあり、
  テンプレート一覧のインポートから取り込みます。内視鏡の検査時情報・偶発症は JED 用語集[基本情報]の統一表記です。
- **カルテのタブ**: 「検査結果」配下の「放射線検査」「生理検査」「内視鏡」。病理検査タブと同じく、左に検査日
  (放射線は撮影日)を新しい順に並べ、選ぶと右にレポートを出します。確認(既読)・「新規登録」・「編集」もここから。
  登録・編集は病理検査タブと同じく**タブの中**でフォームに切り替わります(新規登録は実施済でレポートの無いオーダーを
  選んでから書きます)。カルテのカード・部門一覧からはモーダルで開きます。
- **区別**: `category` にオーダー種別(`order-type|physio` / `order-type|endoscopy`)と v2-0074 の `OTH` を持つので、
  検体検査・細菌・病理の結果タブには混ざりません。
