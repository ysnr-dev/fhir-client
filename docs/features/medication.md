# 処方・注射

## 処方オーダー機能

カルテ画面の右ペイン「処方」から新規登録し、タイムラインのカードから表示(詳細モーダル)・編集・削除・DO
を行います。編集・削除も登録と同様に transaction Bundle で行い、`ServiceRequest`・`MedicationRequest`を
まとめて更新・削除します(フォーム上で削除された薬剤行は `DELETE` エントリとして送信されます)。

- **リソースの持ち方**: 1処方 = `ServiceRequest` 1リソース + 薬剤数分の `MedicationRequest`。
  fhir-server がトランザクション Bundle (`POST /`) に対応しているため、登録は **1回の transaction
  Bundle POST**（`ServiceRequest` → 各 `MedicationRequest` の順、`urn:uuid` で相互参照)で行い、
  一部が不正なら全体がロールバックされます。
- **SR→MRの紐づけ**: `MedicationRequest.basedOn` は fhir-server で検索できないため、代わりに
  `ServiceRequest.orderDetail[].extension`（ローカル定義の
  `http://fhir-client.local/StructureDefinition/prescription-medication-request`）に
  `valueReference` で各 `MedicationRequest` の `urn:uuid` を持たせています(Bundle 内での参照解決により
  実IDへ書き換わります)。処方詳細画面はこの extension から MedicationRequest の id を取り出し、並列 read
  で内容を取得します(`_id` のカンマ区切り検索に fhir-server が対応していないため)。
- **RP・医薬品**: 用法・医薬品はいずれもマスタデータAPI([master-data.md](master-data.md))から検索して選択します。RP・医薬品行は
  フォーム上で動的に追加/削除でき、RP番号は自動連番です。**頓用は用法コードの 3 桁目(`5`)で判定**し
  (用法マスタの `basic_usage_category` は 内服 / 外用 / 注射 / 注入 の 4 種で「頓服」が無いため)、
  頓用なら「投与回数」、頓用でない内服なら「投与日数」を入力します。判定は
  `fhir/medicationScheduleHelpers.ts` の `isAsNeededUsage` と `fhir/prescriptionHelpers.ts` の
  `hasDoseDays` に集約していて、フォーム・調剤登録・カードの表示が同じ関数を通ります。
- **オーダー種別**: ほかのオーダーと同じく `ServiceRequest.category` の先頭にオーダー種別
  `order-type|prescription` を持ち、処方一覧・カルテ・経過表などはこの種別で引きます。続けて入外区分
  (`.../prescription-setting`)と処方区分(`.../prescription-category`)を入れます。
- **入院のオーダー**: 入院中に登録した処方は `ServiceRequest.encounter` にその入院を入れます
  (与薬の実施記録がここから Encounter を写します)。
- **処方区分の初期値**: 入外区分で選択肢が違う(入院=定期/継続/臨時/退院/緊急、外来=院外/院内)ので、
  初期値も入外区分ごとに施設設定(管理 > 施設設定「処方区分の初期値」)で持ちます。フォームを開いた
  ときと入外区分を選び直したときに入り、未選択(その都度選ばせる)のままにもできます。登録済みの処方には
  区分が焼き付いているので、設定を変えても過去の処方は動きません。
- **薬剤の安全性チェック**: 医薬品を選ぶと、その行にアレルギー(銘柄・成分)と重複投与
  (フォーム内の別の行、投与中の他の処方)の警告、医薬品名の後ろに麻薬・毒薬・覚醒剤原料・
  向精神薬・生物由来製品・造影剤の印を出します。**登録は止めません**(判断は医師のもの)。
  処方・注射・医薬品検索モーダルが `fhir/medicationSafetyHelpers.ts` と
  `components/MedicineWarnings.tsx` を共用します。同一成分は YJ コードの上 7 桁で見るため、
  同じ成分でも薬効分類が違えば(アスピリンとバイアスピリン)重複になりません。
  継続・中止の判断が済んでいない持参薬も重複の相手に数えます(「同一成分を服用中(持参薬)」)。
- **調剤指示**: RP の用法のメニュー「調剤指示」で、一包化・粉砕・別包化・混合を選べます(複数可。持参の処方には
  出ません)。RP 内の明細すべての `dispenseRequest.extension` に JP Core の `instructionForDispense` 拡張を
  コードごとに書きます(コードは JAMI の調剤方法コード `http://jami.jp/CodeSystem/DrugDispensePreparationMethod`)。
  カード・詳細・調剤登録の用法の下と、処方箋の用法の次の行に「調剤指示: 一包化・粉砕」と出ます。
- **後発品変更不可**: 外来の銘柄処方は、薬剤行のメニュー「後発品変更不可」で「医療上必要」か「患者希望」を
  付けられます(一般名処方と入院処方には出ません)。`MedicationRequest.substitution` に JP Core の変更可否コード
  「1 後発品変更不可」を入れ、理由をローカルコード(`.../substitution-not-allowed-reason`)で区別します。
  カード・詳細に「変更不可」「患者希望」の印が出て、院外処方箋(様式第2号)では同名の列に「レ」、院内処方箋では
  薬品名の後ろに【変更不可】【患者希望】を刷ります。調剤登録ではその薬剤の銘柄を変更できません。
- **処方区分「持参」**: 継続した持参薬を院内処方に起こしたもので、持参薬タブの「継続」からだけ作ります
  (医師が選ぶ選択肢・施設設定の初期値には出ません)。薬剤部は調剤せず、処方箋 PDF を出さず、
  請求にも載せません。処方一覧には並び、中止はそこからもできます。詳細は下の「持参薬」。
- backend の `/fhir` プロキシは `ALLOWED_RESOURCE_TYPES` に `ServiceRequest` を追加し、
  `POST /fhir`(空パス)を transaction Bundle 中継用のルートとして扱います
  (`backend/app/controllers/fhir_proxy_controller.rb`)。

## 疑義照会

薬剤部から処方医への問い合わせと回答を、通知(`Task`)で往復させます(`fhir/rxInquiryHelpers.ts`)。処方と注射で共通です。

- **照会**: 処方一覧・注射一覧の行の「疑義照会」から、照会内容を書いて送ります。照会 1 件 = 通知 1 件
  (`rx-inquiry`)で、焦点と `basedOn` はオーダーのヘッダ、宛先はオーダーの依頼医、`requester` は照会した薬剤師、
  照会内容は `input` です。依頼医の無いオーダーには照会できません。1 オーダーに同時に出せる照会は 1 件です。
- **照会中は調剤・払出を止めます**。照会と同じ transaction で進捗 Task(`rx-dispense` / `injection`)を `on-hold`
  (照会中)にし、一覧から「調剤登録」「払出登録」が消えます。依頼済から照会したときも、受け取ったものとして
  回答後は受付済へ進みます。
- **回答**: 処方医は通知の「カルテ」かカードの「疑義照会中」から詳細を開き、疑義照会の区画の「回答」で
  回答区分(処方どおり / 薬剤部で変更してよい / 処方を変更する)と回答文を書きます。回答は照会の `output`
  に入り、照会は対応済みになります。同じ transaction で、照会した薬剤師あての回答の通知(`rx-inquiry-answered`)を作ります。
  - 処方どおり・薬剤部で変更してよい: 進捗を受付済へ戻します。
  - 処方を変更する: 回答のあと右ペインでそのオーダーの編集を開き、進捗は「処方変更待ち」(`statusReason`)のまま
    止めます。オーダーの編集を保存すると、同じ transaction で受付済へ戻します。
- **取下げ**: 回答前なら、薬剤師が同じ「疑義照会」から取り下げられます(照会を `cancelled`、進捗を受付済へ)。
- **見えるところ**: 一覧のステータスは「照会中」「処方変更待ち」、回答のあった行には回答区分の印。照会と回答の
  履歴は一覧の「表示」・調剤登録・払出登録と、カルテの詳細に出ます。カルテの処方カードには「疑義照会中」
  「処方変更待ち」の印を、注射カードは進捗の表示で出し分けます。注射カレンダーの記号は受付済と同じです。
- 調剤登録・払出登録をすると、そのオーダーの回答の通知を閉じます。照会の仕組みを入れる前に調剤登録・払出登録の
  自由記載欄で書いた記録(進捗 Task の `note`)は、履歴の下にそのまま出します。

## 持参薬

入院時に患者が持ってきた薬を、カルテの「持参薬」タブ(患者情報のグループ)で登録し、薬剤部が
「部門業務 > 薬剤部門 > 持参薬鑑別一覧」で鑑別し、医師がタブで継続・休止・中止を決めます。
設計は `docs/brought-medication-design.md`。

- **リソースの持ち方**: 持参薬 1 剤 = `MedicationStatement` 1 件(`context` = 入院)。聞き取り・鑑別・
  医師の判断はローカル拡張 3 つに持ち、状態は `status` + `statusReason` で表します(未鑑別・未判断は
  active、継続は active + continue、休止は on-hold、中止は stopped、服用していないは not-taken)。
- **鑑別依頼**: 登録と同じ transaction で入院を焦点にした `Task`(`brought-med-review`)を作ります
  (1 入院に閉じていないもの 1 件)。鑑別一覧で鑑別開始 → 鑑別 → 鑑別完了と進め、鑑別完了で主治医に
  通知「持参薬鑑別済」を出します。判断が出揃うと通知は自動で閉じます。
- **継続**: タブで選んだ持参薬から処方登録(区分「持参」、日数は残日数、代替薬があれば代替薬)を開き、
  処方と持参薬の更新を 1 つの transaction で送ります。処方の明細は `supportingInformation` で元の
  持参薬を、持参薬は拡張で起こした処方を指します。
- **退院**: 退院モーダルで、継続中・休止中の持参薬を終了(completed)にします。
- プロファイルタブには入院中だけ「持参薬」の要約(件数・未鑑別・未判断)が出ます。

## 服薬指導

医師がカルテの右ペイン「服薬指導」で薬剤師に服薬指導を依頼し、薬剤部が「部門業務 > 薬剤部門 >
服薬指導一覧」(`/medication-guidance-worklist`)で受付 → 担当薬剤師の登録 → 入院中の指導(実施)→ 終了と
進めます。設計は `docs/medication-guidance-order-design.md`。

- **栄養指導と同じ期間継続型**です。オーダーは `ServiceRequest` 1 本(`category` = `order-type|medication-guidance`)で、
  進捗の `Task` は「薬剤部の受け入れ状態」(依頼済 → 実施中 → 終了 / 中止)、1 回の指導は `Procedure` 1 件で
  積み上がります。実施しても進捗は動きません(初回の指導で終了扱いにならないように)。
- **オーダーの項目**: 指導区分(服薬指導 / 退院時指導。`code`)、指導条件(ハイリスク薬・麻薬・吸入や自己注射の
  手技など、複数可。`orderDetail`)、対象薬剤、指導してほしいこと、期間(開始日・終了日。終了日が無ければ継続)、
  対象プロブレム、入外区分、薬剤部への連絡事項。指導区分と指導条件は診療報酬の区分に沿った固定の分類なので、
  DB マスタを持たずフロントの定数に置いています。
- **担当薬剤師**は進捗の `Task.owner` に持ちます(一覧の行のケバブ「担当」)。一覧は担当(自分 / 未定)でも絞れ、
  薬剤師のホームの「服薬指導」カードは担当未定の件数も出します。
- **実施入力**: 指導種別(服薬指導 / 服薬指導(ハイリスク薬)/ 退院時指導)、理解度、担当薬剤師、指導内容。
  指導種別は、退院時指導のオーダーなら退院時指導だけ、ハイリスク薬の条件付きならハイリスクが初期値です。
  指導内容はテンプレートからも書けます(回答は実施を取り消すと一緒に消えます)。
- **終了**は一覧のケバブから終了日を入れて行い、オーダーにも終了日を書きます(書かないと一覧に出続けるため)。
  退院モーダルでも「服薬指導オーダーを退院日で終了する」で一緒に止められます。
- カルテのカードは開始日に載り、受付済以降は実施履歴(直近 3 件と件数)を出します。
- 会計連携(薬剤管理指導料)はまだです。会計送信のプレビューでは
  「服薬指導」が送れない項目として出ます。

## 薬剤付加情報

マスタメンテ「医薬品」>「薬剤付加情報」(`/medicine-attributes`)で、医薬品マスタに無い施設独自の薬剤の設定を
1 薬 1 行で持ちます。設計は `docs/lot-number-design.md`。

- 項目は「ロット管理」(実施時にロット番号を記録する薬)、「特定抗菌薬」(- / 届出制 / 許可制)、「DDD」(1 日規定用量、
  g・mg・MU)です。特定抗菌薬と DDD は抗菌薬(薬効分類 61・622・624)にだけ設定でき、それ以外の薬では「-」になります
  (抗菌薬適正使用、`docs/antimicrobial-stewardship-design.md`)。項目の定義は backend の
  `Master::MedicineAttribute::ATTRIBUTES` 1 か所で、画面の列も API の定義から組み立てます。項目を足すときは
  表に 1 行足すだけで、migration は要りません。
- 医薬品マスタの生物学的製剤の印がある薬は、行が無くても「既定」でロット管理の対象です(一覧の「既定で対象の薬も
  表示」で並びます)。チェックを外すと行を作って既定を外します。行を削除すると既定に戻ります。
- 「＋薬剤」で医薬品を選んで行を足します。

## 抗菌薬適正使用(AST)

特定抗菌薬の警告と届出、AST チームの一覧、抗菌薬の使用量(AUD・DOT)の集計。設計は `docs/antimicrobial-stewardship-design.md`。

- **警告**: 処方・注射のフォームの薬の行に、薬剤付加情報で特定抗菌薬にした薬は「特定抗菌薬(届出制 / 許可制)」、同じ成分の抗菌薬を
  続けて投与していて開始日が 7 日目以上なら「投与 N 日目」(14 日目以上は強い警告)を出します。登録は止めません。
- **届出の通知**: 特定抗菌薬を含む処方・注射を登録すると、依頼医に「特定抗菌薬の届出」が届きます(連日の注射は 1 件)。
  届出書(テンプレート `AST_NOTIFY_01`)を保存すると、届出制は完了、許可制は「許可待ち」になり、AST チームの構成員が許可すると完了します。
- **一覧**(部門業務 > 薬剤部門 >「抗菌薬適正使用」、`/ast-worklist`): 使用中(特定抗菌薬)・長期投与(7 日以上)・血液培養(直近 14 日の陽性)・
  届出(届出書の記入と許可)・集計(月 × 病棟の DOT・AUD、CSV)のタブ。行から AST チームへのチーム依頼を出せます。
  薬剤師のホームに届出未提出・許可待ちの件数のカードが出ます。

## 特定生物由来製剤のロット番号

特定生物由来製品などのロット番号を実施時に記録し、ロットから投与した患者を逆引きします。設計は
`docs/lot-number-design.md`。

- **入力**: 注射・処置・手術・内視鏡・放射線(造影剤)の実施入力で、薬剤付加情報でロット管理の薬の行に
  「ロット番号」欄が出ます。全角は半角にそろえます。空でも登録でき、空の行があると列見出しに「未入力」が出ます。同じ記録の
  同じ薬に同じロットが重なると登録できません。
- **持ち方**: `MedicationAdministration` のローカル拡張 `medication-lot-number`(輸血の製剤番号
  `transfusion-lot-number` と同じ作法)。カルテの実施履歴では薬剤に「ロット ○○」を添えます。
- **ロット管理画面**(部門業務 > 薬剤部門 >「ロット管理」、`/lot-management`):
  - ロット検索: ロット番号(前方一致、完全一致も可)から実施日時・患者・種別・薬・量を並べ、CSV で出せます。
    輸血の製剤番号も同じ検索で引けます。
  - ロット未入力: 期間内の実施記録から、ロット管理の薬でロットの無い投与を並べます。行の「ロット入力」で後から
    入れます(投与記録の版を確かめて拡張だけを書き足します)。
- 上流の `MedicationAdministration?lot-number` に依存するので、本番は fhir-server を先にデプロイします。

## 注射オーダー機能

カルテ画面の右ペイン「注射」から新規登録し、処方と同じくタイムラインのカードから
表示(詳細モーダル)・編集・削除・DO を行います(JAHIS注射データ交換規約 Ver.2.2 /
JP Core の `JP_MedicationRequest_Injection` プロファイルを参考にした表現)。

- **リソースの持ち方**: 処方と同一(1注射 = `ServiceRequest` + 薬剤数分の `MedicationRequest`、
  RP = 同じルートから同時に投与する薬剤のまとまり(混注)、登録・更新・削除は transaction Bundle)。
  実装は `frontend/src/fhir/injectionHelpers.ts`。
- **処方との判別**: `ServiceRequest.category` にローカルのオーダー種別
  (`http://fhir-client.local/CodeSystem/order-type` = `injection`)を付与します。カルテの
  タイムラインは処方と同じ `ServiceRequest` 検索(1本のページング)で取得し、この category で
  処方カード/注射カードに振り分けます(処方は `order-type|prescription`)。
- **入外区分・注射区分**: `category` にはオーダー種別に続けてこの2つも入れます。入外区分
  (入院/外来)は処方と同じコードシステム(`.../prescription-setting`)を共用し、注射区分は
  選択肢が処方と異なるため専用のコードシステム(`.../injection-category`)にしています
  (入院→定時/臨時/緊急、外来→外来)。category は 3 要素になるので、読み出しは処方
  (添字で引く)と違い system で引きます。
- **用法**: JP Core の `JP_MedicationDosage_Injection` に寄せて `dosageInstruction` に持ちます。
  - 用法種別(点滴/ワンショット): 対応する標準コード表が無いためローカル拡張
    (`http://fhir-client.local/StructureDefinition/injection-usage-type`)
  - 投与経路: `route`。JP Core の `route-codes`(HL7 Table 0162 ベース。IV/IM/SC など)
  - 投与部位: `site`。JAMI標準用法規格 表13 外用部位コード(`urn:oid:1.2.392.200250.2.2.20.32`。
    SS-MIX2 でも利用されるコード表)
  - 手技: `method`。JAMI詳細用法コード(`urn:oid:1.2.392.200250.2.2.20.40`)の注射手技(30〜3Z)。
    投与経路から手技が一意に決まるもの(筋肉内→筋肉内注射、皮下→皮下注射、皮内→皮内注射、
    動脈内→動脈注射、髄腔内→脳脊髄腔注射、腹腔内→腹腔内注射)は経路の選択時に自動で入れます。
    静脈内だけは末梢の静脈注射(30)と中心静脈注射(31)のどちらもありうるので自動選択しません。
    経路を選び直したときは、前の経路に固有だった手技は経路と食い違うので落とします
  - ライン: JP Core の `JP_MedicationDosage_Line` 拡張。コードは公式表が無いためローカル定義
    (末梢/中心静脈 × 本管/側管)
  - 投与速度: `doseAndRate.rateQuantity`(mL/h、UCUM)。点滴のときのみ入力(下記の自動計算あり)
  - 開始時刻: `timing.event`(複数可)。入力は時刻(HH:mm)のみで、日付は注射日を使う。
    FHIR の dateTime は時刻を持つならタイムゾーンが必須なので、実行環境のオフセットを付けて
    `2026-08-04T10:00:00+09:00` の形で保存する
  - 投与量: `doseAndRate.doseQuantity`(処方の用量と同じ持ち方)
- **医薬品検索**: 処方と同じ医薬品検索モーダルを剤形区分 4(注射薬)で初期絞り込みして使います
  (`/master/medicines` に `dosage_form` パラメータを追加)。
- **総投与量と投与速度の自動計算**: 投与量は薬価算定単位(袋・管・瓶…)で入力するため、
  投与量換算マスタ(`master_medicine_dose_conversions` の `from_unit = mL` の行。
  1[薬価算定単位] = `factor` [mL])を掛けて RP 内の薬剤を mL に揃え、合計を **総投与量**として
  常時表示します(ワンショットでも表示)。点滴では **投与時間**(30分〜24時間)を選ぶと
  `総投与量 ÷ 投与時間` を投与速度(mL/h)として自動計算し、その間は投与速度が読み取り専用に
  なります。投与時間を「指定なし」に戻すと計算値を初期値として直接入力に切り替わります。
  保存するのは計算結果の投与速度だけで、投与時間は FHIR に持たせません(編集時は直接入力に戻る)。
  mL 換算行を持たない医薬品(粉末バイアル等、容量がマスタに無いもの)は合計から除外し、
  「N件はmL換算できないため含みません」と件数を添えます(注射薬 4176 件のうち mL 換算を
  持つのは 2569 件。輸液バッグは 583 件中 545 件と、量を占めるものは概ね揃っています)。
  RP 内の医薬品はまとめて引くため、`/master/medicine_dose_conversions` の `medicine_code` は
  カンマ区切りの複数指定に対応し、`from_unit` での絞り込みも追加しています。
- **用法種別の自動入力**: 医薬品を選ぶと、包装(薬価算定単位)から点滴/ワンショットを推定して
  用法種別に入れます(`frontend/src/fhir/usageMapping.ts` の `presetInjectionUsageType`)。
  点滴かワンショットかは本来オーダーの指示であって医薬品の属性ではないため確定はできませんが、
  包装は強い手がかりになります(注射薬 4176 件で確認: アンプル(管)に 100mL 以上は 0 件、
  バッグ(袋)は 95% が 100mL 以上)。判定は上から順に、名称に「点滴」→ 点滴 / 袋 → 点滴 /
  キット(名称に「シリンジ」を含むものを除く)→ 点滴 / 瓶かつ注射容量 100mL 以上(輸液ボトル)
  → 点滴 / 管・筒・シリンジのキット → ワンショット / それ以外(主に粉末バイアル)は空。
  これで約 73% に既定値が入り、残りはユーザーが選びます。
  判定は RP 単位で行い、混注は「輸液 + アンプル」の構成になるので **RP 内に点滴の薬剤が
  1 つでもあれば点滴**とします。用法種別を手で選んだ RP は、以降医薬品を変えても上書きしません。
  点滴になったときは投与経路の既定として静脈内(`IV`)を入れます(自動判定・手動選択のどちらでも)。
  投与経路が選択済みなら上書きしないので、手で選んだ経路が医薬品の入れ替えで戻ることはありません。
- **期間・実施パターン(連日オーダー)**: 注射日(開始日)と終了日、実施パターン
  (**毎日 / N日ごと(隔日など) / 曜日指定**)を指定すると、該当する日ぶんを 1 日 1 オーダー
  (`ServiceRequest` + `MedicationRequest`)に展開し、1 つの transaction で登録します
  (一度に 14 件・期間 90 日まで。上限超過は打ち切らず入力エラーにします)。
  展開した各日は `requisition`(`.../Identifier/injection-series`、同じ uuid)で束ね、開始日を
  root 拡張 `.../StructureDefinition/injection-series-start`(valueDate)、実施パターンを
  `.../StructureDefinition/injection-series-schedule`(valueTiming。N日ごと=`period/periodUnit`、
  曜日=`dayOfWeek`、`boundsPeriod` に期間)に持ちます(毎日は拡張を付けず、無いものは毎日と読みます)。
  カードには「連日 N日目(開始日〜)」「隔日(開始日〜)」を添え、編集・削除では後続日があるとき
  「この日のみ / この日以降すべて」を選べます。方針の検討(オリジナルオーダー方式との比較)は
  `docs/injection-order-design.md`。
- **進捗と中止**: オーダーの `ServiceRequest` はそのままに、進捗を `Task`
  (`task-code|injection`、依頼済/受付済/払出済/実施済/中止)で持ちます。Task は最初の
  ステータス変更で作り、それまでは「Task が無い = 依頼済」として扱います。カルテのカードの
  ケバブから中止・中止取消ができ、連日オーダーでは「この日のみ / この日以降すべて」を選べます
  (実施済の注射は中止できません)。受付済・払出済へは注射一覧、実施済へは実施入力で進みます。
  詳細は `docs/injection-order-design.md` §5。
- **実施記録(施用)**: カードのケバブ「実施入力」から、施用の開始・終了時刻、実施者、結果
  (実施 / 途中で中止 / 実施せず)と理由、薬剤ごとの実施量を登録します。オーダーに無い薬剤も
  RP ごとに追加でき(依頼時と実施時で内容が変わることが多いため)、その `MedicationAdministration`
  は `request` を持たず、カードでは「(追加)」と印が付きます。輸血と同じく実施 1 回を
  `Procedure`(`category = order-type|injection`、`basedOn` = オーダー)のハブにし、薬剤ごとの
  `MedicationAdministration`(`partOf` = ハブ、`request` = その `MedicationRequest`)をぶら下げます。
  1 日に複数回の施用(開始時刻が複数)があるので、実施記録はオーダーに複数付き、予定回数に達した
  ときに Task を実施済にします。「実施取消」は記録をすべて消して Task を依頼済に戻します。
  詳細は `docs/injection-order-design.md` §6。
- **注射カレンダー**: カルテ左ペインの「注射カレンダー」タブ(タブ行では「診療情報」の中)。「RP × 日付(2 週間)」の
  表で、各日の注射を予定の開始時刻ごとに進捗の記号(○依頼 ◎受付 ◇払出 ●実施 △途中中止 ×実施せず
  ―中止)で並べ、表の上に凡例を出します。実施した回は実施時刻で出し、予定の回数を超えて実施した回は
  時刻の直後に「+」を付けて足します。行は経過表の注射欄と同じ「薬剤の組・用法種別・経路」で分け、
  実施量が指示と違う日に「量」、同じ束ねの前の日から内容が変わった日に「変」の印を付けます。
  「この日以降すべて」の変更で薬剤の組が変わると行が分かれ、後の行は字下げして前の行の直下に並べます。
  週送りの開始日は URL(`view`)に残ります。
  - 注射のマス: モーダルでその日の注射を開き、予定(指示量)と実施(実施量)を薬剤ごとに並べ、前の日
    からの変更点を出します。「実施」「実施取消」「変更」「複写」「中止」「中止取消」「削除」を置きます
    (化学療法の日オーダーは「実施」「実施取消」だけ)。「変更」「複写」は右ペインのフォームを開きます。
  - 空きのマス: 押すと選択、Shift で同じ行の範囲を選び、ツールバーの「複写」(その行の直前の内容)・
    「新規」が選んだ期間を初期値にした注射登録を開きます。
  - 行のメニュー: 「継続」は束ねの最終日の内容のまま、同じ束ね(requisition・開始日・パターン)で
    終了日まで日を足します(「連日 N日目」が続番になる)。「中止」は表示中で今日以降の最初の未実施日
    から中止を開きます。
  詳細は `docs/injection-order-design.md` §9。
- **注射一覧(部門ワークリスト)と払出**: 部門業務メニューの「注射一覧」(`/injection-worklist`)で
  注射日 1 日ぶんを並べ、「受付」→「払出登録」で進めます。払出は薬剤ごとに `MedicationDispense`
  (`authorizingPrescription` = その `MedicationRequest`、数量の既定は投与量 × その日の施用回数、
  銘柄変更は `substitution.wasSubstituted`)を作り、払出済の Task と同じ transaction で書きます。
  疑義照会は処方と共通(下の「疑義照会」)。詳細は `docs/injection-order-design.md` §5.3。
- **帳票**: 注射一覧の「注射箋発行」(`GET /reports/injections/:order_id/pdf`、A5、注射指示票を兼ねる。
  発行が受付を兼ねる)と「注射ラベル発行」(`GET /reports/injection_labels/:order_id/pdf`、RP ごと 1 枚、
  60×40mm、患者番号バーコード)。処方箋と同じ帳票基盤(同梱 `.tlf`)で、プレースホルダーは
  `docs/report-mappings/injection-01.md`。
- テンプレートへの一括入力(`%prescriptions`)は最新の「処方」を対象とし、注射オーダーは
  対象外です(検索結果から category で除外)。
- **インスリン指示**: 薬効分類 2492 で投与量換算マスタに「単位」の行がある薬剤を選ぶと、量の単位が
  「単位」になり、用法は皮下のワンショットが既定になります。薬剤行の「+ スケール」で**血糖スケール**
  (mg/dL)か**食事量スケール**(主食の摂取量 %)の幅ごとの単位、または**フリースケール**(幅の代わりに
  条件を文で書く。実施入力で当てはまる行を選ぶ)を入れます。マスタメンテ > 医薬品 >
  **スケールセット**(`/insulin-scale-sets`、`/master/insulin_scale_sets`)に施設のスケールを登録して
  おくと、スケールの「セット」で選んで行を写せます。投与量を入れれば
  「基本量 + スケール」、空ならスケールのみです。実施入力では施用時刻の前 2 時間〜後 30 分の
  簡易血糖(看護指示「血糖値」の記録やインスリンの実施入力で入れた値)、食事量は前 3 時間〜後 1 時間の
  主食の摂取量を初期値にして案内量を出し、案内と違う量にしたら変更理由が必須です。その場で入れた
  血糖値は看護観察と同じ形の `Observation`(MEDIS 31000303 + LOINC 41653-7)で同じ transaction に
  書きます。経過表では測定の行に「血糖」、注射の上に「インスリン」の節(施行した単位)が出ます。
  持ち方は `docs/injection-order-design.md` §10。
- **血糖インスリン指示患者一覧**(`/insulin-worklist`、入院患者一覧の「病棟マップ」の右と指示簿の見出しのケバブメニュー「血糖インスリン」から): 病棟の 1 日ぶんの
  インスリンの施用(注射の開始時刻ごと)と血糖測定(看護指示「血糖値」の頻度を展開した時刻ごと)を時刻順に並べます。
  実施日・病棟(上流の ward 検索)・依頼科・勤務帯(日勤 8:30〜/準夜 16:30〜/深夜 0:30〜 の固定)・区分・状態で絞り、
  行の「実施」でインスリン・血糖それぞれの実施入力を開き、患者名でカルテ、「経過表」で経過表タブを開きます。
