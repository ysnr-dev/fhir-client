# 患者プロファイル・病名

## 患者の基本情報（`Patient` の拡張項目）

患者登録・編集画面（`components/PatientForm.tsx`）で、氏名・住所・電話に加えて次を登録できます。
いずれも任意で、新患登録（受付時）の必須は従来どおり氏名・カナ・性別・生年月日だけです。

**入力欄の並びは新患登録モーダルと共通のレイアウト**（CSS の `.patient-fields`）です。窓口が
同じ患者属性を同じ並びで書けるよう、関連する欄を横に並べます。患者登録画面・患者編集画面・
カルテのプロファイルタブの 3 か所すべてで同じ見た目になります。

情報のかたまり（属性 / 住所 / 本人の連絡先 / 緊急連絡先 / かかりつけ医）は
**枠で区切ります**（`.patient-fields__group-box`）。項目が増えるとまとまりの名前だけでは
切れ目が読めなくなるためです。**新患登録モーダルだけは枠を使いません**。受付の最中に書く
画面で項目も少なく、枠を足すと縦に伸びて受付情報まで届かなくなるためです。

| 項目 | 置き場所 | 補足 |
|---|---|---|
| 旧姓 / 通称名 | `name`（`use=maiden` の `family` / `use=nickname` の `text`） | 漢字名・カナ名の後ろに置きます（上流が先頭の `name` を検索用に採るため） |
| 死亡日 | `deceasedDateTime` | `deceasedBoolean` は書きません（併記すると上流が弾きます） |
| 使用言語 / 通訳要否 | `communication.language`（BCP-47） / `preferred` | 言語未指定で通訳だけを立てるときは `language` を `und` にします（1..1 のため） |
| 緊急連絡先・キーパーソン | `contact[]` | 続柄・氏名・電話・住所。何件でも登録できます |
| かかりつけ医・紹介元 | `generalPractitioner` | 連携先医療機関または医師を検索モーダルから選びます |

- **続柄は複数選べます**（v2-0131 の `C` 緊急連絡先 / `N` 近親者 / `BP` 支払・保証人 /
  `E` 勤務先 / `U` 不明）。「キーパーソン」単独のコードが無く、近親者かつ緊急連絡先のように
  重なるためです。「長女」のような補足はコードで表せないので、コードを持たない `text` だけの
  concept として同じ `relationship` に添えます。
- **連絡先の氏名にカナはありません**。`Patient.contact.name` が 0..1 で、本人の氏名のように
  漢字とカナを別の `HumanName` に分けられないためです。
- 死亡した患者は**患者一覧の氏名の後ろと患者帯に赤で出ます**。死亡後のオーダー抑止は
  入れていません（表示のみ）。
- 使用言語と通訳要否は**患者帯にも出ます**（「ポルトガル語 / 通訳必要」）。

## 血液型（`Observation`）

カルテの「プロファイル」タブの **身体** 区画で患者の血液型を登録します。ABO と RhD は
LOINC が別項目（883-9 / 10331-7）なので `Observation` を 1 件ずつ作り、「ABO は分かっているが
RhD はこれから」という状態をそのまま保存できます。保存は片方だけ書かれた状態を作らないよう
transaction でまとめて送ります。コードの値集合は輸血オーダーと共有です。

| 要素 | 内容 |
|---|---|
| `code` | LOINC 883-9（ABO）/ 10331-7（RhD） |
| `valueCodeableConcept` | 輸血オーダーと同じ `transfusion-abo` / `transfusion-rhd` のコード |
| `method` | 情報源。`tested`（検査確定）/ `reported`（本人・家族の申告）/ `referred`（他院からの情報） |
| `effectiveDateTime` | 確認日（検査日または申告を受けた日） |

- **情報源は値と必ず並べて出します**。申告のままの型で製剤は出せないので、検査確定でないときは
  「検査未確定」の印を付けます。
- **患者帯にも出ます**（「血液型 A型 RhD＋」）。輸血・手術で真っ先に確かめるためです。検査で
  確定していない型には「検査未確定」の印を付けます。確認日は帯には出しません（行を増やさない
  ため）。詳細はプロファイルタブで読みます。
- **輸血オーダーの血液型の初期値に入るのは検査確定の型だけです**（新規登録のときのみ。編集や
  DO で写った型は上書きしません）。申告値はオーダー画面に参照として並べるに留めます。
- 患者の型とオーダーで選んだ型が**食い違うときは赤字で知らせます**。選択自体は妨げません。
  意図して別の型を出すことがあるためです。
- 輸血オーダー側の血液型の項目は残してあります。オーダーの型は「何型を出すか」という依頼の
  中身で、患者の血液型と食い違いうるためです。

## 身長・体重と腎機能（読み取り専用）

プロファイルタブの **身体** 区画に、バイタルと検体検査の結果から**最新値を引いて**出します。
本体はそれぞれの画面にあるので、ここでは編集できません（同じ情報を 2 経路に持たないためです）。

| 項目 | 引き当て | 補足 |
|---|---|---|
| 身長 / 体重 / BMI | LOINC 8302-2 / 29463-7 | 測定日を併記します。BMI は両方あるときだけ出します |
| 血清クレアチニン | JLAC11 分析物 `C3002` | 材料・測定法の違いは分析物コードで吸収します |
| シスタチンC | JLAC11 分析物 `C3003` | あれば出します。eGFR の算出には使いません |
| eGFR | 血清クレアチニンから算出 | 日本腎臓学会の推算式 |

- **測定日を必ず併記します**。小児のように値が変わる患者で、いつの測定かで読み方が変わる
  ためです。身長と体重の測定日が離れていても BMI は出します（体重だけ測り直すのが普通です）。
- **eGFR は算出値です**（男性 194 × Cr^-1.094 × 年齢^-0.287、女性はその 0.739 倍）。配布マスタに
  eGFR の項目が無いためです。**性別か生年月日が未登録のときは算出せず、その理由を出します**。
  薬用量の判断に使う値なので、当てずっぽうを出しません。
- 身長・体重は**患者帯には出しません**（プロファイルタブで読みます）。帯の枠は限られており、
  輸血・手術で真っ先に確かめる血液型を優先しています。

## 妊娠・授乳（`Observation`）

血液型と同じ **身体** 区画で登録します。妊娠状態（LOINC 82810-3）と授乳状態（63895-7）は
別項目なので `Observation` を 1 件ずつ作り、「妊娠していないが授乳中」もそのまま保存できます。

| 要素 | 内容 |
|---|---|
| `code` | LOINC 82810-3（妊娠状態）/ 63895-7（授乳状態） |
| `valueCodeableConcept` | SNOMED CT（妊娠中 77386006 / 妊娠していない 60001007 / 不明 261665006、授乳中 413712001 / 授乳していない 169750002） |
| `component` | 分娩予定日（LOINC 11778-8）。妊娠中のときだけ入れます |
| `effectiveDateTime` | 確認日（必須） |
| `category` | `survey`。問診・観察で得る情報なので、検体検査の結果一覧に混ざりません |

- **確認日は必須です**。いつ時点の状態かが分からないと使えないためで、画面は常に確認日の
  新しいものを出します。「不明」を選択肢に残すのは、確認したが分からなかったことと、
  まだ聞いていないこと（登録が無い状態）を区別するためです。
- **処方と放射線検査のオーダー画面の先頭に注意が出ます**（`components/PregnancyNotice.tsx`）。
  催奇形性・乳汁移行と被曝の判断に要るためです。妊娠中・授乳中のときだけ出し、そうでなければ
  何も出しません。常に出すと読み飛ばされ、本当に注意が要るときに目に入らなくなるためです。
- **オーダーは妨げません**。妊婦にも必要な検査・薬はあり、判断は医師のものだからです。

放射線検査のオーダー画面は、選んだ撮影項目に造影・MRI が含まれるときにも注意を出します
(`components/RadSafetyNotice.tsx`、`fhir/radSafetyHelpers.ts`、`docs/rad-backlog.md` B-1 / B-2)。
妊娠と同じく該当が無ければ何も出さず、登録も止めません。

- **造影**(JJ1017 の手技小分類が `01`、または種別が血管撮影): 注意区分「造影剤注意」、造影剤アレルギー
  (JFAGY コードが造影剤区分 1 の医薬品に当たるもの、コードが無く名前に「造影」を含むもの)、eGFR
  (45 未満、30 未満は強く。クレアチニンが無いなど算出できないときはその旨)、ビグアナイド系(YJ 上 4 桁 3962)の内服。
- **MRI**(種別 `7`): 注意区分「体内金属・ペースメーカー」。機種と MRI 対応の可否などは特別指示の
  テンプレート `RAD_MRI_01`(`docs/report-mappings/rad-mri-01.md`)で依頼医が書きます。

## 感染症（`Observation`）

カルテの「プロファイル」タブの **感染症** 区画で、種類ごとに 1 行で読みます。情報は 2 経路から
集まります。

- **検体検査の結果**（`category=laboratory`）。JLAC11 の**分析物コード（先頭 5 桁）**で
  「この結果は HBs 抗原」と判定し、自動で拾います。陽性・陰性は**値の文字列を先に読みます**
  （「陽性」「(+)」「reactive」など）。検査結果の登録画面は異常フラグ（`interpretation`）を
  選ばなければ `N`（正常）で保存するので、判定を先に見ると「陽性」と入れた結果まで陰性に
  なってしまうためです。異常フラグは値から読めないときの補助に留めます。
  値から読み取れない結果（抗体価などの数値）は「**判定不明**」にします。基準値の持ち方が項目
  ごとに違い、ここでは決められないためで、陰性と決めつけません（橙色で出します）。
- **手入力**（`category=exam`）。検査していないが他院情報・本人申告で分かっている分です。
  `code` はローカルコード（`infection-type`）を先に置き、LOINC を添えます。LOINC だけでは
  種類を引き直せず、ローカルコードだけでは標準の相手に読ませられないためです。

同じ種類が両方にあるときは**検査結果を優先**します。検査で出た値が正だからです。そのため
**検査結果由来の行は画面から編集できません**。手入力分だけ編集・削除できます。「未検」は
`Observation` を作らないことで表すので、結果の選択肢は陽性・陰性だけです。

**陽性があると、放射線・生理・内視鏡のオーダー画面の先頭にも出します**（`components/InfectionNotice.tsx`）。
検査室の清掃順・感染対策の判断に要るためです。

部門業務の各一覧(検体検査・病理・放射線・生理・内視鏡・手術・輸血・リハビリ・栄養指導・食事・処方・持参薬鑑別・
服薬指導・注射・処置・外来化学療法室)の患者氏名の後ろにも、外来患者一覧と同じ注意のピクトグラム
(注意区分・アレルギー・感染症)を並べます。一覧に並ぶ患者ぶんをまとめて引きます。

**陽性が 1 つでもあると患者帯にバイオハザードのピクトグラムが出ます**（赤）。標準予防策に
加えるかの判断に直結するためです。種類が複数あってもアイコンは 1 つで、件数を右肩に添え、
種類・情報源・確認日は押して開く吹き出しに出します（帯にバイオハザードが並ぶと、どれが何か
読めないまま場所だけ取るためです）。この図柄は**注意区分マスタの選択肢には出しません**。
感染症は注意として登録するものではなく、二重管理になるためです。

### 分析物コードの粗さ

対応づけは `fhir/infectionHelpers.ts` の定数（`INFECTION_TYPES.analytes`）に持ちます。分析物
コードは配布マスタが決める全国共通のコードで施設ごとに変わらず、種類の一覧自体も定数なので、
施設マスタにはしていません。

- **材料（血清 / 血漿）と測定法は分析物コードでは分かれません**。1 コードでその種類の検査を
  全部拾えます（HBs 抗原は 229 行が 1 件で済みます）。
- **大項目まで粗くすると誤ります**。大項目「HBs」は HBs 抗原と HBs 抗体の両方を含みますが、
  抗原陽性は感染、抗体陽性はワクチンか既感染で意味が逆です。
- **HTLV-1・MRSA・結核は検査結果から拾いません**（手入力のみ）。配布マスタの項目名から分析物を
  特定できなかったためで、分かった時点で定数に足します。
- 上流のコード検索は完全一致で前方一致が使えないため、患者の検体検査の結果を新しい順に 500 件
  引き、突き合わせは画面側で行います。

## 診療上の注意（`Flag`）と注意区分マスタ

カルテの **「プロファイル」タブ** に、患者の「現在の状態」を区画ごとに読むタブがあります
（[`docs/patient-profile-design.md`](../patient-profile-design.md)）。時系列ではないので
タイムラインには出ません。現在の区画は **診療上の注意** と **基本情報** で、身体（血液型・妊娠）・
感染症・生活などの区画を後から足す前提の構造になっています。

基本情報の「患者情報編集」は、**患者編集画面へ遷移せずタブの中で開きます**（注意の登録・編集と
同じ挙動）。カルテを見ているところから離れず、戻り先を見失わないためです。楽観ロックと競合時の
扱いは患者編集画面と同じです。

注意は 1 件が 1 つの `Flag` です。

| 要素 | 内容 |
|---|---|
| `status` | `active`（有効）/ `inactive`（終了）。画面から `entered-in-error` は書きません |
| `category` | `http://fhir-client.local/CodeSystem/flag-category`。`safety`（安全）/ `clinical`（臨床）/ `advance-directive`（意思）/ `administrative`（事務） |
| `code` | `http://fhir-client.local/CodeSystem/patient-caution`。コードは注意区分マスタの `code`、`display` は登録時点の表示名。`text` に内容の自由記載 |
| `subject` | `Patient/{id}` |
| `period` | 開始日・終了日（どちらも任意）。終了日が無ければ継続中 |
| `author` | ログイン中の医療従事者（無ければ省略） |

- **削除は用意していません**。誤登録も「終了」（`inactive` ＋ 終了日）で残します。一覧の既定は
  有効なものだけで、「終了したものも表示」で全件になります。
- 上流は JP Core が Flag をプロファイルしていないため、HL7 の基本定義で登録されます
  （`docs/server-improvement-backlog.md` の 2026-09-05 の項）。

### 注意区分マスタ（`/patient-cautions`）

「何を注意として選べるか」と「患者帯にどう出すか」を決める施設マスタです（マスタメンテ > 共通 >
注意区分）。列は コード / 表示名 / 区分 / **ピクトグラム** / 表示順で、seed に初期値 15 件が入って
います（転倒リスク・暴力/粗暴歴・離院リスク・体内金属・造影剤注意・抗凝固薬内服・認知症/せん妄・
車椅子・聴覚障害・視覚障害・DNAR・輸血拒否・未収金・要配慮・その他）と、ピクトグラムを持たない
「SpO2 スケール2(高CO2血症リスク)」(`spo2-scale2`。付けた患者は NEWS2 の SpO2 をスケール 2 で点数にする)。

- ピクトグラムの図柄は `frontend/src/components/icons/cautionPictograms.tsx` の 1 モジュールに
  まとまっており、**選択肢もそのキー一覧から作ります**（定義を 2 か所に持たないため）。backend
  にも同じ一覧を検証用に持っていますが、正は TS 側です。
- **ピクトグラムが空の区分は患者帯に出ません**（「帯に出すか」の真偽値は別に持ちません）。

### 患者帯のピクトグラム

患者帯（`PatientHeader`）は行を増やさないルールなので、注意は **文字ではなくピクトグラム**で
出します。有効な注意のうち、マスタにピクトグラムがあるものだけを並べます。

- 図柄は区分ごとに色分けします（安全=赤 / 臨床=橙 / 意思=紫 / 事務=灰）。大きさは 20px で、
  帯の文字（14px）より少し大きくしてあります。離れた席からでも図柄を読めるようにするためです。
  帯全体は baseline 揃えですが、アイコンには基準線が無く下寄りに見えるので、行の中央に
  合わせています。
- 同じ図柄が複数あれば 1 つにまとめ、右肩に件数を添えます。並びはマスタの表示順です。
- **押すと吹き出しが開き**、名称と内容が読めます。もう一度押す・外側を押す・Escape で閉じます。
  吹き出しの中のリンクから、対応する画面（プロファイルタブ・アレルギータブ）へ移動します。
  ホバーの `title` ではなくクリックにしているのは、帯のアイコンは離れた席からも見るもので、
  内容を読むのに正確なホバーを要求したくないためです。読み上げには同じ文言を `aria-label` で
  持たせています。
- マスタに無いコードの注意は帯に出ません（タブには出ます）。マスタのピクトグラムが未知のキーの
  場合は汎用の三角（`alert`）で描き、黙って消しません。

**注意以外もここに並びます**（いずれも赤で、注意区分マスタの選択肢には出しません）。

- **アレルギー**。薬剤（カプセルに禁止記号）とそれ以外（皿に禁止記号）で図柄を分けます。
  薬剤禁忌は処方・注射で真っ先に確かめるもので、食物・環境のアレルギーとは見るべき場面が
  違うためです。活動性のものだけを出し、解消済み・非活動は出しません。吹き出しの
  「アレルギーを開く」でアレルギータブへ移動します。
- **感染症**（バイオハザード）。陽性が 1 つでもあれば出ます。
- **早期警告**（心拍の波形）。直近 3 日の最新の NEWS2 が中以上なら出し、中は注意色・高は危険色にします。
  吹き出しに点数・測定日時・点数のある項目、「経過表タブを開く」を出します。
- **Web 問診**（用紙にチェック。アクセント色）。取込待ちの回答があれば件数付きで出ます。吹き出しの
  「問診を取り込む」で、カルテの右ペインをその回答の取込で開きます（`docs/features/karte.md`「Web 問診の取込」）。

各種一覧の行を押して開く患者ドロワーにも、氏名の横に患者帯と同じピクトグラム（化学療法を含む）を
並べます。ドロワーは中身ごとスクロールするので、吹き出しは一覧の行と同じく body 直下に出します。

## 病名の区分（プロブレム / 既往歴 / 保険病名）

「病名」タブの区分ラジオで 3 つを選び分けます。いずれも同じ `Condition` で、`category` で区別します。

| 区分 | 用途 | `Condition.category` |
|---|---|---|
| プロブレム | POMR のプロブレムリストに載る現在の問題 | `problem-list-item` |
| 既往歴 | 基礎データとしての過去の病歴。プロブレムリストには載せない | `problem-list-item` ＋ ローカルの `past-history` |
| 保険病名 | レセプト用 | `encounter-diagnosis` |

- **既往歴が 2 つの分類を持つ理由**: FHIR 標準の `condition-category` には `problem-list-item` と
  `encounter-diagnosis` の 2 コードしか無く、既往歴に当たるコードがありません。JP Core も既往歴を
  `Condition` で表す方針なので、標準の `problem-list-item` を併記したうえで、ローカルの
  `http://fhir-client.local/CodeSystem/condition-category` の `past-history` で印を付けています。
  標準しか見ない相手にはプロブレムリスト項目として読め、アプリ内では区別できます。判定
  （`conditionCategoryOf`）はローカルコードを先に見ます。
- 既往歴には**プロブレム番号を振りません**。プロブレム帯・プロブレム選択の候補・診療記録やオーダーの
  対象プロブレムにも出しません（`splitConditions` がプロブレムと別に返します）。
- MEDIS 病名検索・接頭/接尾修飾語・転帰は 3 区分とも共通です。既往歴は転帰「治癒」＋終了日を
  入れる使い方を想定しています。

看護問題(看護計画の対象。`condition-category|nursing-problem`)は病名ではないので、病名タブ・プロブレムリストには
出しません(「看護計画」節)。

### 病名の入力方法（マスタ / フリー入力）

区分とは別に「入力方法」を選べます。**フリー入力**は、既往歴のように具体的な傷病名が判別できない
場合に使います（区分は問わず、保険病名でも選べます）。

- フリー入力の病名は `Condition.code` に **`text` だけ**を入れ、`coding` は付けません
  （レセプトに使えるコードが無いことを表します）。フォームのプレビューにも「(コードなし)」と出ます。
- **修飾語（接頭語・接尾語）と疑い病名はフリー入力では出しません**。修飾語はマスタの病名に
  付けるものだからです。マスタ→フリーに切り替えた時点で設定済みの修飾語も落とします
  （画面に出ていない語が付いたまま保存されるのを防ぐため）。
- 編集時の入力方法は保存内容から判定します（病名コードがあればマスタ、無ければフリー入力）。
  `code.text` は「接頭語＋病名＋接尾語」を連結したものなので、フリー入力として開き直すときは
  両端から修飾語の名称を剥がして病名本体を復元します（前後一致を確かめてから外すので、
  想定外の text を壊しません）。

### 疑い病名

「疑い病名(接尾語に「の疑い」を付ける)」のチェックボックスで、MEDIS 修飾語の **「の疑い」**
（管理番号 27000001）を付け外しできます。毎回修飾語のモーダルから探す手間を省くためのものです。

- チェックは**接尾語リストの表示そのもの**です。モーダルから「の疑い」を追加してもチェックが入り、
  接尾語のチップを × で消せばチェックも外れます（状態を二重に持ちません）。読みが「〇〇の疑い」に
  なるよう、常に接尾語の末尾に置きます。
- 疑い病名は確定診断ではないので、`Condition.verificationStatus` を `provisional` にします
  （付いていなければ従来どおり `confirmed`）。レセプト表記は修飾語、FHIR としての確からしさは
  `verificationStatus` と、二本立てで表しています。

### 病名の一括転帰

「病名」タブの「一括転帰」でモーダルを開き、選んだ病名をまとめて書き換えます
(`components/ConditionBulkModal.tsx`)。退院時・終診時に複数の病名を同じ日付で閉じるためのものです。

- 操作は 2 つです。**転帰**は転帰区分(軽快・治癒・中止)と終了日(既定は今日)を付けます。
  **開始日変更**は開始日をそろえます。「継続」は選べません(終了日を持つ病名は active 以外、FHIR con-4)。
- 候補は患者の病名全件です(タブの一覧は 20 件ずつのページングなので、ページをまたいで選べません)。
  既定では転帰が「継続」の病名だけを並べ、「転帰済みも表示」で全部を出します。
- 病名フォームと同じ規則を病名ごとに確かめます。終了日は各病名の開始日以降、開始日は既存の終了日
  以前です。外れた行には理由を出し、1 件でもあれば登録できません。
- 保存は書き換えた Condition を**1 つの transaction で PUT** します(`useBulkUpdateConditions`)。
  フォーム値から組み直す `buildCondition` は使わず、読んだリソースの `clinicalStatus`・`abatementDateTime`
  (または `onsetDateTime`)だけを差し替えます(`applyBulkConditionChange`)。フォームに無い項目
  (`note` など)を落とさないためです。
- 楽観ロックは読んだ版(`meta.versionId`)を `postBundle` が `ifMatch` に添えます。1 件でも版が違えば
  全体が 412 で失敗し、モーダルは最新を読み直します(選択は残るので、確かめて登録し直せます)。
