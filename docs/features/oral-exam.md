# 口腔診査情報

日本歯科医師会「口腔診査情報標準コード仕様」(JDAOES Ver.1.02、厚生労働省標準規格 HS034。
配布元 https://www.jda.or.jp/dentist/program/business-latest.html)の **口腔状態スナップショット** を、
歯式図の画面から登録・閲覧します。

## 置き場所と画面

カルテ左ペインの「患者情報」ドロップダウンの **口腔診査情報** タブです(`components/KarteOralExamTab.tsx`)。
登録・編集はタブの中で行い、右ペインは使いません。

- **診査ごとに残します**(1 回の診査 = 1 スナップショット)。見出しのセレクトで回を選び、既定は最新です。
  選んだ回は URL の `view`(見出しの Observation の id)に載り、リロード・戻るで復元されます。
- **新規登録は表示中の回を複写して開きます**。入力種別は「治療による更新(処置履歴)」、診査日・最終診療日は今日に
  なります。記録が無い患者は空の歯式(入力種別「初診時口腔診査」)から始めます。同じ日の 2 件目も登録できます。
- 見出しの下に診査者と、現在歯・未処置歯・処置歯・喪失歯の本数を出します(歯ごとに最初の併存グループで数え、
  過剰歯は数えません)。
- 削除はその回の Observation をまとめて消します。

### 歯式図(`components/OralExamChart.tsx`)

上から上顎永久歯・上顎乳歯・下顎乳歯・下顎永久歯の 4 行で、**患者の右が画面の左**です。乳歯の行は
15 歳未満の患者か、乳歯に記録がある回だけ出します(登録画面ではチェックで切り替え)。

| 表示 | 意味 |
|---|---|
| 歯の色 | 基本状態(TD-2)。健全・現在歯=通常、要観察・要注意乳歯=注意色、未処置歯=危険色、処置歯=アクセント、欠損補綴・インプラント=青、喪失=淡色に斜線、埋伏・未萌出=点線、未検査・情報なし=縞、記録なし=点線の枠 |
| 5 面図 | 中央が切端・咬合面、周囲が頬側(唇側)・口蓋側(舌側)・近心・遠心。現在歯の内容で歯面(TP-13〜17)を付けた面を塗る。頬側は口腔の外側、近心は正中の側 |
| 歯の下(上)の字 | 歯科健診記号(TD-3。／ C ○ △ (△) シ サ CO ×) |
| その下の略号 | 内容の略号(優先順に 2 つまで。全部はツールチップ)。う蝕 C1〜C4・Att・WSD、冠 FMC・JC・前装・MB・帯環・PC、根面板・Abu・At、部分修復 CR・AF・In・On・3/4・4/5・LV、TeC、Br・連結、欠損補綴 Pon・隙・FD・PD・Den・Im、Cl、埋伏 HRT・RT・HIT・未萌出 |
| 右肩の数字 | 併存グループが複数ならその数、無ければ現在歯の内容(併存レコード)の数(2 以上のとき) |
| 歯の下の小さな「+」 | 近傍過剰歯 |

歯を押すと、表示画面ではその歯の記録、登録画面では編集パネルが下に開きます。

### 登録・編集(`components/OralExamForm.tsx`)

- 診査日・入力種別(NS-2)・最新初診日(NS-3)・最終診療日(NS-4)・メモ。診査者はログイン中の医療従事者です
  (編集では最初の診査者を残します)。
- 「記録の無い歯」+「一括設定」で、表示中の行の未記録の歯をまとめて同じ基本状態にします(初診時に全歯を書くため)。
- **スタンプ**(`components/OralExamStampPalette.tsx`、定義は `fhir/oralExamHelpers.ts` の `ORAL_EXAM_STAMPS`)。
  歯式図の上のパレットからよく使う状態を選び、歯を押して入れます。続けて何本でも押せます。
  - 状態(健全・CO・シーラント・未萌出・埋伏・未検査)、欠損・補綴(ポンティック・部分床義歯・総義歯・インプラント・
    喪失・消す)は歯を押すとその状態に置き換わります。
  - う蝕(C1〜C3)と充填(CR・インレー)は **歯の 5 面図の面を押すとその面に付きます**(もう一度押すと外れます)。
    歯の番号を押せば面を指定せずに付きます。C4・残根は歯を押します。
  - 冠(FMC・前装冠・白い冠・Br 支台)は歯を押すと、その歯のう蝕・部分修復・ほかの冠を置き換えます。
    充填を押した面のう蝕は消えます(治療済みになるため)。
  - 基本状態(未処置歯・処置歯)・状態コード・健診記号・標準プロファイルは、押した内容から決まります。
  - コード表にある細かい種類(材質・色・窩洞など)は「選択」に戻して歯を押し、編集パネルで直します。
    スタンプは「銀色・内容不明」など代表的なコードを入れるので、必要なら編集パネルで置き換えます。
- **歯の編集パネル**(`components/OralExamToothEditor.tsx`)
  - 基本状態(TD-2)を選ぶと、状態コード(TB-3)と健診記号(TD-3)を既定値で埋めます(現在歯 0 / 欠損歯 2 /
    残根上義歯 6 / インプラント 7)。「(記録なし)」に戻すとその歯(グループ)の記録を消します。
  - 基本状態が欠損歯(インプラントを除く 50〜69)なら **欠損歯の内容**(TM)、それ以外は **現在歯の内容**(TP)を
    書きます(仕様上 TP と TM は排他。インプラントの上部構造・アバットメントは TP に書く)。
  - 現在歯の内容は「追加」で行を増やせます(1 歯 2 窩洞などの併存レコード)。歯面は IO / B / PL / M / D の
    チェック、萌出異常・クラスプ・歯肉などは「その他」に畳んであります。
  - 「併存グループを追加」は残根上義歯のように同じ歯に別のグループが要るときに使います。
  - 「過剰歯を追加」でその歯の近傍過剰歯(101A など)を足します。
  - 製品識別情報(TE-2〜4)と特記事項(TE-6)。
  - **標準プロファイル 26 項目**(TF)は入力させず、選んだコードから導いて表示します(下記)。
- **口腔全体**(`components/OralExamMouthForm.tsx`): 口腔内装置等(KS)・矯正関係(KK)・その他の疾病及び異常(SI)・
  所見・特記事項(SK)。歯式の欄は「歯式を選ぶ」で歯式図を選択モードにし、歯を押して足し外しします(「完了」で戻る)。
- 選択肢は「該当なし」(00)を空欄で表し、有効期限の切れたコード(診療報酬改定で廃止)は出しません。
- 保存は 1 回の transaction です。版が変わっていた(412)・先に削除されていた(404)ときは
  「他の操作によって更新されています」を出します。

### 標準プロファイル 26 項目の導出

コード表の各コードに付いた対応 TF(備考の〔TF-n〕)を集めます。乳歯は TF-3 を足します。仕様の排他関係表に従い、
TF-3〜TF-26 のどれかがあれば TF-27(歯あり・状態不明)を落とし、TF-3〜TF-27 のどれかがあれば TF-28(情報なし)を
落とします。1 つでもあれば TF-2(情報の有無)を 01 にします。

## FHIR の表現(`fhir/oralExamHelpers.ts`)

1 回の診査は、`identifier`(`http://fhir-client.local/oral-exam-snapshot` の uuid)で束ねた Observation の組です。
共通: `status=final`、`category=exam`、`subject`、`effectiveDateTime`=診査日、`performer`。

| 種類 | `code`(`http://fhir-client.local/CodeSystem/oral-exam`) | 件数 | 中身 |
|---|---|---|---|
| 見出し | `snapshot` | 1 | component に NS-2・NS-3・NS-4、`note` にメモ。一覧はこの code で引く |
| 歯 | `tooth` | 歯 × 併存グループ | `bodySite` = 歯種コード(MEDIS 標準歯式 `urn:oid:1.2.392.200119.4.1401`、4 桁)。component に TB-3・TB-4・TB-5・TD-2・TD-3・TM・TE・TF |
| 現在歯の内容 | `tooth-content` | 併存レコードごと | 同じ `bodySite`。component に親の鍵(TB-3・TB-4・TB-5)と TP-2・TP-3〜34 |
| 口腔全体 | `mouth` | 0〜1 | component に KS・KK・SI・SK。歯式の項目は歯の数だけ繰り返す(値は 6 桁の歯式コード) |

- component の `code` は HL7 変換仕様の項目コード(JDAS 表 0003、OBX-3 の `TP11` など)を
  `http://fhir-client.local/CodeSystem/jdaoes-item` で持ちます(JDAS 表 0003 の OID が公開されていないため)。
- 値は `valueCodeableConcept` で、system は OID 表のコーディングシステム名の OID(`urn:oid:1.2.392.200354.1.2.1.5.3.11` など)。
  製品名・特記事項などの自由記載は `valueString`、日付は `valueDateTime`。
- HL7 の OBX-4(歯 T / 併存グループ U / 併存レコード R)にあたる束ねは Observation の単位で表します。
  現在歯の内容と親の歯は **歯種 + TB-3 + TB-4 + TB-5 の一致** で結びつけます(参照は使いません)。
  併存グループ連番(TB-5)・併存レコード連番(TP-2)は 2 つ以上あるときだけ付けます。「該当なし」は書きません。
- 保存は見出しを PUT(読んだ版を `If-Match` に添えて、見出しの版でスナップショット全体の競合を見る)、
  子は前回のものを DELETE して POST で作り直します。読み出しは `identifier` 1 回の検索です(上限 500 件)。
- `category=exam` なので、データ抽出で区分「診察」を選ぶと口腔診査の Observation も件数に入ります。
  感染症の手入力(`category=exam` + 種類コードで絞る)とは混ざりません。

## コード表(`/master/oral_exam_codes`)

配布の「マスター形式データ」と「OID 表」(xlsx)から、TB/TD/TP/TM/TE/TF/NS/KS/KK/SI/SK のコード値を持つ行
(827 行)を `backend/db/seed_data/oral_exam_codes.csv` にしてあります。列は record / item / item_name / code / display /
tf_ref(対応 TF)/ cs_name / cs_oid / note / display_order。

- 投入は `OralExamCodeSeed.load!` で、`db:seed` と migration(本番は起動時に seed が走らないため)の両方から呼びます。
  同じ (item, code) の行は触りません。
- 固定の標準コード表なので API は一覧だけで、マスタメンテ画面はありません。
- 版が上がったら配布 xlsx を `backend/tmp/master-data/oral-exam/` に置いて CSV を作り直します。

```bash
docker compose exec backend bin/rails "master_oral_exam_codes:csv[tmp/master-data/oral-exam/<マスター形式データ>.xlsx,tmp/master-data/oral-exam/<OID表>.xlsx]"
```
