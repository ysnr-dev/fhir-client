# 口腔診査情報

日本歯科医師会「口腔診査情報標準コード仕様」(JDAOES Ver.1.02、厚生労働省標準規格 HS034。
配布元 https://www.jda.or.jp/dentist/program/business-latest.html)の **口腔状態スナップショット** を、
歯式図の画面から登録・閲覧します。

## 置き場所と画面

カルテ左ペインの「患者情報」ドロップダウンの **口腔診査情報** タブです(`components/KarteOralExamTab.tsx`)。
登録・編集はタブの中で行い、右ペインは使いません。

- **診査ごとに残します**(1 回の診査 = 1 スナップショット)。見出しのセレクトで回を選び、既定は最新です。
  選んだ回は URL の `view`(見出しの Observation の id)に載り、リロード・戻るで復元されます。
- **新規登録は表示中の回を複写して開きます**。入力種別は「治療による更新(処置履歴)」、診査日・最終診療日は今日に
  なります。記録が無い患者は空の歯式(入力種別「初診時口腔診査」)から始めます。同じ日の 2 件目も登録できます。
- 見出しの下に診査者と、現在歯・未処置歯・処置歯・喪失歯の本数を出します(歯ごとに最初の併存グループで数え、
  過剰歯は数えません)。1 つ前の診査があれば「前回との違い」で、記録が変わった歯に印(橙の枠)を付け、本数を出します。
- 登録・編集の画面でも、比べる元(新規は前回の診査、編集は開いたときの記録)から変えた歯に同じ印が付きます。
  変えた歯には歯ごとの更新日(TE-8、当該歯情報入力・更新年月日)として診査日が入り、変えていない歯は前回の更新日を
  引き継ぎます。最初の診査では全部の歯に診査日が入ります。
- 削除はその回の Observation をまとめて消します。

### 歯式図(`components/OralExamChart.tsx`)

上から上顎永久歯・上顎乳歯・下顎乳歯・下顎永久歯の 4 行で、**患者の右が画面の左**です。乳歯の行は
15 歳未満の患者か、乳歯に記録がある回だけ出します(登録画面ではチェックで切り替え)。

| 表示 | 意味 |
|---|---|
| 歯の色 | 基本状態(TD-2)。健全・現在歯=通常、要観察・要注意乳歯=注意色、未処置歯=危険色、処置歯=アクセント、欠損補綴・インプラント=青、喪失=淡色に斜線、埋伏・未萌出=点線、未検査・情報なし=縞、記録なし=点線の枠 |
| 5 面図 | 中央が切端・咬合面、周囲が頬側(唇側)・口蓋側(舌側)・近心・遠心。現在歯の内容で歯面(TP-13〜17)を付けた面を塗る。頬側は口腔の外側、近心は正中の側 |
| 歯の下(上)の字 | 歯科健診記号(TD-3。／ C ○ △ (△) シ サ CO ×) |
| その下の略号 | 内容の略号(優先順に 2 つまで。全部はツールチップ)。う蝕 C1〜C4・Att・WSD、冠 FMC・HJC(レジン系)・セラ(セラミック系)・JC(材質不明)・前装・MB・帯環・PC、CAD/CAM 冠用材料の非金属冠・インレーは CAD・CAD-In、根面板・Abu・At、部分修復 CR・AF・In・On・3/4・4/5・LV、TeC、Br・連結、欠損補綴 Pon・隙・FD・PD・Den・Im(2 床目・3 床目は PD2 など)、大連結子 Bar・Pl・LA、補強線 補強、埋伏 HRT・RT・HIT・未萌出 |
| 歯の間の線 | 同じブリッジ・連結冠の歯は実線、同じ有床義歯の人工歯・鉤歯は破線(咬合平面の側に引く) |
| 橙の枠 | 「前回との違い」で、前回の診査から記録が変わった歯 |
| 橙の Cl・R | 鉤歯(クラスプ TP-26・レストシート TP-25)。略号の数の制限で隠れないよう別の行に出す。2 床目・3 床目の義歯の鉤は Cl2 など |
| 右肩の数字 | 併存グループが複数ならその数、無ければ現在歯の内容(併存レコード)の数(2 以上のとき) |
| 歯の下の小さな「+」 | 近傍過剰歯 |

歯を押すと、表示画面ではその歯の記録、登録画面では編集パネルが下に開きます。

「?」の隣のアイコンで、歯式図をペインの幅いっぱいに広げる(最大化)/ 元の大きさに戻すを切り替えます。最大化すると
歯の図・記号・略号が比例して大きくなり、歯面も押しやすくなります。設定は端末ごとにブラウザに覚え、表示画面と
登録画面で共通です(ブリッジ・有床義歯のモーダルの歯式図は切り替えに従いません)。

歯式図の横の「?」(表示画面は本数の行の先頭、登録画面は乳歯の切り替えの行の先頭)で、この表と略号の一覧を
「歯式図の見方」のモーダルで開けます(`components/OralExamLegend.tsx`)。色の見本は実際の歯の図で描きます。

### 登録・編集(`components/OralExamForm.tsx`)

- 診査日・入力種別(NS-2)・最新初診日(NS-3)・最終診療日(NS-4)・メモ。診査者はログイン中の医療従事者です
  (編集では最初の診査者を残します)。
- 「記録の無い歯」+「一括設定」で、表示中の行の未記録の歯をまとめて同じ基本状態にします(初診時に全歯を書くため)。
  健全歯など現在歯の状態を入れるときは、永久歯の 8 番(第 3 大臼歯)だけを未萌出歯にします(萌出していないことが多いため)。
  未検査・欠損などを入れるときは 8 番も同じ状態にします。既に記録のある歯は変えません。
- **スタンプ**(`components/OralExamStampPalette.tsx`、定義は `fhir/oralExamHelpers.ts` の `ORAL_EXAM_STAMPS`)。
  歯式図の上のパレットからよく使う状態を選び、歯を押して入れます。続けて何本でも押せます。
  - 状態(健全・CO・シーラント・未萌出・埋伏・未検査)、欠損・補綴(インプラント・喪失・消す)は歯を押すとその状態に
    置き換わります。
  - う蝕(C1〜C3)と充填(CR・インレー・CAD/CAM インレー)は **歯の 5 面図の面を押すとその面に付きます**
    (もう一度押すと外れます)。歯の番号を押せば面を指定せずに付きます。C4・残根は歯を押します。
  - 冠(FMC・前装冠・CAD/CAM 冠・セラミック冠)は歯を押すと、その歯のう蝕・部分修復・窩洞・仮歯・ほかの冠と
    それらの歯面を置き換えます。同じ内容の行にあるクラスプ・レスト・失活歯などは残します。
    充填を押した面のう蝕は消えます(治療済みになるため)。
  - 失活歯・仮歯(TeC)・暫間固定・歯石は現在歯の内容の 1 行目に書き足します(併存レコードを増やさない)。
  - 根面板は残根(状態コード 6・基本状態 09 処置歯)として、失活歯・歯根部・根面板(金属・銀色)を入れます。
    コアは支台築造(メタルコア・銀色)で、仕様どおり未処置歯(治療中)になります。
  - インプラント(基本状態 62〜66)の歯に冠を押しても基本状態と状態コード「部インプラント」(7)は変わらず、
    アバットメントと上部構造が現在歯の内容に並びます(仕様のモデルケースと同じ形)。
  - ブリッジ・連結冠・有床義歯は複数の歯で 1 つの装置なので、スタンプではなく「ブリッジ・連結冠」「有床義歯」の
    ボタンから専用のモーダルで入れます(下記)。
  - CAD/CAM 冠は全部非金属冠のレジン系、CAD/CAM インレーは非金属インレーのレジン系(単純・複雑の情報なし)で、
    どちらも材料に「CAD/CAM冠用材料」を入れます(仕様に CAD/CAM 専用のコードは無いため)。
  - 修復のスタンプは材料も入れます(FMC・インレー・前装冠は金銀パラジウム、CR はコンポジットレジン、
    セラミック冠はセラミック)。
- **ブリッジ・連結冠**(`components/OralExamBridgeModal.tsx`)。種類(ブリッジ / 連結冠)・顎・固定性 / 半固定性・番号
  (同じ顎で何装置目か。既定は使っていない最小)を選び、顎の歯式図で「支台」「ポンティック」の役割を付けて、
  支台の冠(TP-21)・ポンティックの種類(TM-2)・材料をまとめて決めます。
  - 支台歯は状態コード「支台歯」(3)・処置歯、現在歯の内容の 1 行目に TP-21・TP-23(連結冠 01 / ブリッジ支台 02)・
    TP-24(番号)。冠と同じくう蝕・部分修復・ほかの冠を置き換えます。ポンティックは基本状態 60・TM-2・TM-3(番号)。
  - 支台を 2 本以上選ぶと、その間の喪失歯(補綴されていない欠損歯)を自動でポンティックにします。喪失歯を選んで
    開くとその歯がポンティック、現在歯を選んで開くとその歯が支台になった状態で開きます。
  - インプラントを支台に選ぶと、基本状態と状態コード「部インプラント」(7)を保ったまま冠と支台の印を書きます
    (インプラントブリッジ)。
  - 歯は続けて選ぶ必要があります。ブリッジは支台とポンティックが 1 本以上、連結冠は支台が 2 本以上。
    同じ顎の別の装置と番号や歯が重なると反映できません。
  - 編集パネルの「ブリッジを編集」でその装置を読み込んで開きます。反映は読み込んだ装置をいったん外して書き直します。
    外した支台歯は冠を残して支台の印だけ消し、外したポンティックは喪失に戻します(「削除」も同じ)。
- **有床義歯**(`components/OralExamDentureModal.tsx`)。顎・床番号(1〜3 床目)・種類(局部義歯 / 総義歯)を選び、
  顎の歯式図で「人工歯」「クラスプ」「レスト」の役割を付けて、床(TM-4、種類で絞る)・人工歯(TM-6)・大連結子(TM-8)・
  補強線(TM-9)・クラスプの種類(TP-26)・材料をまとめて決めます。顎・床番号を変えると、その義歯が既にあれば読み込みます。
  - 人工歯の歯は基本状態 57・状態コード欠損歯で、TM-4・TM-5(2 床目以降)・TM-6・TM-8・TM-9 を同じ値でそろえて書きます
    (仕様の「有床義歯の範囲すべての欠損歯に記録」)。材料は人工歯の歯の特記事項に入ります。
  - 鉤歯は現在歯の内容の 1 行目に TP-26・TP-25・TP-34(2 床目以降)を書き足します。欠損歯には付けられません。
    人工歯と鉤は同じ歯に付かず、クラスプとレストは同じ歯に付けられます。
  - 開いたとき、その顎の喪失歯(補綴されていない欠損歯)を人工歯の候補として選んでおきます。
  - 「残根上」は残根(根面板)の上に義歯が乗る歯です。仕様の記録例どおり、義歯のグループ(1 つ目)と残根のグループ
    (2 つ目)の併存グループで書きます。残根のグループが既にあればそれを使い、無ければ根面板(失活歯・歯根部・
    根面板 金属・銀色)で作ります。義歯を外しても残根のグループは残ります。
  - 総義歯を選ぶとその顎の永久歯をすべて人工歯にし、クラスプ・レストは出しません。
  - 編集パネルの「義歯を編集」で読み込んで開きます。外した人工歯の歯は喪失に戻し、外した鉤歯はクラスプ・レストを消します。
  - バーとクラスプのろう着のように鉤歯の側に書く情報は、モデルケースどおりその歯の特記事項に書きます。
  - 基本状態(未処置歯・処置歯)・状態コード・健診記号・標準プロファイルは、押した内容から決まります。
  - コード表にある細かい種類(材質・色・窩洞など)は「選択」に戻して歯を押し、編集パネルで直します。
    スタンプは「銀色・内容不明」など代表的なコードを入れるので、必要なら編集パネルで置き換えます。
- **歯の編集パネル**(`components/OralExamToothEditor.tsx`)
  - 基本状態(TD-2)を選ぶと、状態コード(TB-3)と健診記号(TD-3)を既定値で埋めます(現在歯 0 / 欠損歯 2 /
    残根上義歯 6 / インプラント 7)。「(記録なし)」に戻すとその歯(グループ)の記録を消します。
  - 基本状態が欠損歯(インプラントを除く 50〜69)なら **欠損歯の内容**(TM)、それ以外は **現在歯の内容**(TP)を
    書きます(仕様上 TP と TM は排他。インプラントの上部構造・アバットメントは TP に書く)。
  - 現在歯の内容は「追加」で行を増やせます(1 歯 2 窩洞などの併存レコード)。歯面は IO / B / PL / M / D の
    チェック、萌出異常・クラスプ・歯肉などは「その他」に畳んであります。
  - 「併存グループを追加」は残根上義歯のように同じ歯に別のグループが要るときに使います。
  - 「過剰歯を追加」でその歯の近傍過剰歯(101A など)を足します。
  - 製品識別情報(TE-2〜4)・材料・特記事項(TE-6)。
  - **材料**は仕様にコードが無いので、配布の「口腔状態モデルケースとコード化例」と同じく特記事項(TE-6)の先頭に
    材料名を書きます(後ろの自由記載とは「、」で区切る)。選択肢の表記はモデルケースに合わせています(金銀パラジウム・
    銀合金・金合金・チタン・コバルトクロム・金床・CAD/CAM冠用材料・ハイブリッドレジン・硬質レジン・コンポジットレジン・
    グラスアイオノマー・セラミック・ジルコニア・ファイバーポスト)。選択肢に無い材料は特記事項に書きます。
  - 金属の材料を選ぶと、その歯の修復・補綴のコードの色を合わせます(金合金なら「金色」のコードへ。色だけが違う名称の
    コードがあるものに限る)。
  - **標準プロファイル 26 項目**(TF)は入力させず、選んだコードから導いて表示します(下記)。
- **口腔全体**(`components/OralExamMouthForm.tsx`): 口腔内装置等(KS)・矯正関係(KK)・その他の疾病及び異常(SI)・
  所見・特記事項(SK)。区分ごとに「追加」で行を足せます(矯正装置が 2 つなら矯正関係を 2 行。仕様のモデルケース 18 と
  同じ形)。歯式の欄は「歯式を選ぶ」で歯式図を選択モードにし、歯を押して足し外しします(「完了」で戻る)。
- 選択肢は「該当なし」(00)を空欄で表し、有効期限の切れたコード(診療報酬改定で廃止)は出しません。
- 保存は 1 回の transaction です。版が変わっていた(412)・先に削除されていた(404)ときは
  「他の操作によって更新されています」を出します。

### 標準プロファイル 26 項目の導出

コード表の各コードに付いた対応 TF(備考の〔TF-n〕)を集めます。乳歯は TF-3 を足します。仕様の排他関係表に従い、
TF-3〜TF-26 のどれかがあれば TF-27(歯あり・状態不明)を落とし、TF-3〜TF-27 のどれかがあれば TF-28(情報なし)を
落とします。1 つでもあれば TF-2(情報の有無)を 01 にします。

## FHIR の表現(`fhir/oralExamHelpers.ts`)

1 回の診査は、`identifier`(`http://fhir-client.local/oral-exam-snapshot` の uuid)で束ねた Observation の組です。
共通: `status=final`、`category=exam`、`subject`、`effectiveDateTime`=診査日、`performer`。

| 種類 | `code`(`http://fhir-client.local/CodeSystem/oral-exam`) | 件数 | 中身 |
|---|---|---|---|
| 見出し | `snapshot` | 1 | component に NS-2・NS-3・NS-4、`note` にメモ。一覧はこの code で引く |
| 歯 | `tooth` | 歯 × 併存グループ | `bodySite` = 歯種コード(MEDIS 標準歯式 `urn:oid:1.2.392.200119.4.1401`、4 桁)。component に TB-3・TB-4・TB-5・TD-2・TD-3・TM・TE(TE-8 更新日は `valueDateTime`)・TF |
| 現在歯の内容 | `tooth-content` | 併存レコードごと | 同じ `bodySite`。component に親の鍵(TB-3・TB-4・TB-5)と TP-2・TP-3〜34 |
| 口腔全体 | `mouth` | 区分の行ごと | component に KS・KK・SI・SK のいずれか 1 行分。歯式の項目は歯の数だけ繰り返す(値は 6 桁の歯式コード)。以前の全区分を 1 件にまとめた形も区分ごとに分けて読める |

- component の `code` は HL7 変換仕様の項目コード(JDAS 表 0003、OBX-3 の `TP11` など)を
  `http://fhir-client.local/CodeSystem/jdaoes-item` で持ちます(JDAS 表 0003 の OID が公開されていないため)。
- 値は `valueCodeableConcept` で、system は OID 表のコーディングシステム名の OID(`urn:oid:1.2.392.200354.1.2.1.5.3.11` など)。
  製品名・特記事項などの自由記載は `valueString`、日付は `valueDateTime`。
- HL7 の OBX-4(歯 T / 併存グループ U / 併存レコード R)にあたる束ねは Observation の単位で表します。
  現在歯の内容と親の歯は **歯種 + TB-3 + TB-4 + TB-5 の一致** で結びつけます(参照は使いません)。
  併存グループ連番(TB-5)・併存レコード連番(TP-2)は 2 つ以上あるときだけ付けます。「該当なし」は書きません。
- 保存は見出しを PUT(読んだ版を `If-Match` に添えて、見出しの版でスナップショット全体の競合を見る)、
  子は前回のものを DELETE して POST で作り直します。読み出しは `identifier` 1 回の検索です(上限 500 件)。
- `category=exam` なので、データ抽出で区分「診察」を選ぶと口腔診査の Observation も件数に入ります。
  感染症の手入力(`category=exam` + 種類コードで絞る)とは混ざりません。

所見・特記事項(`%oralExamNote`、SK-3)、歯ごとの健診記号(`%oralTeeth.where(tooth = '右上8').symbol`。`.abbr` で略号)、
歯式図の画像(`%oralExamChart`。様式の「画像」項目用。`fhir/oralExamChartImage.ts` が紙の歯式図と同じアーチ状に描く)を入れられます
(`fhir/populateOralExam.ts`)。本数の数え方は見出しの下の本数と同じです。
歯科疾患管理料の管理計画書(`../report-mappings/dental-plan-form-01.md`)の口腔内の状況の歯式図・むし歯の有無・歯数はこれで入ります。

## コード表(`/master/oral_exam_codes`)

配布の「マスター形式データ」と「OID 表」(xlsx)から、TB/TD/TP/TM/TE/TF/NS/KS/KK/SI/SK のコード値を持つ行
(827 行)を `backend/db/seed_data/oral_exam_codes.csv` にしてあります。列は record / item / item_name / code / display /
tf_ref(対応 TF)/ cs_name / cs_oid / note / display_order。

- 投入は `OralExamCodeSeed.load!` で、`db:seed` と migration(本番は起動時に seed が走らないため)の両方から呼びます。
  同じ (item, code) の行は触りません。
- 固定の標準コード表なので API は一覧だけで、マスタメンテ画面はありません。
- 版が上がったら配布 xlsx を `backend/tmp/master-data/oral-exam/` に置いて CSV を作り直します。

```bash
docker compose exec backend bin/rails "master_oral_exam_codes:csv[tmp/master-data/oral-exam/<マスター形式データ>.xlsx,tmp/master-data/oral-exam/<OID表>.xlsx]"
```

## CSV 出力(口腔状態スナップショット)

タブの見出しの「CSV出力」で、表示中の診査を仕様の CSV ファイル(`.oes`)にしてダウンロードします。
レコードは画面(`fhir/oralExamCsv.ts`)が組み立て、backend(`POST /reports/oral_exam_file`、`OralExamSnapshotFile`)が
仕様の記録方式どおりのバイト列にします。

- **ファイル名**: 医療機関内等 ID(患者番号の数字、6 桁未満は先頭を 0 で埋める)-出力日時(14 桁)-スナップショット日時
  (診査日 + 時刻不明の `999999`).oes。
- **文字と区切り**: Shift_JIS(Windows-31J)、項目はカンマ区切りで引用符なし、レコードの末尾は CR LF、ファイルの最後は
  改行の後に EOF(0x1A)。JIS 規定外の文字は全角の「？」に置き換えます。「〜」「−」など Windows-31J で別の字に割り当てられた
  記号は寄せます(DPC 様式1 の出力と同じ表)。自由記載のカンマ・引用符は全角に、改行は空白にし、最大バイト数で切ります。
- **レコード**: VR(`JDAOES000102`)・ON・PN・NS・歯の診査情報レコードグループ(歯ごとに TB・TD・TP・TM・TE・TF を仕様の
  記録順で)・KS・KK・SI・SK・DT。予備を含めた項目数はレコードごとの定義どおりで、情報の無いレコードは書きません。
  - ON(入力機関): 入力機関種別「医療機関」(02)、都道府県コードと入力機関コード(10 桁)は自院の保険医療機関番号から、
    名称・電話番号は自院の Organization から。診療科は仕様の既定どおり「90 歯科」。
  - PN(個人識別): 医療機関内等 ID(患者番号)・診療年月日(診査日)・氏名・フリガナ・性別・生年月日・年齢・郵便番号・
    住所・電話番号。
  - TB の併存グループ連番・TP の併存レコード連番は 2 つ以上あるときだけ書きます。TF は画面と同じ導出、TE-8 は歯ごとの更新日。
  - 歯式の項目(KS-4・KK-9・SI-5・SI-8・SK-4)は 6 桁の歯式コードを区切らずに並べます(仕様のモデルケースと同じ)。
  - DT: 出力年月日・時刻と、スナップショット作成年月日(診査日)・時刻(不明の `999999`)。
- 自院・保険医療機関番号・患者番号・性別・生年月日が無いときは、その項目を空にして出力し、見出しの下に知らせます。
- 書かないもの: 送信先機関(ON-2〜5)、保険(PN-2〜6)、医療等 ID(PN-8・9)、健診の実施名称(PN-10・11)。いずれも省略可です。
