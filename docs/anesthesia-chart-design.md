# 麻酔チャート(術中リアルタイム記録)の設計

手術オーダー第3段階(`docs/surgery-order-design.md` §7-2)の残りだった、術中の
リアルタイム記録。5 分毎のバイタルサイン・麻酔経過のイベント・薬剤投与を、
手術中にその場で 1 点ずつ記録し、チャート(グラフ + 表)で見せる。

麻酔記録テンプレート `SUR_ANES_01`(`docs/report-mappings/sur-anes-01.md`)が
「退室後にまとめて書く要約」なのに対し、こちらは**術中に進行形で足していく時系列**。
両者は併存する(チャートが事実の記録、テンプレートが考察と申し送り)。

実装日: 2026-08-28。

本文中の区別:
- **［事実］** = FHIR R4 / JP Core の仕様、または上流・既存実装で確認した内容
- **［導出］** = 仕様から論理的に導ける内容
- **［提案］** = 本ドキュメントの設計判断

---

## 1. 実施入力・経過表との棲み分け

| # | 既存のもの | チャートとの関係 |
|---|---|---|
| 1 | **実施入力**(`docs/surgery-result-design.md`。退室後にまとめて 1 回) | 別のツリー。実施入力は算定と提出データの完成形、チャートは術中の進行形の記録。実施取消でチャートは消えない(§2.2) |
| 2 | **実施入力の薬剤**(MedicationAdministration) | 算定に載せる薬剤は従来どおり実施入力に入れる。チャートの薬剤は「いつ・どれだけ入れたか」の記録で、算定への流し込みは申し送り(§7) |
| 3 | **バイタル**(category: vital-signs。経過表・カルテのバイタルカード) | チャートの打点は category を持たせず、経過表・カルテに**出さない**。5 分毎の打点で経過表が埋まるのを避ける(手術の測定値・被曝線量と同じ流儀) |
| 4 | **Task の入室中**(`surgeryTaskHelpers`) | チャートは入室中に開始するのが通常運用だが、Task とは独立(チャート開始で Task は動かさない)。実施済(退室後)のオーダーでも閲覧できる |

［提案］**記録は 1 点ずつ即保存する**。実施入力の「完成形で 1 回書く」作法から
外れるが、麻酔記録は術中に端末が落ちても失われないことが第一で、進行形である
こと自体が記録の性質。そのためチャートのハブは記録中 `in-progress` を持つ
(実施入力ハブが completed で生まれるのとは意図的に違える)。

## 2. FHIR の構造

```text
ServiceRequest(申込) ←basedOn── Procedure チャートハブ(オーダー単位で1件)
                                  │ status = in-progress(記録中) / completed(確定)
                                  │ category = order-type|anesthesia-chart
                                  │ code = 「麻酔チャート」(ローカル固定)
                                  │ performer[0] = 麻酔担当(function = surgery-staff-role|anesthesiologist)
                                  │ performedPeriod = 開始〜確定
                                  ├ partOf ← Observation (バイタル打点。category 無し)
                                  ├ partOf ← Observation (イベント。code = anesthesia-event)
                                  └ partOf ← MedicationAdministration (薬剤。単回/持続)
```

- ［事実］手術の実施記録と同型(ハブ Procedure + partOf の子)。読み出しも同じ
  検索(`Procedure?based-on=SR` + `_revinclude` / `part-of` 検索)が使える。
- ［提案］ハブの category は `order-type` システムに **`anesthesia-chart`** を足して
  区別する。実施記録側の振り分け(`isSurgeryProcedure`)は category = `surgery` を
  見るので、チャートのハブ・子が実施記録として表示されることはない。

### 2.1 子リソース

**バイタル打点**: 1 時点 1 項目 = 1 Observation(`effectiveDateTime`)。血圧だけは
バイタル入力(`vitalHelpers`)と同じく 85354-9 のパネル 1 件に収縮期・拡張期を
component で持つ(組で読めなくなるため)。コードは LOINC:

| 項目 | code | 単位(UCUM) |
|---|---|---|
| 血圧 | 85354-9(component 8480-6 / 8462-4) | mmHg |
| 脈拍 | 8867-4 | /min |
| SpO2 | 2708-6 | % |
| EtCO2 | 19889-5 | mmHg |
| 体温 | 8310-5 | Cel |
| 呼吸数 | 9279-1 | /min |

［提案］category は持たせない(§1-3)。経過表に出す判断をする日が来たら、
category を足す migration ではなく経過表側の取得条件を変える。

**イベント**: `code = ローカル CodeSystem anesthesia-event` の Observation。
値は持たず時刻(`effectiveDateTime`)が本体。自由文イベントは code `other` +
`note` に本文。麻酔開始・挿管・執刀開始・執刀終了・抜管・麻酔終了・その他。

［導出］イベントを Observation にするのは「後から 1 件ずつ足し引きする時系列の
1 点」だから。ハブの拡張リストにすると毎回ハブを PUT することになり、
2 端末同時記録で上書き競合する。

**薬剤**: MedicationAdministration。
- 単回(ボーラス): `effectiveDateTime` + `dosage.dose`。status = completed。
- 持続(シリンジポンプ等): `effectivePeriod.start` + `dosage.rateQuantity`。
  投与中は status = **in-progress**(FHIR の正規の値)で end 無し。「終了」操作で
  end を入れて completed にする。
- 経路は実施入力と同じ JP Core route-codes(`SURGERY_ROUTE_OPTIONS`)。

### 2.2 実施取消との干渉(既存バグの修正)

［事実］実施取消(`useUpdateSurgeryTaskStatus`)は `Procedure?based-on=SR` +
`_revinclude` で拾った Observation / MedicationAdministration を**無条件に全部
DELETE していた**。チャート導入後はこの検索にチャートの子も入るため、実施取消が
麻酔チャートの記録を巻き添えにする。

`buildSurgeryPerformDeleteEntries` を、**手術の実施記録(category = surgery)の
Procedure に partOf でぶら下がる子だけ**を消すように直した(ハブの絞り込みは
従来からあったが、子の絞り込みが無かった)。逆にチャートの取消(§4)は
チャートハブの子だけを消す。

## 3. 画面

### 3.1 入り口

手術一覧(`SurgeryWorklistPage`)の行の**ケバブメニュー**(`RowMenu`)に「麻酔チャート」を
足す。出すのは**入室中**と**実施済**の行だけ(チャートを書き始めるのは入室後で、
実施済では振り返りに読む)。遷移先は専用ページ `/surgeries/:orderId/anesthesia-chart`。

［提案］行に直接ボタンを並べず**ケバブに畳む**。一覧の常設の並びは「今その行で
進める操作」(受付・入室・実施)のためのもので、チャートは手術室の担当者が別の
文脈で開くもの。常設にすると列が伸び、押す頻度の高いボタンが右へ流れる
(`ui-compact-band-kebab-menu` と同じ判断)。

［提案］モーダルではなくページにする。チャートは手術中ずっと開きっぱなしにする
画面で、グラフ + 表 + 3 種の入力を持ち、モーダルの幅では足りない。

### 3.2 ページの構成

1. **ヘッダ**: 患者(氏名・患者番号)・術式・手術室・予定・麻酔担当(ハブの
   performer)。チャート未作成なら「チャート開始」ボタンだけを出す
   (押すとハブを作る。麻酔担当はログイン中の医療従事者)。
2. **グラフ**(SVG): 横軸 = 時刻。収縮期(∨)・拡張期(∧)・脈拍(●)を 0〜220 の
   共通軸に描く(紙の麻酔チャートと同じ流儀)。イベントは上端に ▼ + ラベル。
   SpO2 など軸の違う項目はグラフに重ねず表で見せる。横に長くなるので
   スクロールコンテナに入れる。

   ［提案］記号の**凡例**をグラフの上(倍率ボタンの右)に置く。∨ と ∧ は紙の
   チャートの流儀で、初見では収縮期・拡張期のどちらか分からない。凡例の記号は
   グラフと同じクラス(`anes-plot__bp` など)で描くので、色や形を変えたときに
   凡例だけ取り残されない。

   ［提案］**横軸の目盛りは 4 段階から選べる**(広く 1.5px/分・標準 4px/分・
   拡大 10px/分・**全画面**)。手術は 30 分で終わるものから 8 時間を超えるものまであり、
   1 分あたりの幅を固定すると短い手術は左端に潰れ、長い手術は延々と横に伸びる。
   拡大はイベントのラベルが重なったときの逃げ道にもなる。グリッドと時刻ラベルの
   間隔は 1 分あたりの幅から決めるので(`gridSpec`)、どの倍率でも目盛りが詰まらない。

   ［提案］**「全画面」は 1 分あたりの幅を持たず、記録の全体が画面幅に収まるよう
   その場で計算する**。短い手術で枠が左に縮むのも、長い手術で横スクロールが要るのも
   避けられる。幅は `ResizeObserver` で追うが、**初回は同期で測る**
   (`useLayoutEffect` + `getBoundingClientRect`)。observer の初回配信を待つと、
   標準の幅で 1 度描いてから飛ぶ。［事実］配信は rAF のタイミングなので、
   非表示のタブでは止まる(自動化で確認したときに気付いた)。

   ［提案］**軸の範囲は「記録がある範囲」で決める**(記録中は右に 15 分の余白、
   確定後は 5 分)。ハブの開始時刻や「今」まで伸ばすと、記録を止めている間や
   退室後に開いたときに余白ばかりの軸になる(打点が 15 分ぶんしか無いのに
   軸が 9 時間あるような状態)。記録が 1 件も無いうちだけ、開始時刻から 30 分を
   枠として見せる。
3. **バイタル表**: 列 = 時点、行 = 項目。時点の列頭に削除(その時点の打点を
   まとめて消す)。追加フォームは時刻(既定 = 今)+ 各項目で、入力した項目だけ
   Observation になる。

   ［提案］時刻の入力には**「現在」ボタン**を添える(バイタル・イベント・薬剤の
   3 つとも)。既定値は画面を開いた時刻で止まるので、記録しながら使うと必ず古くなる。
   ［提案］列頭の削除は**枠も地も持たせず沈める**。常時 4〜5 個が横に並ぶので、
   ボタンとして目立つと表の数字が読みにくくなる。行の削除(イベント・薬剤)は
   ゴミ箱アイコン(既存の `rp-card__icon-button`)に揃える。
4. **イベント**: 種別(+ その他は自由文)と時刻で追加。一覧に削除。
5. **薬剤**: 薬剤検索(`MedicineSearchModal`)から単回/持続を選んで追加。
   持続の行には「終了」(end を入れて completed)。一覧に削除。
6. **確定 / 再開**: 確定でハブを completed にし performedPeriod.end を打つ。
   確定後は入力 UI を出さない(閲覧のみ)。「再開」で in-progress に戻す。
   「チャートを取消」(記録ごと削除)はケバブ相当の副次操作で、confirm を挟む。

### 3.3 保存の単位

- チャート開始 = ハブ 1 件の POST。
- バイタル追加 = その時点の Observation 一式を 1 transaction(血圧 + 脈拍 +
  SpO2 を別々に POST して途中で失敗すると、時点の組が欠けるため)。
- イベント・薬剤 = 1 件ずつ POST / PUT。
- 時点の削除 = その時点の Observation を 1 transaction で DELETE。
- チャート取消 = 子 → ハブの順に 1 transaction で DELETE(実施取消と同じ理由で
  entered-in-error は使わない。履歴は上流の _history に残る)。

### 3.4 読み出し

ハブは `Procedure?based-on=ServiceRequest/<id>` から category で選ぶ。子は
`Observation?part-of=Procedure/<hubId>`・`MedicationAdministration?part-of=...` を
`_offset` でページングして全件読む(5 分毎 × 数時間で 100 件を超えるのが普通
なので、実施記録のような 1 ページ読みでは足りない)。

## 5. 検証したこと

開発環境(2026-08-28、テスト太郎の胆摘オーダー)で以下を通した。`tsc -b` clean・
`oxlint` 既存 4 warnings のみ。

1. **開始**: 手術一覧の実施済(のち入室中でも)の行のケバブに「麻酔チャート」が出る
   (日程未定タブ・申込済/受付済の行には出ない)→ ページで「チャート開始」→ ハブが
   in-progress で作られ、麻酔担当 = ログイン中の医療従事者(児玉)、ヘッダに
   術式・手術室・予定・「記録中」バッジ
2. **打点**: 4 時点(01:00〜01:15)を追加。FHIR 上で血圧が 85354-9 のパネル
   (component に 8480-6/8462-4)、他が LOINC 単項目 + UCUM、時刻が JST オフセット付き、
   全打点が `partOf = チャートハブ` になること。表(列 = 時点)とグラフ
   (∨/∧ = 血圧・● + 折れ線 = 脈拍)に反映
3. **イベント**: 麻酔開始・挿管・執刀開始。グラフに ▼ + 破線 + ラベル
4. **薬剤**: プロポフォール単回(effectiveDateTime + dose)と
   レミフェンタニル持続(status in-progress・effectivePeriod.start + rateQuantity)。
   「投与中」表示 → 「終了」で end が入り completed
5. **時点の削除**: 01:10 の × でその時点の Observation 一式が 1 transaction で消え、
   表・グラフから消える → 同値を再追加
6. **確定 / 再開**: 確定でハブ completed + performedPeriod.end、入力 UI が消えて
   閲覧のみ。「再開(確定を解除)」で in-progress + end 除去 → 再度確定
7. **実施取消の巻き添え防止(§2.2)**: 実施記録(手術ハブ)がある状態で実施取消 →
   手術ハブだけが消え、**チャート(ハブ + Observation 20 件 + MedicationAdministration
   2 件)は無傷**で残ることを上流への直接検索で確認。その後実施を再登録し、
   チャートと実施記録が同じオーダーに共存すること

8. **サンプルデータ**(2026-08-28 追加): 緊急の腹腔鏡下胆嚢摘出術
   (`daeef4bd-861e-433f-a829-be522c1a9242`)に 2 時間ぶんの記録を投入した
   (打点 25 時点・イベント 8 件・薬剤 9 件、リソース計 143 件を 1 transaction)。
   入室時の緊張 → 導入で下降 → 挿管で一過性の上昇 → 気腹・執刀 → 出血で低下し
   エフェドリンで回復 → 覚醒に向けて上昇、という推移にしてある。

［実装］イベントのラベルは**近接すると 1 段下げる**(「前のラベルの半分 + 自分の
半分」が空いていなければ段を変える。2 段で足りない密度は「拡大」で開く)。
麻酔開始と挿管のように数分差で続くイベントは実運用でも必ず起きる。

［実装］グラフの枠は中身の幅に合わせる(`width: fit-content`)。短い手術では
グラフが画面幅より狭くなり、枠を全幅にすると右が余白だけの帯になる。

## 7. 申し送り

1. **生体情報モニタ接続**: 打点は手入力。モニタ(HL7 / ベンダー API)からの自動
   取り込みは、このチャートの Observation を書き込み先にする形で足せる。
2. **実施入力への流し込み**: チャートのイベント時刻(麻酔開始・執刀開始…)と
   薬剤を、実施入力フォームの初期値に流し込めば二度書きが減る。実施入力側の
   フォーム初期化にチャートの読み出しを足すだけで済む構造にしてある。
3. **カルテでの見え方**: チャートはカルテのタイムラインに出していない(手術
   カードの実施情報とテンプレートが要点を持つ)。カルテから読みたい要望が出たら、
   手術カードの詳細モーダルにチャートへのリンクを足すのが最小。
4. **帳票**: 麻酔チャートの印刷(紙カルテ運用・他院提供)は ThinReports では
   グラフを描けないので、SVG → PDF の別経路が要る。
5. **同時編集**: 1 点 1 リソースなので追加同士は衝突しないが、ハブの確定と
   追加が同時に走ると「確定後の追加」が残りうる。運用(麻酔担当 1 人が記録)で
   足りている間は楽観のまま。
