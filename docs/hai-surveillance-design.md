# 医療関連感染サーベイランス(手術部位感染・デバイス関連感染の判定と発生率)の設計

`docs/functional-gap-backlog.md` §6.0 #3・§6.1「医療関連感染サーベイランス」。
**状態: 第 1 段階を実装済(2026-11-17)。** 手術部位感染(SSI)の判定と発生率、デバイス関連感染(CLABSI / CAUTI / VAP)の
判定と感染率まで。JANIS の提出ファイル・リスクインデックス・手指衛生は §7。
画面の表記は「感染サーベイランス」。コードやパスの識別子は `hai-surveillance` / `infection-surveillance`。

- **［事実］** = FHIR 仕様、このリポジトリ・上流(`../fhir-server`)の実装で確認した内容
- **［設計］** = 本ドキュメントの決めごと
- **［要確認］** = JANIS の実施マニュアル・施設の運用で確かめていないこと

## 1. 背景とスコープ

感染対策向上加算は JANIS などのサーベイランスへの参加を求める。感染対策チーム(ICT)は、手術のあと 30 日
(埋入物のある手術は 90 日)の創部の経過と、中心静脈カテーテル・尿道留置カテーテル・人工呼吸器の留置中の感染を
追い、手術件数・デバイス日数を分母に発生率を出す。分母になる記録(手術の実施記録と創分類、留置台帳とデバイス日数)は
既にあるが、感染の判定を残す器と、判定を追う一覧が無かった。

含めるもの:

- 判定の記録(Observation)。対象は手術の実施記録、または留置
- 一覧(診療業務 > 感染サーベイランス、`/infection-surveillance`)の 3 タブ
  - 「SSI判定」: 手術 × 術後日数 × 術後の培養陽性 × 判定。CSV
  - 「SSI発生率」: 創分類別・依頼科別の手術件数・SSI 件数・発生率
  - 「デバイス関連感染」: 病棟 × 月のデバイス日数・感染件数・感染率と、対象の留置の判定

含めないもの(§7): JANIS の提出ファイル、手術手技分類とリスクインデックス、手指衛生遵守率、判定基準のチェックリスト、
感染の通知・カルテのカード。接触者追跡・隔離(`functional-gap-backlog.md` §4.2)と耐性菌の感受性推移は別の機能。

## 2. 判定の記録(`Observation`)

［設計］新しいリソースは足さない。感染の判定 1 件 = Observation 1 件で、対象を `partOf` で指す。

```text
Observation
  status                = final
  category              = http://fhir-client.local/CodeSystem/observation-category | hai-surveillance 「医療関連感染」
  code                  = http://fhir-client.local/CodeSystem/hai-surveillance | ssi / clabsi / cauti / vap
  subject               = Patient
  encounter             = 対象の Procedure の encounter(あれば)
  partOf[0]             = Procedure(手術の実施記録のハブ、または留置)
  effectiveDateTime     = 診断日(感染なしは判定日)。日付だけ
  valueCodeableConcept  = hai-surveillance | infected 「感染あり」/ not-infected 「感染なし」
  performer[0]          = 判定者(ログイン中の医療従事者。管理者ログインでは無し)
  component[]           (code は hai-surveillance 体系)
    depth     感染部位  valueCodeableConcept: superficial 表層切開創 / deep 深部切開創 / organ-space 臓器・体腔(SSI の感染ありだけ)
    implant   埋入物    valueBoolean true(SSI だけ。あるときだけ書く)
    pathogen  起因菌    valueString(感染ありだけ)
  note[0].text          = コメント(判定の根拠)
```

- ［事実］上流で対象から判定を引ける参照は `Observation.partOf`(`part-of` 検索と `_revinclude=Observation:part-of`)。
  `focus` の検索は無い(`server-improvement-backlog.md` C-29)。手術の測定値(出血量など)と留置の刺入部観察も
  同じ `partOf` で結んでいるので、判定は既存の検索にそのまま乗る。
  - 手術: `fetchSurgeryExtract`(手術実績の抽出・NCD 症例登録と同じ検索)の `_revinclude=Observation:part-of`
  - 留置: 留置台帳の検索の `_revinclude=Observation:part-of`
- ［設計］同じ `partOf` に並ぶ記録は `code` で分ける。手術の測定値は `SURGERY_OBSERVATION_FIELDS` の code だけを拾い、
  刺入部観察は `line-drain-site-finding|site-check` だけを拾う(`parseSiteObservation`)。判定は `category` で見分ける。
- ［設計］デバイス関連感染の種別は留置の区分から決まる(`haiTypeOfKind`): 中心静脈 → CLABSI、尿路 → CAUTI、気道 → VAP。
  それ以外の区分は対象にしない。
- ［設計］判定は対象 1 件に 1 つ。更新はフォームから組み直して PUT(`withVersionLock`、版違いは 412)、判定者は登録した人のまま。
  削除は DELETE(刺入部観察と同じ)。同じ対象に複数あれば診断日の新しいものを採る(`haiJudgmentsByTarget`)。
- ［設計］Provenance は付けない。オーダーではなく観察の記録で、誰が判定したかは `performer`(留置・有害事象の決定を踏襲)。
- ［設計］起因菌は文字列で持つ。入力欄の候補に術後の培養陽性の菌名を出す。細菌検査結果(分離菌の Observation)への参照は持たない
  (検体と感染の対応は判定者の判断で、1 対 1 にならない)。
- ［設計］判定はカルテの時系列に出さない(時系列はこの category の Observation を読まない)。見るのは一覧だけ(§7-7)。

## 3. 状態と期限

| 画面の状態 | 判定 | `valueCodeableConcept` |
|---|---|---|
| 未判定 | 無し | — |
| 感染なし | あり | not-infected |
| SSI / 感染あり | あり | infected |

- ［設計］SSI の観察期間は術後 30 日、判定に「埋入物」があれば 90 日(`SSI_FOLLOW_UP_DAYS` / `SSI_IMPLANT_FOLLOW_UP_DAYS`)。
  観察期間を過ぎて未判定の手術は術後日数を赤で出す。感染なしの判定は観察期間が終わってから入れる運用で、画面は時期を縛らない。
- ［要確認］埋入物ありの観察期間(90 日)と、対象にする手術手技の範囲。JANIS SSI 部門は対象の手術手技を施設が選ぶ。
  一覧は全手術を出し、依頼科で絞る前提。
- ［設計］判定の日付は対象の始まり(手術日・挿入日)から今日まで。SSI の感染ありは感染部位が必須。

## 4. 画面(`pages/InfectionSurveillancePage.tsx`)

判定はタブの中のボタンとモーダル(`components/HaiJudgmentModal.tsx`)で書く。カルテの右ペインは開かない。

### 4.1 「SSI判定」

- 絞り込み: 手術日の期間(既定は今日までの 90 日)・依頼科・判定(未判定 / 感染なし / SSI)。URL に持つ。
- 行 = 手術の実施記録 1 件(NCD 症例登録と同じ対象。`not-done` を除く)。患者番号・患者・手術日・術式・依頼科・創分類・
  手術時間(執刀開始〜終了)・術後日数(期限超過は赤)・培養陽性・判定・感染部位・診断日・起因菌・判定者・「判定」。
- **培養陽性**: 手術日の翌日から観察期間の終わりまでに採取した細菌検査結果のうち、分離菌のあるものの件数。
  内訳(採取日・材料・菌名)はツールチップ。未判定で陽性があれば赤。判定の手がかりで、SSI かどうかは判定者が決める
  (血液・尿など創部以外の検体も数える)。細菌検査の抽出(`fetchMicroExtract`)を候補の患者だけで引く。
- **CSV**: 表示中の行を `SSI_CSV_HEADER` の列で出す。［要確認］JANIS SSI 部門の提出形式には合わせていない。

### 4.2 「SSI発生率」

- 同じ期間・依頼科の手術を、創分類別と依頼科別にまとめる(`ssiRateSummary`)。列は手術件数・未判定・SSI・
  感染部位ごとの件数・発生率(SSI ÷ 手術件数 × 100)。末尾に合計。
- ［設計］分母は期間内の手術すべて。観察期間が終わっていない手術も入るので、未判定の件数を並べて出す。
- 手術を読み切れていないとき(`truncated`)は表を出さない(分母が欠ける)。

### 4.3 「デバイス関連感染」

- 病棟 × 月(留置物管理の「デバイス日数」タブと同じ在院の計算。`hooks/useWardMonthPresence.ts` を共用)。
- 中心静脈カテーテル(CLABSI)/ 尿道留置カテーテル(CAUTI)/ 気管チューブ(VAP)ごとに 1 区画。集計と対象の留置を同じ区画に置く。
- 区画の見出し: デバイス日数・感染件数・感染率(感染件数 ÷ デバイス日数 × 1000)・使用比。
  感染件数は、その月に病棟に居た患者の留置のうち診断日が月内(当月は今日まで)のもの。
- 区画の表: 月と重なる対象の留置。患者・種別と部位・留置期間(挿入日〜抜去日。抜去前は「留置中」)・留置日数・
  抜去区分(「感染疑い」で未判定は赤)・判定・診断日・起因菌・判定者・「判定」。列幅は区画をまたいで揃える。
- 入院または留置を読み切れていないときは表を出さない。
- ［設計］転棟した患者の感染は、その月に居た病棟すべてで数えられる(デバイス日数は居た日の分だけ)。病棟の特定は判定に持たない。

## 7. 未実装・今後

1. **JANIS の提出ファイル**(SSI 部門・全入院患者部門): 提出形式を確かめていない。CSV は一覧の控え。
2. **手術手技分類とリスクインデックス**: JANIS の手術手技コード(COLO・CHOL など)と K コードの対応マスタが無い。
   リスクインデックス(創分類・ASA-PS・手術時間のカットオフ)は手技分類ごとのカットオフが要るので、対応マスタと同時に足す。
   ASA-PS は麻酔科術前診察の回答にある(`docs/anesthesia-preop-design.md`)。
3. **手指衛生遵守率**: 病棟 × 月の観察回数・実施回数の入力(backend の台帳)。
4. **判定基準のチェックリスト**: 基準(創部の排膿・培養・症状など)を項目で持たず、根拠はコメントに書く。
5. **デバイス関連感染の培養の手がかり**: 血液培養・尿培養の陽性を留置の行に出す(いまは SSI だけ)。
6. **通知・ホームのカード**: 観察期間を過ぎた未判定の件数、抜去区分「感染疑い」の未判定。
7. **カルテでの表示**: 判定は一覧でだけ見る。プロファイル区画「留置物」や手術のカードには出していない。
8. **データ抽出・指標**: SSI 発生率・感染率を「指標」タブに足す(延べ日数が分母の指標はまだ表せない)。
9. **医療関連感染のその他**: 血管内留置以外の血流感染、CDI、耐性菌の新規検出は対象外。

  「判定」で SSI・表層切開創・起因菌を登録すると行に出て、「SSI発生率」の創分類別・依頼科別に数えられること。
