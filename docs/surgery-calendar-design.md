# 手術室カレンダーとダブルブッキング防止の設計

手術オーダー第1段階(`docs/surgery-order-design.md` §7-3)の残りだった、手術室の
可視化・部屋の取り合いの防止・曜日ごとの科割り当てをまとめて扱う。

実装日: 2026-08-28。

本文中の区別:
- **［事実］** = FHIR R4 / JP Core の仕様、または上流・既存実装で確認した内容
- **［導出］** = 仕様から論理的に導ける内容
- **［提案］** = 本ドキュメントの設計判断

---

## 1. 予約枠(Slot)を使わない判断は変えない

第1段階で「手術は予約枠を持たない」と決めた(`surgery-order-design.md` §1)。
カレンダーを入れるにあたって作り直す選択肢もあったが、そのままにした。理由は 4 つ。

1. **［事実］枠は事前量産で、手術の時間は可変**。`SlotPattern`(曜日 × 時間帯 ×
   1 枠の長さ × 定員)から固定長の枠を作り置きする方式なのに対し、手術の所要時間は
   術式ごとに 30 分〜8 時間まで散らばり、開始時刻も枠境界に乗らない(前の手術が
   延びればその日の全部が後ろへずれる)。5 分刻みで作れば 1 部屋 1 日で 200 件近い
   Slot になり、しかも毎日ずらす。
2. **［事実］申し込む人と日程を決める人が違う**。既存 4 種は
   `buildExamAppointmentEntries` のとおりオーダーの transaction に予約を同梱する
   先着モデル。手術は診療科が日程未定で申し込み、手術部が後から組む(§5.2)。
   枠を取る操作が申込から切り離されている。
3. **［導出］多資源の同時確保が表現できない**。`AppointmentSlotPicker` は枠表を
   1 つ選ぶ作りで、複数枠表の空きの AND を取れない。手術は 手術室 × 執刀医 ×
   麻酔科医 の同時空きが要る。(部屋 × 執刀医)の組み合わせごとに枠表を作れば
   組み合わせ爆発するし、麻酔科医は当日まで決まらないことも多い。
4. **［導出］ブロックスケジュールの融通が枠表分割では効かない**。`Schedule.specialty`
   で部屋 × 曜日 × 科の枠表に割っても、「割当科が使わない枠を前日に他科へ開放する」を
   別枠表の Slot 間で動かせない。

［提案］したがって**部屋の空き状況の真実の源は手術オーダーそのもの**
(`occurrenceDateTime` + 所要時間のローカル拡張)のままにする。カレンダーはその
読み替えで、新しいリソースは作らない。**上流 fhir-server の改修は不要**
(使う検索は既存の `occurrence` だけ)。

［導出］Slot を捨てた代償は排他の仕組みが無いこと。そこを埋めるのが §3。

## 2. 手術室カレンダー

手術一覧(`/surgery-worklist`)の 3 つ目のタブ。日付は一覧タブと共有していて、
一覧で見ていた日のままカレンダーへ移れる。

［実装］読むクエリは一覧と同じ `useSurgeryWorklist(date)`。**queryKey が同じ**なので
タブを切り替えても読み直しは起きない。週表示は `useSurgeryWorklistWeek` が同じ
クエリを 7 本並べるだけで、週から日へ降りるときもキャッシュがそのまま効く。

### 2.1 日ビュー(横 = 手術室、縦 = 時刻)

当日の運用把握と、部屋の重なりの視認。

- 列は**登録済みの手術室(Location 種別 `SU`) ∪ その日に使われている部屋**。
  マスタから消えた部屋に予定が残っていても列が消えないようにする。
- 1 分 = 1px の絶対配置。時間軸は既定 8:00-18:00 で、はみ出す予定があれば
  その ぶんだけ広げる(夜間の緊急手術が格子の外に出ないように)。
- **［提案］日をまたぐ手術は 24:00 で切る**。またぎを正しく描くには翌日の列が要り、
  1 日の格子という前提が崩れる。長時間手術の終了時刻は一覧・詳細で読む。
- **重なりは列の中で横に分ける**。重なりの塊ごとに必要なレーン数を数え、その塊の
  全員を同じ分割数で描く(幅が揃って読みやすい)。重なったカードは警告色。
- **中止は出さない**(部屋を空けるので、一覧・重なり判定と同じ扱い)。
- **［提案］時刻・手術室が未定の手術は格子の下に列挙する**。格子に置けないからと
  落とすと、予定が消えて見える。

#### カードの中身

上から ステータス + 入室〜退室予定 / 患者(番号・氏名(カナ)・年齢・性別) /
主術式 / 執刀医。見出し行(1 行目)と本文の間だけ余白を空けて、2 つのまとまりに見せる。

［提案］時刻は**終了予定まで出す**(`rangeLabel`。一覧・確認モーダルと同じ書式)。
所要時間はカードの高さでも分かるが、重なりを詰めるときに読みたいのは数字の方。

［導出］**カードの高さは所要時間で決まる**ので、短い手術では下の行が隠れる。
そこで**隠れて困る度合いが低いものを下に置く**。当日の手術部が見るのは「今どの部屋で
誰の何が動いているか」なので、ステータスと患者を上に置き、執刀医を最後にした。
全文は title(ツールチップ)に入れてあるので、隠れても読めなくはならない。

［提案］患者氏名を出す。第1段階の `SurgeryRoomDaySchedule`(§5.5)は患者名を
**出さない**判断をしたが、あちらはカルテの申込フォームからも開く「空き確認」の
表示で、無関係な患者の氏名を並べる必要がなかった。カレンダーは手術部の業務画面で、
一覧タブと同じ情報が並ぶ場所なので、そろえて出す。

［提案］ステータスは色を 3 つに分ける(これから = 受付済 / 進行中 = 入室中 /
済 = 実施済)。申込済は色を付けない —— まだ手術部が触っていない状態で、
カレンダー上で目立たせる意味がない。

［提案］**強弱は「ステータス + 時刻」と「患者氏名」に寄せる**。カードを離れて見た
ときに拾いたいのはこの 2 つで、他は近づいて読む情報。具体的には見出し行
(ステータスの枠付きバッジ + 時刻)と氏名を太字・`--text-h`・本文より 1px 大きく、
カナだけ括弧書きの補足として小さく保つ。**患者番号・年齢・性別は本文と同じ大きさ**
にする(氏名を特定するための添え物だが、読めなければ意味がないので縮めない)。
なお年齢・性別に `.order-select__muted` は使わない —— padding が付いて行が間延びする。

#### カードの操作(進捗ボタンとケバブ)

見出し行の右端に、一覧タブ(予定日別)と同じ組み方で置く。押せる操作・遷移先は
`surgeryTaskActions` が持っているものをそのまま使う。

- **普段押す操作をボタンに**(申込済 → 受付 / 受付済 → 入室 / 入室中 → 実施)。
  格子の中の操作なので一覧の行ボタンより一段小さくする。
- **「実施」は実施入力モーダルを開く**。ステータスを進めるだけでなく実施記録を
  書く操作なので、一覧タブと同じ `SurgeryPerformModal` に繋ぐ。
- **押し間違えると進捗が巻き戻る操作(取消・中止)はケバブに畳む**。麻酔チャート
  (入室中・実施済でだけ開ける)と「カルテを表示」も同じメニューに入れる。
  カルテへは一覧の患者名リンクと同じく `useKarteLinkState` で戻り先を渡す。

［導出］操作は**必ず見出し行(1 行目)に置く**。カードの高さは所要時間で決まり、
短い手術では下の行から隠れるため、下に置くと押せないカードが生まれる。

［実装］絶対配置ではなく flex で右へ押し出す(`margin-left: auto`)。絶対配置だと
狭いカードで時刻の文字と重なる。

［実装］**この塊の pointerdown は止める**。止めないとボタンを押した指がそのまま
カードのドラッグを始め、押す前にカードが動く。
カレンダーは `overflow` の中にあるので `RowMenu` は `escapesClipping` で開く。

［提案］週ビューのチップには操作を付けない。チップはセル(日ビューへ降りる
ボタン)の中にあり、button の入れ子は不正になる。週ビューは日を選ぶための画面で、
1 件ごとの操作は日ビューへ降りてから行う。

### 2.2 週ビュー(横 = 曜日、縦 = 手術室)

日程を組むときの空き探し。格子は予約枠カレンダー(`.slot-calendar`)を借り、
セルの中身だけを手術用に組んだ。

- セルはその日その部屋の件数 + 各手術のチップ(時刻 + 主術式)。
- 重なりのある日はセルを警告色にする(週で見ても取りこぼさない)。
- セルと日付見出しのクリックでその日の日ビューへ降りる。

### 2.3 ドラッグ＆ドロップで日程を動かす

カード/チップを掴んで動かせる。

- **動かせるのは 申込済・受付済 だけ**(`isSurgeryMovable`)。入室中・実施済はもう
  起きた事実で、予定日時を後から動かすと実施記録と食い違う(訂正は実施入力の担当)。
  中止はそもそもカレンダーに出ない。掴めるカードだけカーソルが変わる。
- **日ビュー**: 縦で入室時刻(**5 分刻み**)、横の列で手術室。日付は変わらない。
- **週ビュー**: 別のセルへ落として日付と手術室。**時刻は動かさない**
  (セルは 1 日ぶんの箱で、その中のどこに落ちたかに意味が無いため)。
- **掴みしろを保つ**。カードの真ん中を持ったのに頭がポインタへ飛ぶと、掴んだ瞬間に
  予定が動いたように見える。掴んだ位置とカードの頭のずれを引いてから丸める。
- 日をまたぐ移動は作らない(0:00〜24:00 にクランプ)。§2.1 と同じ理由。
- ［事実］HTML5 の Drag and Drop は使わない(ドラッグ像を制御できず、タッチが
  ブラウザ任せになる)。Pointer Events で自前で追う(`hooks/useCardDrag.ts`。
  既存の前例は `KarteSplitter`)。**4px 未満はクリック扱い**でドラッグを始めず、
  Escape とポインタのキャンセルで中断できる。
- ［実装］週ビューのセルは押すと日ビューへ降りるので、**ドラッグ直後の click は飲む**
  (`consumeClick`)。掴んで離しただけで画面が変わるのを防ぐ。
- ［実装］pointermove / up は window で拾う。掴んだ要素の外(別の列)へ出ても追う
  必要があり、`setPointerCapture` だと移動先の列でイベントが要素に届かない。

#### ドロップで即書き込みにはしない

［提案］落とした時点では書かず、**移動の確認**(`SurgeryMoveConfirmModal`)を挟む。
日程は手術部・病棟・麻酔科が見ている予定で、手が滑ったドラッグがそのまま他部署へ
流れると取り返しが面倒になる。確認では変更前 → 後を並べ、**移動先の日を引き直して**
(キャッシュを見ない。§3-1 と同じ理由)重なりを出す。重なっていればボタンが
「重なりを承知で移動」に変わる —— 止めはしないが、承知したことは残る。

割当科の食い違いも同じモーダルに出すが、これは警告まで(§4-2)。

書き込みは `buildSurgeryMoveBundle`(occurrence と所要時間・手術室の拡張だけ差し替え、
他の拡張は保持)。**Task には触らない**。確定モーダルの「未定 → 確定」は受付済へ
進める操作だが、こちらは既に日程の入った手術を動かすだけで、手術部が受け付けた
事実は日程を動かしても変わらない。

### 2.4 読み切れなかったとき

［導出］`truncated` のときは「重なりなし」も「件数」も嘘になる。日ビュー・週ビュー
どちらでもその旨を必ず出す(`SurgeryRoomDaySchedule` と同じ扱い)。

## 3. ダブルブッキングの防止

［提案］**重なりを検知したら登録を一旦止め、「重なりを承知で登録」を明示した
ときだけ通す**。

第1段階の §5.5 では「警告まで。登録は止めない」と導出していた。緊急の割り込みや、
前の手術が早く終わる読みでわざと詰めることがあり、止めると運用が回らないため。
一方 §7-3 は「競合するオーダーをそもそも作れなくすること」を残タスクにしていた。
確認 1 回ぶんの手数で両立させる —— 意図して詰めるときは 1 クリック増えるだけ、
うっかりの二重予約はここで気づける。

### 3.1 差し込む場所

日程が書かれる経路は 2 つで、どちらにも同じ確認を入れた。

| 経路 | 画面 |
|---|---|
| 手術部の日程確定 | `SurgeryScheduleModal` |
| 診療科の申込・カルテからの日程変更 | `SurgeryOrderForm` |

手順は `useSurgeryConflictCheck` に切り出してある。

1. バリデーションを通す
2. **キャッシュを見ずに**その日の一覧を引き直す(`fetchQuery` + `staleTime: 0`)
3. 判定は `fhir/surgeryConflictHelpers` の純関数(表示・カレンダーと同じもの)
4. 重なりゼロならそのまま登録。あれば `SurgeryConflictConfirmModal` を出す

［導出］キャッシュを見てはいけない。一覧を開いた直後に確定モーダルを開くと
キャッシュがそのまま効き、「一覧を見た後に他端末が入れたぶんを拾う」というこの
確認の目的そのものが果たせない。

### 3.2 確認しないで通す場合

日付・手術室・入室時刻のどれかが未定なら取り合う相手が定まらないので、確認せず通す。
部屋未定のまま日程だけ入れる申込は普通にあり、そこで確認を出しても答えようがない。

### 3.3 確かめられなかった場合

［導出］一覧の読み込みに失敗した/読み切れなかった(`truncated`)ときは、重なりが
無いと言い切れない。**重なりゼロでも確認モーダルを出す**(「確かめられませんでした」
と伝える)。黙って通すと、確認を挟んだこと自体が嘘になる。

### 3.4 サーバー側の排他は入れない

［提案］上流 FHIR サーバーに手術専用の予約テーブルを足す話になり、Slot を使わない
判断(§1)と釣り合わない。ここで塞げるのは「一覧を見てから登録するまでの間に他の
端末が入れた」ぶんで、残るのは submit の前後数秒に同時登録が重なるケースだけ。
麻酔チャートの同時編集(`anesthesia-chart-design.md` §7-5)と同じく、運用
(手術部が日程を握る)で足りているうちは楽観のままにする。

### 3.5 window.confirm は使わない

重なっている相手を一覧で見せられないのと、ブラウザ自動化で操作が詰まるため。
`Modal` は非ポータルで、申込フォームからは外側の `<form>` の内側に描かれる。
**確認モーダルに `<form>` を置いたりボタンの `type` を省いたりすると外側の
フォームがネイティブ送信される**ので、`type="button"` を必ず付ける。

## 4. ブロックスケジュール(曜日ごとの科割り当て)

「月曜の第1手術室 9:00-12:00 は外科」という運用上の取り決め。

### 4.1 置き場所

［提案］**backend のマスタに置く**(`master_surgery_room_blocks`)。FHIR の
`Schedule` を使わないのは、予約が紐付かない純粋な施設設定で、読むのはカレンダーの
背景と申込フォームの警告だけだから。§1 で Slot を捨てた以上、Schedule だけ持っても
予約機構には繋がらない。

| 列 | 内容 |
|---|---|
| `location_id` / `location_name` | 手術室(Location 種別 `SU`)の id と名称の写し |
| `weekday` | 0=日 … 6=土(`SlotPattern`・`Date#getDay` と同じ並び) |
| `start_time` / `end_time` | "09:00" 形式 |
| `department_code` / `department_name` | SS-MIX2 統一診療科コードと名称の写し |
| `valid_from` / `valid_to` / `note` | 他マスタと同型 |

- 名称を写しで持つのは `Schedule.actor.display` と同じ考え方(Location /
  Organization が消えても行の意味が読める)。表示は今の Location 名を優先する。
- 検索用の `search_*` 列は持たない。名称で引くマスタではなく、部屋と曜日で
  全件を読んで使うため。
- **同じ部屋・同じ曜日で時間帯が重なる割り当てはモデルで弾く**。1 つの時間帯を
  2 つの科に割り当てると、警告のどちらを出せばよいか決められない。ただし
  有効期間が重ならないもの(年度で入れ替える運用)は重複と見なさない。

### 4.2 使い方は警告だけ

［提案］**割当外の科でも登録は止めない**。割当科が使わない枠を前日に他科へ回す運用が、
マスタを触らずに回るようにするため。ここを固くすると、融通のたびに割当変更か
ブロック解除の操作が要る。

- カレンダー: 日ビューは列の背景帯、週ビューはセル頭のチップ。
- 申込・日程確定: `SurgeryRoomDaySchedule` に「割当」行を出し、入れようとしている
  時間帯が別の科の割当に掛かっていれば「この時間帯は◯◯科の割当です」を出す。
- **確認モーダルの対象は時間の重なりだけ**。割当外は警告に留める(止める基準を
  2 つ持つと、どちらで止まったのか読み取れない)。

### 4.3 全件を読む

［事実］`Master::BaseController#pagination_params` は 1 ページ 100 件が上限。
手術室 × 曜日 × 時間帯は部屋が増えるとすぐ 100 を超えるので、
`fetchAllSurgeryRoomBlocks` がページを最後まで読む。「その部屋のその曜日」を
引き当てられないと警告が嘘になるため、ここだけは読み切る。

### 5.1 §5.5 の表示は残す

`SurgeryRoomDaySchedule`(日程を触る画面に、その日その部屋の予定を出す)は
カレンダーが入っても捨てない。カレンダーは別タブで、日程を入れている最中には
見えないため。第1段階の §5.5 の判断のとおり。

## 6. 申し送り

1. **多資源(執刀医・麻酔科医)の空き**: 今のカレンダーは手術室だけ。執刀医の
   重複(同じ医師が同じ時間に 2 部屋)は判定していない。`summarizeSurgeryOrder` の
   `staff` に執刀医が入っているので、判定は `surgeryConflictHelpers` に足せる。
   ［提案］運用で困ってから入れる —— 執刀医の重複は診療科の中で見えているのに対し、
   部屋の重複は誰にも見えないという非対称があって、後者から塞いだ。
2. **月ビュー**: 週より広い範囲の空き探し。7 本のクエリを 30 本に増やすことになるので、
   日付ごとの件数だけを返す上流の `$distinct-dates`(件数モード。予約枠の月カレンダーが
   使っている)に相当するものが `ServiceRequest` にも要る。
3. **ドラッグでの所要時間の変更**: カードの下端を掴んで伸縮させる(リサイズ)は
   持っていない。所要時間はカルテの編集フォームで直す。移動(§2.3)と同じ確認を
   挟む形にすれば足せる。
4. **ブロックスケジュールの一括生成**: 今は 1 行ずつ登録する。`SlotGenerateModal` と
   同じ「曜日 × 時間帯をまとめて作る」が欲しくなったら足す。
5. **祝日**: 週ビューの曜日色は土日だけ。祝日マスタを持っていないので、祝日に
   割当が出たままになる。
