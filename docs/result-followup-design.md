# 検査結果フォロー(要フォロー推奨の追跡・未確認結果の滞留一覧)の設計

`docs/functional-gap-backlog.md` §5.3「要フォロー推奨の閉ループ追跡と未確認結果の滞留一覧」(海外 EHR との照合、2026-10-18)。

**実装済み(2026-10-18)**。開発環境で §6 の検証を通した。

- **［事実］** = FHIR R4・上流・このリポジトリの実装で確認した内容
- **［設計］** = 本ドキュメントの決めごと

## 1. 背景とスコープ

画像診断レポートの「6 か月後に CT で再検」のような推奨は、依頼医が読んでも実施されずに終わることが多い。
海外では EHR で推奨を構造化し、実施されるまで追跡する(Duke 大学の追跡で完了率 43% → 71%。国内でも初回連絡時に
6 割が未対応という報告がある)。あわせて、結果が届いたまま確認されずに日数が経ったものを一覧にする。

含めるもの:

- 読影レポート・生理検査と内視鏡の所見レポートに「フォロー推奨」(内容・期限)を書く
- 確定したレポートの推奨を依頼医あての台帳(Task)に載せ、対応(オーダー済・他院へ依頼など)を記録するまで残す
- 確認されないまま一定の日数が経った検査結果の通知の一覧
- 一覧画面(診療業務 > 検査結果フォロー)とホームのカード

含めないもの(§7):

- 病理・検体検査の推奨、推奨どおりのオーダーが実施されたら自動で閉じる仕組み、期限前後の通知(ベル)

## 2. データの持ち方

### 2.1 レポートの推奨

［設計］`DiagnosticReport.extension` に `<接頭辞>-follow-up`(`rad-` / `physio-` / `endoscopy-`、`fhir/examReportHelpers.ts`)。

| 子拡張 | 型 | 内容 |
|---|---|---|
| `recommendation` | valueString | 推奨の内容(「3 か月後に胸部 CT で再検」) |
| `due` | valueDate | 期限 |

［事実］重要所見(`<接頭辞>-critical-finding`)と同じく、種別ごとに URL を分ける既存の作法に合わせた。
推奨を外すと拡張ごと消える。

### 2.2 台帳(Task)

［設計］`fhir/followUpHelpers.ts`。通知(`fhir/notificationHelpers.ts`)の Task の組み立てを使い、種別だけ新しくする。

| 要素 | 値 |
|---|---|
| `code` | `task-code|followup-recommendation`(フォロー推奨) |
| `status` | `requested`(未対応)/ `completed`(対応済み)/ `cancelled`(推奨を外した・レポートを削除した) |
| `priority` | `routine`(お知らせ) |
| `focus` | レポート(`DiagnosticReport`) |
| `for` / `owner` / `basedOn` | 患者 / オーダーの依頼医 / オーダー |
| `restriction.period.end` | 期限 |
| `input` | 種別(`rad` など)・検査日・検査内容・推奨 |
| `output` | 対応(`followup-resolution` の Coding: `ordered` オーダー済 / `referred` 他院へ依頼 / `declined` 患者が希望せず / `not-needed` 不要と判断)、対応オーダー(`ServiceRequest` の参照、任意) |
| `note` | 対応した人・日時・メモ(メモが無ければ定型文) |

- ［設計］**台帳に載せるのは確定(最終報告・訂正報告)したとき**。暫定報告は推奨が変わりうるので載せない
  (検査結果確認の通知と同じ判断)。
- ［設計］レポート保存の transaction で次のように書く(`followUpEntries`)。
  - 推奨あり・Task なし(または取り下げ済み)→ 作る
  - 推奨・期限が同じ → そのまま(対応済みなら対応の記録を残す)
  - 推奨か期限が変わった → 書き換えて未対応に戻す(前の対応の `output` と `note` は外す)
  - 推奨を外した → 未対応なら取り下げる。対応済みは残す
- ［設計］レポートを削除すると、未対応のフォロー推奨も取り下げる(検査結果確認・重要所見と同じ)。
- ［設計］**通知レジストリには登録しない**。期限は数か月先になることが多く、ベルと通知一覧に何か月も残ると、
  いま対応すべき通知が埋もれる(海外 EHR の受信箱の肥大の教訓)。追跡は一覧画面とホームのカードで行う。
  Task を器にするのは、宛先・状態・期限・対象を通知と同じ形で持てるため。
- ［事実］上流の Task 検索に期限(`restriction.period`)の検索・並べ替えは無い。未対応は全件を読んで画面で
  期限順に並べる(医師 1 人あたり数十件の想定。上限 2,000 件で欠けたらエラーにする)。上流への要望は
  `server-improvement-backlog.md` C-26。

### 2.3 未確認の結果

［設計］新しいリソースは作らず、既存の通知を「通知日から n 日以上未確認」で引く。

- 対象の種別は `result-review`(検査結果確認)・`lab-panic`(緊急異常値)・重要所見 3 種。緊急の通知が未確認の間は
  検査結果確認を作らない作りなので、両方を数えないと抜ける。
- 検索は `Task?code=<5 種>&status=requested&authored-on=lt<今日 - n + 1>&owner=…&_include=Task:subject&_sort=authored-on`。
  日付だけの値は上流が施設のタイムゾーンで解釈する。
- 行の見せ方(種別名・対象日と内容のセル・カルテへの遷移)は通知レジストリの対応表をそのまま使う。

## 3. 画面

### 3.1 レポートの入力・表示

- 入力(`components/ExamReportForm.tsx`)に区画「フォロー推奨」: 「フォロー推奨あり」のチェックと、内容・期限。
  チェックしたら両方必須。
- 内容表示(`components/ExamReportDetailPanel.tsx`)は重要所見の下に「フォロー推奨 内容 期限」の枠を出す
  (重要所見ほど急がないので枠はアクセント色)。

### 3.2 検査結果フォロー(`/result-followup`、診療業務)

既定は自分あて。「自分あてのみ」を外すと宛先の決まらないものも出る。タブは 2 つ。

- **フォロー推奨**: 状態(未対応 / 対応済)で切り替える。
  - 未対応は期限の近い順。期限を過ぎたものは「超過 n 日」(赤)、14 日以内は「あと n 日」(一段弱い色)。
  - 「カルテ」はレポートを選んだ状態の検査結果タブ、「対応」はモーダルで対応区分・対応オーダー・メモを書く。
    対応オーダーの候補は、その患者の検査(放射線・生理・内視鏡・検体・細菌・病理)と他科依頼のオーダーのうち、
    検査日以降に出したもの(推奨を書いたレポートの元のオーダーは除く)。
  - 対応済は対応の新しい順で、対応・対応オーダー・対応日・対応者を出す。「未対応に戻す」で記録の誤りを直せる。
- **未確認の結果**: 経過日数(3 / 7 / 14 / 30 日以上、既定 7 日)で絞り、通知日の古い順。確認はカルテで行う
  (一覧からは確認させない。読まずに閉じられると滞留一覧の意味が無くなるため)。

### 3.3 ホームのカード「検査結果フォロー」

自分あてのフォロー推奨の件数(期限超過・14 日以内の内訳)と、7 日以上未確認の結果の件数。医師・歯科医師の
既定のカードに加えた。

## 5. 採らなかった案

- **通知一覧(ベル)に載せる**: §2.2 のとおり、数か月残る通知で受信箱が埋まる。期限超過だけをベルに出すには
  定期実行が要るが、このシステムには定期実行の主体が無い(`documentDueHelpers.ts` と同じ制約)。
- **推奨どおりのオーダーが実施されたら自動で閉じる**: 各オーダーフォームに「どのレポートの推奨か」を選ばせる必要があり、
  16 種別のフォームに手が入る。まずは対応の記録で対応オーダーを結び付ける。
- **推奨の内容を選択肢(検査種別 × 期間)にする**: 推奨は「造影 MRI で精査」「専門医へ紹介」など幅が広く、選択肢に収まらない。

## 6. 検証(2026-10-18、開発環境・医師 一郎でログイン)

- テスト太郎 2026-09-17 の読影レポート(最終報告)に推奨「3 か月後に胸部 CT で再検」・期限を付けて保存 → 訂正報告になり、
  拡張 `rad-follow-up` と Task(`requested`、期限、宛先 児玉 義憲)ができる。内容表示に枠が出る。
- 一覧(自分あてを外す)に「超過 n 日」付きで出る。対応(オーダー済・10/15 の CT・メモ)→ 対応済に移り、対応オーダーと
  対応者が出る。「未対応に戻す」で `requested` に戻り `output` と `note` が消える。
- 推奨を外して保存 → Task が `cancelled`。もう一度付けると同じ Task が `requested` に戻る。
- 未確認の結果(7 日以上・すべて)に緊急異常値・重要所見・検査結果確認が通知日の古い順に出る。
- ホームに「検査結果フォロー」のカードが出る。
- `npx tsc -b`・`npm run lint`(新規の警告なし)・import 循環の確認。

## 7. 残課題

- 病理レポート・検体検査結果の推奨(病理は別フォーム。「再生検を推奨」など需要はある)。
- 推奨どおりのオーダーが実施されたら自動で閉じる(§5)。
- 上流に Task の期限の検索・並べ替え(`server-improvement-backlog.md` C-26)。入れば期限超過の件数を `_summary=count` で引ける。
- 対応状況の集計(推奨の件数・期限内の対応率)をデータ抽出・指標に出す。
