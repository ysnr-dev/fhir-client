# 検査レポート(読影・生理検査・内視鏡の所見)の設計

放射線の読影レポート(`docs/rad-report-design.md`)を共通の部品にして、生理検査と内視鏡の所見レポートを
同じ部品で書けるようにした。オーダー側は `docs/physio-order-design.md` / `docs/endoscopy-order-design.md`。

調査・実装日: 2026-09-27。

**実装済み(2026-09-27)**。開発環境で §7 の検証を通した。

本文中の区別:
- **［事実］** = FHIR R4 / JP Core の仕様、または上流・このリポジトリの実装で確認した内容
- **［導出］** = 仕様・事実から論理的に導ける内容
- **［提案］** = 本ドキュメントの設計提案

---

## 1. スコープ

- 生理検査・内視鏡の所見レポートの登録・編集・削除・表示(所見・診断(判定)・記載医・報告日時・画像)
- 報告区分(暫定・最終・訂正)、依頼医の既読、重要所見の通知
- 所見のテンプレート記入と、検査項目マスタの既定テンプレート
- 導線: 生理検査一覧・内視鏡一覧とカルテのカード

含めないもの(§6 の申し送り):

- 心電図・心エコーの計測値の Observation 化とチャート連携
- JAHIS 内視鏡レポート構造化記述規約に沿った構造化、JED 診断処置用語の選択肢化、JED 提出
- 装置が出力する PDF(心電図波形・エコーレポート)の添付
- 帳票、所見入力ワークリスト

---

## 2. 共通化の方針

［事実］読影レポートは「所見 1 件(自由文)+ 診断(`conclusion`)+ 画像(`Binary` + 拡張)+ テンプレート記入 +
重要所見」の形で、生理検査・内視鏡の所見もこの形にそのまま収まる。病理(JAHIS のセクション LOINC)や
検体検査(項目 × 値)のように種別固有の構造を持たない。

［提案］読影レポートのコードを種別の設定(`ExamReportConfig`)を引数に取る形に移し、3 種で共用する。
写して 3 つにしない。［事実］生理検査と内視鏡はオーダー・実施入力が既に写しで 2 重になっており
(`docs/endoscopy-order-design.md` §8-6)、レポートまで写すと 3 重の写しが 2 系統できる。

［実装］放射線の保存形式は変えていない。載せ替えの前後で、同じフォーム値から組み立てた Bundle・読み戻した
フォーム値・削除の entry・重要所見の Task が一致することを、旧実装と並べて確かめた(§7-1)。

### 2.1 種別ごとの設定(`fhir/examReportHelpers.ts` の `EXAM_REPORT_CONFIGS`)

| | 放射線 | 生理検査 | 内視鏡 |
|---|---|---|---|
| 種別の判定(`category` 1 つ目) | LOINC `LP29684-5` | `order-type` `physio` | `order-type` `endoscopy` |
| v2-0074(`category` 2 つ目) | `RAD` | `OTH` | `OTH` |
| `code` | JP_DocumentCodes `18748-4` | `exam-report` `physio`(施設コード) | LOINC `18751-8` Endoscopy study |
| 所見 Observation の category | `imaging` | `procedure` | `procedure` |
| 拡張・所見コードの接頭辞 | `rad-` | `physio-` | `endoscopy-` |
| 見出し | 読影レポート / 読影医 / 診断 | 所見レポート / 記載医 / **判定** | 所見レポート / 記載医 / 診断 |
| 描き込みの色 | 黄・赤・水色・白 | 既定(黒・赤・青・緑) | 黄・赤・水色・白 |
| 重要所見の `Task.code` | `rad-critical-finding` | `physio-critical-finding` | `endoscopy-critical-finding` |
| カルテの詳細 | `rad-result` | `physio-result` | `endoscopy-result` |

設計判断:

- **種別の判定にオーダー種別の coding を使う**。［事実］実施記録の `Procedure.category` が既に
  `order-type|physio` / `order-type|endoscopy` を持つ。［導出］同じ coding をレポートにも置けば、
  `DiagnosticReport?category=` で種別ごとに引け、新しいコード体系を作らずに済む。放射線は JP Core の
  Radiology プロファイルに合わせた LOINC を既に判定に使っているので、そのまま残す。
- **v2-0074 は `OTH`**。［事実］結果タブ(`useResultSummariesQuery`)は `LAB` / `MB` / `SP,CP` を指定して
  検索する。［導出］それ以外の値なら混ざらない。v2-0074 には心電図(`EC`)・肺機能(`PF`)などもあるが、
  生理検査の種別は 8 つ(心電図・超音波・呼吸機能・脳波…)に分かれ、超音波には対応する値が無い。
  種別ごとに変えるより 1 つに固定する方が読み手が迷わない。
- **内視鏡の `code` は LOINC `18751-8`**。［事実］tx.fhir.org で ACTIVE・"Endoscopy study" を確認した。
  生理検査は心電図(`11524-6`)・心エコー・呼吸機能と文書コードがばらばらで、1 つに決められないため
  施設コードにした。検査内容は `code.text`(オーダーの GP の見出しを「・」で連結)に入る。
- **拡張の URL は種別ごとに分ける**(`physio-report-image` など)。［導出］子拡張の意味は放射線と同じだが、
  URL に種別が入っていれば、拡張だけ見てどの種別のレポートか分かる。放射線の URL は既存データがあるので変えない。
- **重要所見の `Task.code` も種別ごとに分ける**。［導出］通知一覧の種別フィルタで「重要所見(内視鏡)」のように
  分けて絞れる。放射線の `Task.code.display` は既存の「重要所見」のまま、一覧の表示だけ「重要所見(放射線)」にした。
  `Task.input` の見出しは放射線が「撮影日 / 撮影内容」、生理・内視鏡が「検査日 / 検査内容」。

## 3. 画面

読影レポートの画面(`docs/rad-report-design.md` §4)と同じ。違いだけ書く。

- **部品**: `ExamReportEntryModal`(入力)・`ExamReportForm`・`ExamReportDetailPanel`(表示)・
  `ReportImagesEditor`(画像欄)。どれも `config` を受ける。入力モーダルは種別ごとの差し込み口
  (`ADAPTERS`)で、オーダー・実施記録の取得、依頼内容の表示、実施情報の行、既定テンプレートの引き方を切り替える。
- **実施情報の行**: 放射線は造影剤・被曝線量。生理検査は実施者・手技・薬剤。内視鏡は実施者・手技・薬剤
  (前処置・鎮静の薬剤と生検などの追加手技を、所見と突き合わせるため)。
- **部門一覧**: 生理検査一覧・内視鏡一覧に「所見」列と、実施済の行に「所見 / 所見編集」ボタン。
  ［事実］両一覧の検索は `_revinclude` を `params.set` で 1 本だけ付けていた。［実装］`append` に直して
  `DiagnosticReport:based-on` を足した(set のままだと Task の取得が上書きされ、全行が依頼済に戻る)。
- **カルテ**: 生理検査・内視鏡カードにバッジ(「所見:暫定報告」「所見:訂正報告」)、メニューに
  「所見レポート表示」「所見レポート登録 / 編集」、FHIR JSON に「所見レポート」の節。

### 3.1 カルテのタブ(2026-09-27 追加)

「検査結果」配下に「放射線検査」「生理検査」「内視鏡」のタブ(`rad-report` / `physio-report` / `endoscopy-report`、
`KarteExamReportTab`)。病理検査タブと同じく、左の日付ペイン(`SpecimenDateList`、見出しは「撮影日」「検査日」)に
レポートを新しい順で並べ、選ぶと右に `ExamReportDetailPanel` を出す。表示対象は URL の `view`。

- 日付ペインの検索は検体検査・細菌・病理と同じ `useResultSummariesQuery` に、種別の category の token
  (`examReportCategorySearch`)を渡す。［実装］「編集」でオーダーを引くため、要約の `_elements` に `basedOn` を足した
  (検体検査・細菌・病理の要約にも入るが、使っていないので影響は無い)。
- 操作は確認(既読)と「編集」(部門一覧と同じ入力モーダル)。［提案］新規登録は置かない。レポートは実施済みの
  オーダーに 1 件ずつ付くもので、どのオーダーかは部門一覧・カードの側で決まる。
- 検査結果確認・重要所見の通知の「カルテ」は、詳細モーダルではなくこのタブを、そのレポートを選んだ状態で開く
  (検体検査・細菌・病理と同じ開き方にそろえた)。カードのメニューの「レポート表示」は従来どおり詳細モーダル。

## 4. 既存の操作との整合

`docs/rad-report-design.md` §8 と同じ規則を生理検査・内視鏡にも当てた。

- **実施の取消は、所見レポートがあると止める**(`assertNoExamReportForCancel`)。一覧の「取消」も無効にする。
- **オーダーの削除も止める**(`examReportDeleteGuard`)。カードの「削除」を無効にする。
- **レポートの削除**は所見・テンプレート回答を消し、未確認の通知(検査結果確認・重要所見)を取り下げる。
  画像の `Binary` は消さない。

## 5. テンプレート

`docs/report-mappings/exam-report-templates.md`。検査項目マスタに `report_findings_template_canonical` を足し
(migration `20260927100000`)、マスタ画面の「既定のテンプレート」に「所見」を足した。

- 心電図 `PHY_ECG_RPT_01`: 調律・心拍数・電気軸・各間隔・異常所見
- 上部内視鏡 `END_EGD_RPT_01` / 大腸内視鏡 `END_CS_RPT_01`: 検査時情報(JED 基本情報の統一表記)・部位別所見
  (自由文)・生検・偶発症(JED 基本情報)

［事実］JED の診断処置用語集は手元に無い(リポジトリにあるのは基本情報編だけ)。［提案］所見の質的診断を
選択肢にするのは、施設が診断処置用語集を取り寄せてからテンプレートを改版する(§6-2)。

## 6. 申し送り

1. **計測値の構造化**(心電図の各間隔・心エコーの EF など)。いまはテンプレートの回答(QuestionnaireResponse)と
   平文にしかならない。経過表・チャートに出したくなったら、回答から Observation を作る(SDC の抽出)か、
   所見レポートの `result` に計測値の Observation を**追加**する。どちらも今の形から足すだけで移れる。
2. **JED 診断処置用語・JAHIS 内視鏡レポート規約**(`docs/endoscopy-order-design.md` §8-1)。部位 × 所見 × 診断の
   構造化は Observation を部位ごとに分ける形になり、JED 提出データの生成もそこから作る。
3. **ERCP・小腸・気管支鏡のテンプレート**。今回は EGD と CS だけ。
4. **装置の PDF**(心電計・エコー装置のレポート)。`presentedForm` か DocumentReference の関連付けかは、
   装置連携の形が決まってから判断する(`docs/rad-report-design.md` §9-2 と同じ課題)。
5. **オーダー部分の共通化**(`docs/endoscopy-order-design.md` §8-6)。今回はレポート層だけを共通にした。

## 7. 検証(2026-09-27、開発環境)

1. **放射線の回帰**: 旧 `radReportHelpers.ts` と新 `examReportHelpers.ts` を Vite の SSR で読み、同じフォーム値
   (保存済み・新規の画像、テンプレート参照、重要所見、編集で外れる Observation・回答)から組み立てた Bundle・
   読み戻したフォーム値・削除 entry・重要所見の Task が一致した。画面ではテスト太郎の 08-12 の読影レポート
   (訂正報告・画像 4 枚)の表示と、放射線検査一覧の「訂正報告 / 読影編集」が従来どおり出ることを確かめた。
2. **内視鏡(テスト太郎 08-24 の EGD、医師 一郎でログイン)**: 一覧の「所見」→ 画像 2 枚(1 枚に黄の矢印)・
   重要所見ありで暫定保存 → 一覧が「暫定報告 / 所見編集」、ステータスは実施済のまま → 上流に
   category(`endoscopy` / `OTH` / 入院)・LOINC 18751-8・記載医・発行施設・検査日時(実施記録から)・
   画像拡張 2 つ(1 つ目は source + annotated)・所見 Observation(`procedure`)・重要所見の Task
   (アラート・依頼医あて・検査日 / 検査内容 / 要点)が入った。暫定なので検査結果確認は無し。
   通知一覧の「重要所見(内視鏡)」→「カルテ」で詳細モーダル(`endoscopy-result`)が開いた。カードに
   バッジ・メニュー・削除の無効化・FHIR JSON の節。カルテから最終報告に更新 → 重要所見が未確認なので
   検査結果確認は作られない → 通知一覧で確認 → 既読の来歴 → 一覧から編集すると「訂正報告として更新」→
   `amended` と検査結果確認(種別 endoscopy)。実施の「取消」が無効。
3. **テンプレート**: EGD の既定(`END_EGD_RPT_01`)が所見の「テンプレート」で最初から開き、記入して反映すると
   平文が所見欄に入って直接編集不可になる。保存で回答(QuestionnaireResponse)がレポートの拡張から参照された。
4. **生理検査(テスト次郎 08-23 の心電図)**: 入力欄の見出しが「判定」、空のまま・判定なしの最終報告は
   それぞれ保存させない。最終報告で保存すると検査結果確認(種別 physio)が作られ、レポートを削除すると
   410 になって検査結果確認が取り下げられた。
5. 型チェックは `tsc -b`(コンテナ内)、oxlint は変更ファイルに警告なし。backend の rspec
   (physio / endoscopy / rad の items spec、81 examples)は `RAILS_ENV=test ADMIN_TOKEN=` で通過。

開発環境には、テスト太郎の 08-24 の内視鏡オーダーに訂正報告の所見レポート(画像 2 枚・テンプレート記入・
重要所見確認済み・検査結果確認が未確認)が残っている。
