# 機能一覧(functional.xlsx)との照合 — 取り込み候補

`backend/tmp/functional.xlsx`(498 機能、機能名称 / 機能概要 / 機能詳細の 3 列。大規模病院向け商用電子カルテの機能一覧)を
本リポジトリの実装(readme.md・docs/*-design.md・frontend/src・backend)と突き合わせ、取り込めそうな機能を
**既存機能の拡張**と**新規機能**に分けて整理したもの(2026-10-08)。

凡例:

- **［対応物］** = 本リポジトリに既にある土台
- **［不足］** = xlsx の機能詳細にあって本リポジトリに無い要素
- **［当たり］** = 実装の置き場所の目安(FHIR リソース・既存部品)
- **既載** = 既存の backlog / design に同じ課題が書いてある
- 必要度 **高 / 中 / 低** は、日本の病院(急性期〜ケアミックス)の電子カルテとしての必要度

## 0. 結論の要約

- 498 機能のうち、**オーダー 16 種別・部門ワークリスト・カルテ・看護(指示簿・計画・サマリ・プロファイル)・パス・
  化学療法・予約枠・病棟マップ・データ抽出・レセコン連携・マスタ群**は骨格が揃っており、機能名単位では
  過半が「既にある」か「拡張候補」に入る。
- 無いものは次の塊に集中する。
  1. **制度・ガイドライン要件**: 職種別アクセス権限、制限患者(VIP)、閲覧ログ、自動ログオフ・パスワードポリシー、
     修正・削除の理由、診療記録の一括出力(開示・監査)
  2. **患者誤認・投与事故の防止**: 顔写真、同姓同名警告、死亡患者のオーダー抑止、外泊中・退院後のオーダー検知、
     食物アレルギーと食事オーダーの照合、輸血の払出記録と突合・2 名確認、リストバンド + 患者認証
  3. **まるごと無い部門・業務**: 透析(血液浄化)、地域連携(紹介の台帳と返書管理)、チーム医療(NST / ICT / 褥瘡)、
     看護必要度、管理日誌、麻酔科術前診察、栄養管理計画書、DPC コーディング
  4. **入院運用の横断画面**: ベッドスケジュール(病床ガント)、病床稼働の集計、入退院文書の作成状況一覧、
     看護師の「患者の 1 日」ワークシート、業務分担(勤務帯の受け持ち)
  5. **帳票**: 予約票、麻薬施用票、持参薬鑑定書、カルテ控え印刷、病棟 × 日の一覧印刷、退院サマリー PDF
  6. **入力効率**: 文例・定型文、科別頻用病名、患者別セット、処方の RP 単位の中止・再開、入院処置の継続指示、
     祝日マスタ、予約の連続取得・仮予約
- xlsx 側で**対象外**にしたもの: IC カード・静脈・指紋認証、カードリーダ、スクリーンセーバ常駐、外部 EXE、
  Windows クライアント配布(マスタアップロード・端末マスタ・プリンタマスタ・ランチャー・SE ツール)、
  ベンダー製品連携(DICS-PS・Simplewrite・ARENA・HumanBridge・麻酔器・勤務割)、排他ロック(楽観ロックで代替)、
  保険情報の保持(レセコン正本)、IME 辞書、Excel チャート、移行ツール。

## 2. 分野別の候補

### 2.1 認証・権限・監査(ガイドライン要件)

- **職種別アクセス権限**(新規、高)
  - ［対応物］ホームの職種分岐(`homeSections.ts`)、画面側の「医師か」判定(オーダーセット・チャート定義)。backend は職種を知らない。
  - ［不足］職種ごとの文書種別(書込・閲覧)・画面・一覧・プロファイルへの既定権限と、利用者ごとの上書き。
    師長などの役職権限(看護サマリー承認の readme が「未実装」と明記)。
  - ［当たり］backend に role × 機能のマトリクス、`/auth/me` で返して `useCanXxx` に集約、`/master`・`/reports` の書込で検証。
- **制限患者(VIP・職員患者)**(新規、高)
  - ［不足］患者ごとに閲覧できる利用者を限定、閲覧時の再認証・警告、閲覧の記録。院外利用者(連携先・治験モニター)の閲覧範囲。
  - ［当たり］`Flag(category: security)` か backend `patient_access_restrictions`、`KartePage` 入口と FhirGateway で判定。
- **アクセスログ参照**(新規、高)
  - ［対応物］上流 `AuditEvent` は OAuth クライアント単位のみ(`server-improvement-backlog.md` 既載)。
  - ［当たり］backend の `/fhir` プロキシで患者に関わる読み取りを `access_logs`(user, patient, resource, at)に記録し、管理画面に利用者別・患者別の一覧。上流を直さず済む。
- **ログインポリシー・自動ログオフ**(拡張、高)
  - ［対応物］`User`(has_secure_password、8 文字以上)、セッション 12 時間固定。
  - ［不足］文字種条件・誤入力ロック・有効期限・本人によるパスワード変更、無操作時の画面ロック(外来 / 病棟で時間を分ける)、前回ログイン日時。
  - ［当たり］`users` に failed_attempts / locked_at / password_changed_at、施設設定にポリシー、frontend にアイドルタイマー + ロック画面。
- **修正・削除の理由**(拡張、中〜高)
  - ［対応物］`_history`、Provenance(登録・編集)。削除・中止は理由を持たない(`order-common-backlog.md` §2 障壁 4)。
  - ［不足］文書種別・科ごとに修正・削除時の理由選択を求める、理由の定型文マスタ、警告を無視した理由(共通チェック (37))の記録。
  - ［当たり］`Provenance.reason` / `activity=DELETE`、理由候補は backend の小マスタ。
- **承認要否の設定**(拡張、中): 研修区分・科・項目(麻薬・抗がん剤)ごとに事前 / 事後承認を設定。
  「承認前でも部門へ流す」方針と衝突するので事前承認は要検討。
- **権限の委譲**(拡張、中): 不在時に期間を切って他医師へ承認を委譲(`approval_delegations`、`useCanApproveOrder` に加味)。

### 2.2 診療記録の出力・文書管理

- **診療記録出力(患者 × 期間の一括 PDF)**(新規、高)
  - ［対応物］帳票はオーダー単位・回答単位のみ。`flowsheet-design.md` 末尾に「患者 × 期間のエンドポイントが無い」と既載。`window.print` / `@media print` も無い。
  - ［不足］表紙(入退院歴)・1 号用紙(カルテ 1 号用紙: 患者・保険・病名・労災)・病名 / プロブレムリスト・退院サマリー・プロファイル・診療経過記録(シェーマ・埋め込み文書を含む)・看護計画・経過表・看護プロファイル・レポート・検歴・指示簿を 1 つの PDF に束ねる。複数患者の一括出力。
  - ［当たり］`GET /reports/patients/:id/records.pdf?from&to&sections=`。長文は ThinReports に向かないので HTML → PDF(Gemfile 変更 = 再ビルド)か frontend の印刷用ビュー + `window.print`。まず「診療経過記録 + 病名 + プロブレム + 退院サマリー」から。保険情報はレセコン(`patientgetv2`)から。
- **カルテ控え・オーダー控え・指示歴の印刷**(拡張、高): 上と同じ基盤。タイムラインの印刷用 CSS が最小。
- **病棟 × 日の一覧印刷**(拡張、中): 入院患者一覧・病棟マップ・移動予定・指示簿・注射実施シート・検歴。エンドポイントを 1 種類作れば横展開できる。
- **同意書の状態管理と文書の横断一覧(文書受取管理)**(拡張、高)
  - ［対応物］文書テンプレート(docx / xlsx)、ファイルタブ。手術・輸血の「同意書確認」はチェックボックスのみ。
  - ［不足］文書の状態(作成 → 印刷 → 同意済 → 原本保管 / 受取済)、スキャン原本との結び付け、横断一覧、過去文書を見ながらの作成、印刷部数。
  - ［当たり］`DocumentReference.docStatus` + 拡張(同意日・保管日)、`/document-worklist`、手術・輸血の確認欄を文書参照に置換。
- **入退院文書の作成状況一覧**(新規、高)
  - ［対応物］退院時サマリーの督促 Task だけ。
  - ［不足］入院診療計画書(7 日以内)・退院時サマリー・退院療養計画書・看護サマリーなどの作成状況を病棟・科・担当医で横断、対象文書は施設設定、一覧から作成。
  - ［当たり］入院 × 文書種別(`Composition.type` / `QuestionnaireResponse.questionnaire` + `encounter`)の突き合わせ。入院実施の transaction に計画書の下書きを 1 件積む。
- **退院サマリーの横断一覧と PDF、科別レイアウト**(拡張、高): `Composition?type=18842-5&ward=&status=` + 退院 Encounter で未作成を出す。PDF は `discharge-summary-design.md` §6 既載。前回サマリー複写、DPC 様式 1 の病名取込。
- **文書参照(説明書・パンフレットのライブラリ)**(拡張、中): `document_templates.kind = reference`、右ペインから「印刷のみ」。
- **移行カルテ**(新規、中・導入時のみ): `Composition`(category legacy)+ 取込バッチ(demo-seed と同じ Node 経路)。

### 2.3 患者誤認・オーダー安全(横断チェック)

- **顔写真**(新規、高): `Patient.photo` に `Binary`、患者編集に写真欄、`PatientHeader` にサムネイル。ファイル取込の `Binary` 経路を流用。
- **同姓同名警告・死亡患者のオーダー抑止・二重登録患者**(拡張、高)
  - ［対応物］患者帯の死亡表示(赤)。readme が死亡患者のオーダー抑止を「未実装」と明記。`Patient.link` 未使用。
  - ［当たり］カルテを開いたとき `Patient?name=<カナ>` を 1 本引いて件数 > 1 なら帯に警告、死亡は右ペインの登録ボタンで止める。二重登録は `Patient.link(replaced-by)` + `/karte-pane/:patientId` を並べる。
- **患者状態チェック(種別非依存)**(拡張、高)
  - ［対応物］薬剤安全性チェック(`medicationSafetyHelpers`、アレルギー・重複・相互作用・用量・年齢・腎機能)、`PregnancyNotice`。
  - ［不足］外泊中・退院済の患者への入院オーダー警告、退院時に適用中パスの未評価警告(`clinical-pathway-backlog.md` A-6)、伝票・配膳の締切超過、オーダー発行可能時間、診療科限定薬・利用者限定薬、麻薬施用者免許のチェック、感染症との照合。
  - ［当たり］純関数の器に「患者状態チェック」を 1 本足し、全フォームの登録前に通す。
- **退院後オーダーの検索と一括中止**(拡張、高)
  - ［対応物］退院モーダルは食事・リハ・指導・看護指示・持参薬だけを終了する。
  - ［不足］注射の連日展開・入院処方・検査予約・処置など退院日より後に実施予定日を持つオーダーの一覧と選択中止、入外変更、死亡退院時の自動起動。
  - ［当たり］`ServiceRequest?patient=&occurrence=gt{退院日}&status=active` を退院モーダルに並べ、`revoked`。
- **食物アレルギー × 食事オーダーの照合**(拡張、高): `MealOrderForm` に `useAllergies` で食物アレルギーを表示し、食種・コメントと突き合わせ。`AllergyIntolerance(category=food)` 更新時に進行中の食事オーダーへ警告。
- **感染症の表示**(拡張、高): 放射線・生理・内視鏡フォームと手術一覧・カレンダーの行(清掃順の判断)。`PregnancyNotice` と同じ位置に `InfectionNotice`、行の背景色。`rad-backlog.md` B-4 既載。
- **患者認証(バーコード実施)とリストバンド印刷**(拡張、高)
  - ［対応物］注射ラベル・検体ラベルのバーコード、検体到着のスキャン欄。
  - ［不足］リストバンドと注射 / 輸血製剤のバーコードを読んで照合してから実施入力へ、認証スキップ理由、ミキシング記録。リストバンド・バーコード台紙の帳票。
  - ［当たり］実施入力モーダルの前段に「照合」ステップ、`.tlf` を 2 本。
- **ロット番号のバーコード入力**(拡張、中): GS1-128(AI 10 / 17)を解析してロット・有効期限に分配。

### 2.4 輸血・病理・検査部門

- **輸血の払出記録と突合**(拡張、高)
  - ［対応物］受付 → 出庫 → 実施の Task、オーダーの血液型食い違い警告、実施の製剤番号・副作用。出庫は「何を出したか」を記録しない。
  - ［不足］払出時に製剤種・製剤番号・有効期限・照射済・適合者(クロスマッチ実施者)と日時を記録、依頼と払出の突合、交差試験未確認なら払出不可、製剤の返却、実施時に払出済みから選ぶ。
  - ［当たり］出庫時に製剤ごとの `MedicationDispense`(identifier = 製剤番号、拡張に有効期限・照射・適合者)を Task と同 transaction で書く。注射の払出と同じ器。
- **輸血実施の確認者 2 名・実施量・副作用の定型化・製剤番号の逆引き**(拡張、高)
  - ［当たり］`Procedure.performer` に `function`(実施者 / 確認者)で 2 人、`MedicationAdministration.dosage.dose`、副作用は学会分類を `valueCodeableConcept` に。輸血の MA に `lot-number` 拡張を書いて `LotManagementPage` の対象に(遡及調査、保存 20 年)。
- **自己血採血**(新規、中): 輸血オーダーの検査区分に `autologous-collection`、採血 `Procedure`(採血量)、採取製剤を `MedicationDispense` で台帳化して払出候補に。ラベルは検体ラベルの `.tlf` 流用。
- **不規則抗体陽性の警告・T&S 選択時の血液型検査の自動併発**(拡張、中): `transfusion-order-design.md` §7 既載。
- **病理の標本番号採番と標本ラベル**(拡張、高): 検体検査と同じ上流 `Specimen` 台帳 + `accessionIdentifier`、ラベル(枚数・枝番・染色名)の `.tlf` 1 枚。`patho-order-design.md` §8-1 既載。

- **食事**(拡張、高): 栄養量の表示、食物アレルギー照合(§2.3)、配膳締切時刻(2 段階・休日)のチェック、パターン食の一括入力、セット食、年齢別・科別の既定食種、濃厚流動・ミルクの種別、経管栄養・間食(§7-3 / 7-8 既載)、給食部門ワークリスト・食数集計(§7-1 既載)、転室時の配膳開始日時。
- **入院申込**(拡張、中): 推定入院期間・治療計画・感染症をベッドコントロール向けに、確定時の指導・テンプレートの連携起動、副担当看護師、科単位の既定食事。
- **予約**(拡張、中): 仮予約・仮押え(`Appointment.status = proposed`)、複数日の連続取得(曜日・間隔・回数、リハ・透析・化学療法)、予約枠グループの同時参照、予約コメント、日未定予約の後からの確定、予約複写。
- **化学療法**(拡張、高): 当日実施確認(医師の Go / No-go を日オーダーのヘッダへの Provenance(verifier)で記録、化学療法室一覧に「実施可」列)、途中日からの適用・休日除外(`chemo-regimen-design.md` D-2 / D-7 既載)、外来治療ベッド・椅子の割付と入出床。

### 2.11 マスタ・入力効率・基盤

- **祝日・休診日マスタと伝票締切**(新規、中〜高): `facility_holidays`(内閣府 CSV 取込)、`lib/dates` に営業日関数。パス・レジメン・放射線治療・手術カレンダー・予約枠生成・督促期限・クロス採血日で共用。締切(処方・注射・検査・食事)は施設設定。

- **ヒストリカルビュー**(新規、中): 5〜15 年の記録量分布に主病名・入院・パスの期間を重ね、選んだ期間をタイムラインへ。`$distinct-dates` の件数拡張、Condition / Encounter / CarePlan の period を帯に。
- **テンプレートビューア(回答の日付 × 項目の表)**(拡張、中): `QuestionnaireResponse?questionnaire=` を `linkId` 行 × `authored` 列の表に、しきい値の色、Excel 出力。
- **カルテ本文のキーワード検索**(拡張、中): 上流の `_content` / `_text` 対応を確認(無ければ `server-improvement-backlog.md`)。

- その他: スクリーンセーバの常駐監視(無操作ロックは §2.1 で Web 的に実現)、外部 EXE 起動、HTML ブラウザの別起動、ハードコピー監査(ブラウザ外キャプチャは止められない)、二重患者参照の旧運用、ダミー患者方式のパス患者選択、利用者単語登録(IME)、和暦表示(`lib/dates` にあり低優先)
