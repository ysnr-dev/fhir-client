# チャート(数値の推移 + 治療イベント)の設計

任意の数値項目の推移を縦に積み、**同じ横軸**に手術・入退院・化学療法・放射線治療・
検査/注射の実施を重ねて読む画面。カルテ画面の「診療情報」▸「マルチチャート」タブに出す
(1 枚に複数の項目を並べる・重ねるのがこの画面の値打ちなので「マルチ」を冠する。
`KARTE_TABS` のキーと URL の `tab=chart` はそのまま)。

読みたいのは「この治療の後に値がどう動いたか」なので、値とイベントの**縦の位置が
そろっている**ことがこの画面の要になる。検体検査の時系列表(`LabResultTimelinePanel`)が
「直近 N 回の採取日を等間隔で並べる」のに対し、チャートは**時間に比例した横軸**を
全レーンで共有する。

実装: `frontend/src/components/KarteChartTab.tsx`(タブ・取得)、
`components/PatientChartPanel.tsx`(描画)、
`components/ChartDefinitionEditorModal.tsx`(定義の編集)、
`fhir/chartDefinitionHelpers.ts`(定義の型・横軸・系列とイベントへの変換)、
`fhir/chartStateHelpers.ts`(帯の行を時刻で引く「状態」。§6.1 / §8)、
`components/ChartStratifyModal.tsx` / `components/ChartScatterModal.tsx`(相関を読む道具。§8)、
`lib/stats.ts`(中央値・Spearman)、
backend は `app/models/chart_definition.rb` と `app/controllers/master/chart_definitions_controller.rb`。

## 1. 保存するのは「定義」だけ。患者は持たない

チャートは「どの項目を並べ、どのイベントを重ね、横軸をどの粒度で見るか」を保存する。
**患者は持たない**ので、同じ定義をどの患者に当ててもそのまま開ける
(「化学療法中に見る血算のセット」を作れば、次の患者でも選ぶだけで済む)。

テーブルは backend の `chart_definitions`。オーダーそのものではない雛形なので上流 FHIR には
置かない(オーダーセットと同じ考え。`docs/order-set-design.md` §1.2)。

`definition` は jsonb で形は次のとおり。

    { "schema_version": 1,
      "axis": { "unit": "month", "columns": 12 },
      "items": [
        { "key": "lab:160008010-01", "source": "lab", "name": "WBC", "unit": "X10*3/μL",
          "codings": [{ "system": ".../lab-result-item", "code": "160008010-01", "display": "白血球数" },
                      { "system": ".../jlac11", "code": "..." }] },
        { "key": "vital:85354-9", "source": "vital", "name": "血圧", "unit": "mmHg",
          "codings": [{ "system": "http://loinc.org", "code": "85354-9" }],
          "components": [{ "code": "8480-6", "name": "収縮期" },
                         { "code": "8462-4", "name": "拡張期" }] },
        { "key": "template:<Questionnaire.id>:<linkId>", "source": "template", "name": "通算喫煙年数",
          "unit": "年", "codings": [{ "system": ".../JP_ObservationSocialHistoryCode_CS", "code": "MD0012910" }] },
        { "key": "lab:160046810", "source": "lab", "name": "HBs抗原", "unit": "", "scale": "nominal",
          "codings": [...], "options": [{ "system": ".../JP_PosNegHold_CS", "code": "1", "display": "陽性" },
                                        { "system": ".../JP_PosNegHold_CS", "code": "2", "display": "陰性" }] } ],
      "events": ["encounter", "surgery", "chemo", "radiotherapy", "adverse", "exam", "injection"],
      "drugs": [
        { "key": "yj7:3332001", "name": "ワーファリン錠", "yj7": "3332001", "codes": ["613330003"] } ],
      "overlay": false,
      "background": { "kind": "item", "key": "template:<Questionnaire.id>:<linkId>" } }

`codings` の中身(どのコード体系のどのコードか)は **backend が解釈しない**。
画面が `Observation.code` と突き合わせるためにそのまま持つだけ
(`OrderSetEntry.values` と同じ流儀)。形の検証は `ChartDefinition#definition_shape` が担う。
`background`(§6.1)も同じで、backend は形だけを見る。指す先(項目・薬剤・種別)が定義から
消えていれば画面側(`normalizeChartDefinitionBody`)が落とす。

### 項目の選び方は 3 つ

| source | 選択元 | codings |
|---|---|---|
| `lab` | 検査結果項目マスタ(数値型 `PQ`) | 施設の結果項目コード + JLAC11 |
| `lab`(選択肢) | 同じマスタのコード型 `CD` / `CO`(`code_value_list` を持つもの) | 同上 + `options`(`code_value_list` の並び、system は `value_code_system`) |
| `vital` | 固定の一覧(`VITAL_MEASURES` + 血圧 + BMI) | LOINC |
| `template` | テンプレート(`observationExtract` 有効)の integer / decimal 項目 | `Questionnaire.item.code` |
| `template`(選択肢) | 同じテンプレートの choice 項目(項目コードと選択肢を持つもの) | `Questionnaire.item.code` + `options` |

選択肢の項目は `scale` で尺度を持てる。省略は順序尺度(並び順 = 程度)。`CO`(大小順序のある
コード型)はそのまま、`CD`(順序のないコード型: 陽性/陰性・血液型)は `nominal` にして
濃さを付けない(§5.1)。

マスタ・定義から選ぶので、**その患者に値が無くても項目に足せる**(足してから値が付く
使い方ができる。値の無い期間は「この期間に値がありません」と出す)。

## 1.5 疾患別の初期値(院内共通)

`db/seed_data/chart_definition_presets.json` に疾患別の定義を持ち、`db:seed` で院内共通として入れる
(`ChartDefinitionPresets`)。糖尿病・慢性腎臓病・心不全・関節リウマチ・甲状腺・ワルファリン・
がん化学療法の 7 件。

- JSON は項目を**コードだけ**で持つ(検査は結果項目コード、バイタルは LOINC、薬剤は YJ 先頭 7 桁)。
  名称・単位・coding は投入時にマスタから引き、画面が作るのと同じ形にそろえる
  (`labChartItem` / `vitalChartItems` / `chartDrugOf`)。結果項目コードは同梱の検体検査マスタが
  レセ電算コードで採番しているので、施設が変わっても同じコードで引ける。
- マスタに無い・数値でない検査項目は落とし、落とした項目は seed の出力に出す。項目も薬剤も
  残らない定義は作らない。eGFR(計算値)、HIV のウイルス量・CD4 はマスタに無いので入れていない。
- 薬剤の `codes` には、その成分・投与経路の薬剤のレセ電コードを薬価基準コードから集めて入れる
  (YJ コードを持たない処方も拾うため)。
- 同じ名前の院内共通の定義があれば上書きしない(施設で直した内容を戻さない)。
- 本番は起動時に `db:prepare` を流すだけで、既存の DB では seed が走らないので、同じ処理を
  migration(`20260924120000_seed_chart_definition_presets`)からも呼んで入れる。プリセットを
  足したときは、新しい migration から `ChartDefinitionPresets.load!` を呼び直す(既存は上書きしない)。

## 1.6 患者ごとに最初に開くチャート(ピン留め)

ツールバーのピンで、その患者を開いたときに最初に出すチャートを決める。**患者につき 1 つ**で、
**利用者の間で共有**する(糖尿病の患者は誰が開いても「糖尿病」から始まる)。別のチャートで
ピンを押すと置き換わり、固定中のチャートで押すと外れる。選択欄では固定中のチャートに「(固定)」を付ける。

- backend の `patient_chart_pins`(patient_id 一意、chart_definition_id、固定した人)。
  `GET/PUT/DELETE /master/patient_chart_pins/:patient_id`。ピンが無いときも 200 で
  `chart_definition_id: null` を返す(無いのが普通の状態なので 404 にしない)。
- 初期表示の順は、URL の `view` で指定したチャート → ピン → 自分・診療科・院内共通の先頭。
  個人用のチャートをピン留めした場合、本人以外には見えないので、その人には従来の順で開く。
- ピンを引き終わるまでチャートを開かない(別のチャートを開いてから切り替わらないように)。
- チャート定義を消すと、それを指すピンも外れる(`ChartDefinition has_many :patient_chart_pins, dependent: :delete_all`)。

## 2. 持ち主は 3 段階

オーダーセットと同じ `scope` / `owner_id`(院内共通 / 診療科 / 医師)。
医師かどうかは上流の `PractitionerRole` にしか無く backend からは引けないので、
院内共通・診療科の書き込みは画面側で医師に限り、backend が厳密に守るのは
「医師スコープの持ち主はログイン本人」だけ(`docs/order-set-design.md` §3 と同じ)。

**自分のチャートは医師でなくても作れる**。オーダーを出す道具ではなく、読むための設定なので。

「名前を付けて保存」は複製ではなく **編集中の内容で新規作成する**(項目を足し引きしてから
別名で保存できる)。そのため backend に複製の口は持たない。

## 3. 横軸 = 単位 × 列数。右端が基準日

`axis` は単位(日 / 月 / 年)と列数で、基準日(既定は今日)から遡る。経過表が
「基準日までの 1 週間」を持つのと同じ考え方。月・年は暦の区切りで割り、
**最終列だけは基準日で切る**(まだ来ていない日まで描かない)。

読んでいる位置は URL の `view` に載せる(リロードで今日に戻らず、リンクで共有できる)。

単位・列数・重ねるかどうかの既定は**定義が持つ**(端末には残さない。同じ定義を開けば
誰の端末でも同じ見え方になる)。URL の view に書いてあればその場はそちらが勝つ。
グラフの書き方を `o`(まとめる)/ `s`(項目ごと)の 2 文字に分けてあるのは、真偽値 1 文字だと
「指定なし(定義に従う)」と「まとめない」を区別できないため。
形は `[基準日][@中心の日][~単位列数][/定義 id][o|s][n][!]`(例 `2026-09-23~m12/5on`、単位は `d`/`m`/`y`、
`n` はグラフ上に数値を出している状態)。`@中心の日` はイベントや点を基準に前後を見ているときの
その日で、各グラフに線を引き、ツールチップ・ホバーに「基準+14日」のような日数を添える。
基準日が今日で、単位・列数が定義のままなら省く。区切りに `+` を使わないのは、
クエリ文字列の `+` が空白に解釈されるため(`parseChartView` / `formatChartView`)。

`!` は全画面。経過表・パスシートと同じ枠(左右と下に 24px、上端は「患者情報の下」を
パネル側が実測)で、Escape でも抜けられる。

## 4. 値の取り方

`Observation` を **項目の coding をまとめて 1 回の検索**で引く
(`usePatientChartObservations`)。

    GET /Observation?patient=Patient/<id>&code=<sys|code,sys|code,...>
                    &date=ge<開始>&date=le<基準日>&_sort=date&_count=500&_offset=...

- 検体検査の時系列表は `DiagnosticReport` 起点だが、チャートはバイタルやテンプレート抽出
  (報告書を持たない)も同じ表に載せるので **Observation を直接引く**。
- 日時は `effectiveDateTime` → `effectivePeriod.start` → `issued` の順。
  タイムゾーン付き(テンプレート抽出の `...Z` など)はローカルの文字列に直してから点にする。
- 値は `valueQuantity.value`、無ければ `valueInteger`。テンプレート抽出は単位の無い integer を
  `valueInteger` で持つ(`observationExtract.ts` の `observationValue` と対)。
  `components` を持つ項目(血圧)は `Observation.component` から系列を 2 本作る。
- 同じ日時に 2 件あれば後から来たもの(訂正)を採る。
- 取消・誤登録は**画面側で落とす**。上流が Observation の `status:not` に応えるか未確認のため
  (`api/queries.ts` の外来 Encounter にも同じ注記がある)。

## 5. イベントの取り方

種別ごとに取得元が違う。定義で OFF の種別は `patientId` を渡さずに止める(フックの数は変えない)。

| 種別 | 取得元 | 形 |
|---|---|---|
| 病名 | `useKarteConditions`(カルテのプロブレム一覧と同じ検索) | プロブレムの開始日・転帰日に印(下記) |
| 入退院 | `usePatientEncounterEvents` | 入院は期間バー(退院前なら基準日まで)、転棟・外出泊は印 |
| 手術 | `usePatientSurgeryPerforms` | 実施記録のハブ Procedure、入室時刻に印 |
| 化学療法 | `useRegimenApplications` + `useRegimenDayOrders` | 適用 × クールで 1 本(その日オーダーの最初〜最後) |
| 放射線治療 | `usePatientRadiotherapyOrders` + `useRadiotherapyProcedures` | コースごとに実施済み照射の最初〜最後で 1 本 |
| 有害事象 | `usePatientAdverseEvents`(category で引く。code は用語の text だけなので項目の code 検索には乗らない) | 用語ごとに 1 行、発現〜回復のバーを Grade の濃さで(§5.3) |
| 検査実施 / 注射実施 | `usePatientPerformedProcedures` | ハブ Procedure 1 件が印 1 つ |
| 処方 | `usePatientChartPrescriptions` | オーダー 1 件が**飲んでいた期間**のバー |

検査・注射は経過表の `usePatientExamOrders`(オーダーから `_revinclude` で実施記録まで辿る)を
使わない。チャートは年単位の範囲を見るので、`_count=100` 固定のあの検索では件数が足りず重い。
代わりに**実施記録そのもの**を種別 OR + 期間で検索してページングする。ハブの `code` は
1 件目の手技(検査名)なので、名前はハブだけで出せる。

未来のイベントは出さない(起きたことを読む画面なので)。

処方だけは「出した日」ではなく**飲んでいた期間**をバーにする。投薬と検査値・血圧の
前後関係を読むのが目的で、オーダー日の印だけでは足りないため。期間は Rp ごとの
投与日数(`dispenseRequest.expectedSupplyDuration`)の最大で、開始はオーダーの occurrence。
日数を持たない処方(頓用・外用)は印にする。飲み始めが表示範囲より前でも掛かっていれば
出したいので、検索は範囲の少し前から引く(`ORAL_LOOKBACK_DAYS`)。
処方はオーダー種別(`order-type`)を持たないので、処方区分の system で引き当てる。

病名は**プロブレムだけ**を出す(保険病名は数が多く、節目が埋もれる)。印の横に短い名前を出し、
手術・入退院と同じく各レーンにも縦線を落とす(「確定の前後で値がどう動いたか」を読む節目なので)。

- 開始日: 「の疑い」なら「疑い」、疑いのプロブレムから `problem-succeeded-by` で引き継がれたものは
  「確定」、それ以外は「開始」。下位プロブレム(転移など)も「開始」で出る。
- 転帰日: 転帰(治癒・軽快・中止)。疑いが確定へ引き継がれて閉じたものは、確定の印と同じことを
  2 度描かないので出さない。
- 病名には詳細モーダルが無いので、押したときのメニューは「基準日に設定」だけ。
- 印の名前は隣の印までに丸ごと入るときだけ「確定 #2 Ｓ状結腸癌」と出し、入らなければ「確定」だけにする
  (途中で切った「確定 #…」は何の印か読めない)。

## 5.1 選択肢の項目(症状などの定性的な記録)

テンプレートの choice 項目(浮腫の程度・NYHA 分類など)は、グラフではなく**帯の 1 行**に並べる
(薬剤の行の下)。項目に `options`(選択肢の code / display、並び順どおり)を持たせ、あれば
選択肢の項目として扱う(`isChoiceItem`)。値は数値項目と同じ Observation の検索で一緒に引く
(テンプレートの抽出は choice の回答を `valueCodeableConcept` の Observation にしている)。

- 選択肢の**並び順を程度の順**とみなし(「なし」→「高度」)、記録ごとの四角の濃さを 5 段で変える。
  最も軽いものは縁だけ。程度でない選択肢(「無 / 有」など)も並び順どおりに濃くなる。
- 複数選択は回答 1 つにつき Observation が 1 件になるので、同じ日時のものを 1 つにまとめ、
  名前は「、」でつなぎ、濃さは重い方にする。選択肢に無いコード(テンプレートを後から直した)は
  名前だけ出して一番薄くする。
- 隣の記録までに丸ごと入るときだけ選んだ名前を出す。押すと元の記録(テンプレートの記入、
  検査なら結果の載った報告書)を開ける。
- **定性検査も同じ行になる**。結果項目マスタのコード型(`CD` / `CO`)は `code_value_list` を
  `options` にして持ち、結果の `valueCodeableConcept` と突き合わせる(結果は同じ一覧から
  作られるので code が一致する。system が無い項目もあるので、無い側は system を見ない)。
  順序のない `CD`(陽性/陰性・血液型)は `scale: "nominal"` で、並び順で濃くすると
  「陰性が濃い」誤読になるため、全部を最も薄い塗り(枠だけの 0 と区別する 1)にして名前で読ませる。
  エディタの検索は `PQ,CD,CO` をカンマ区切りで渡す(`Master::LabResultItemsController` が複数可)。
- 程度が上がった(添字が前の記録より大きくなった)記録の日には、各レーンに行の色の破線を
  落とす(悪化の目印。`nominal` は対象外)。

## 5.2 追う薬剤の行

帯の種別の下に、定義の `drugs` に入れた薬剤を **1 薬剤 1 行**で並べる。帯の「処方」
(オーダー 1 件 = バー 1 本)では、Do 処方が毎回別オーダーになるうえ用量が出ないため、
「いつから飲み、いつ増やし・減らし、いつやめたか」が読めない。

- **成分でまとめる**。薬剤マスタから選んだ薬剤の YJ コード(無ければ薬価基準コード)の
  先頭 7 桁(薬効分類 4 桁 + 成分・投与経路 3 桁)を `yj7` に持ち、`MedicationRequest` の
  YJ コード・一般名処方コードの先頭 7 桁と突き合わせる。規格違い(1mg と 0.5mg)・銘柄違い・
  一般名処方(一般名処方コードも同じ体系)が同じ行に入る。保存される MR は YJ コードを
  持たないことがある(HOT に無い薬剤)ので、選んだ薬剤のレセ電コードも `codes` に持つ。
  表示名は規格・屋号を落とした名称を初期値にし、エディタで変えられる。
- **日ごとに「その日の 1 日量」を置いてから区間にする**。処方(内服・頓用でない)は
  `doseQuantity` が 1 日量(`rxDispenseHelpers.ts` の注記と同じ)なので、オーダーの開始日から
  投与日数ぶんの日に置く。同じ日に重なれば後から始まった処方が勝つ(残薬を新しい処方で
  置き換えた、とみなす)。続く日が同じ内容なら 1 区間、内容が変われば区切る。
- **処方と処方の間が `CHART_DRUG_GAP_DAYS`(7 日)以内なら続けて飲んでいたとみなす**
  (外来の受診日のずれで毎回途切れて見えないように)。それより空けば途切れ、次は「開始」。
- **増量・減量**は、錠・カプセルなら名称の含量(「1mg」)×錠数を足した 1 日量で比べる
  (1mg 2 錠 + 0.5mg 1 錠 = 2.5mg)。含量が読めなければ、薬剤 1 つのときだけ数量で比べ、
  比べられなければ「変更」とする。区間の頭に ▲(増量)/ ▼(減量)を置く。
- **中止したオーダーは入れない**。中止は進捗の Task(cancelled)で持つので、処方・注射の
  検索で `_revinclude=Task:focus` を足して除く。帯の「処方」も同じ扱いにした。
- 頓用・外用(期間を持たない)と注射(1 日 1 オーダー)は、その日の印にする。注射は
  オーダーで見る(実施記録ではない)ので、化学療法の日オーダーの薬剤も入る。
- 開始・変わり目・途切れた日には、各レーンにも薬剤色の破線を落とす(治療の前後で値を比べる
  目印)。基準日を越えて続く最後の区間は、まだ飲んでいる途中なので途切れにしない。

## 5.3 有害事象の行

種別 `adverse` を ON にすると、有害事象(`Observation` category `adverse-event`、
`fhir/adverseEventHelpers.ts`)を **用語ごとに 1 行** で出す(`chartBandRows`。他の種別は
種別 1 つに 1 行)。記録が無ければ「有害事象」の空行を 1 つ置く(ON にしたのに行が無いと
消えたように見える)。行ラベルは薬剤の行と同じく幅に収まるぶんだけ出し、`<title>` に全体を持つ。

- 発現日から回復日までのバー。回復していなければ基準日まで(入院と同じ)。
- バーは Grade を濃さにして塗る(選択肢の行と同じ `.patient-chart__level--N`)。G1 が最も薄い塗り(1)、
  G4・G5 が最も濃い(4)で、枠だけ(0)は使わない(起きている有害事象が「無い」ように見えるため。
  `adverseGradeLevel`)。網掛けにしたときも同じ段を使う。
  名前は「G3」。
- **Grade 3 以上の発現日は各レーンに縦線**を落とす(手術・入退院と同じ節目の扱い)。
- 開く先は無い(記録の編集は化学療法・放射線治療の右ペインにあり、`KarteDetailTarget` ではない)。

## 5.5 項目ごとに分ける / 1 つに重ねる

どちらで開くかは**チャートの定義**(`definition.overlay`)が持ち、作成・編集のモーダルの
「グラフ」で決める。ツールバーのアイコンはその場で見方を変えるためのもので、
押すと `view` に `o` / `s` が入って定義より優先される。

- **項目ごと**(既定): 1 項目 1 レーンのスモールマルチプル。縦軸に実際の値の目盛りが出る。
- **重ねる**: 全系列を 1 つのグラフに描く。**目盛りを 2 つ置く(二重軸)のはしない** ——
  単位も桁も違う項目(体温 35〜38・血圧 50〜200・WBC 2〜6)を 1 本の軸に載せると
  誤読するため、各系列を自分の表示範囲で 0〜100% に正規化して重ねる。形を比べる表示なので
  縦軸に数値は出さず、**実際の値と範囲は凡例とツールチップで読む**。

凡例はそのまま**絞り込みの操作**にもなる。押した系列はその場だけ隠れ(定義にも URL にも
残さない)、線・点・ツールチップから外れる。**隠しても色と印は付け替えない** —— 残った系列の
色が変わると、隠す前後で同じ線が別物に見えるため。別のチャートに切り替えたら戻す。

重ねたときの系列の色は dataviz の検証済みカテゴリ配色をスロット 1 から順に使う
(色を作り足さない。スロット 1 は既存の系列色と同じ値)。ライトテーマでは一部の色が
背景との対比 3:1 を下回るので、**凡例を常に出す**(色だけで見分けさせない)。
印の形(丸・下三角・四角・上三角・菱形)も系列ごとに変えるので、色が近くても区別できる。

## 6. 描画

- 横軸は `ChartRange`(`tMin` / `tMax`)を**全レーンが共有**する。列の境界を縦のグリッドに引き、
  今日は破線。列の見出しは幅が足りるものだけ残す(日 92 列でも重ならない)。
  見出しは 2 段で、上の段が「1月」「1/1」、下の段に先頭の列と年が変わった最初の列(1 月・1 月 1 日)
  だけ「2025年」を出す(36 か月でどこが何年か読めるように。上の段の書き方は全列で揃える)。
  間引くときも年を持つ見出しを優先して残す。
- 最上段がイベントの帯。種別ごとに 1 行で、期間はバー、点は ▼。`target` を持つもの
  (手術・検査・注射・放射線治療)はクリックでカルテと同じオーダー詳細モーダルを開く。
- **節目(手術・入退院)だけ各レーンにも縦線を落とす**。検査・注射・処方は件数が多く、
  すべて線にすると値の動きが読めなくなるので帯の印・バーだけにする。
- バーの名前は**隣のバーまでの余地に収まるぶんだけ**出す(同時に何本も走る処方の行で
  名前が重なって読めなくなる)。4 文字も入らなければ出さず、ホバーで読ませる。
  重なったバーを 1 本に見せないよう、バーは地の色で縁を取る。
- 点の数値はツールバーのアイコンで出し入れする(`view` の `n`)。**重なるものは出さない** ——
  左から順に、既に置いたラベルと当たらないものだけ置く。測定が詰まった期間は間引かれるが、
  全部に出して読めなくなるより、読める密度で出すほうが値打ちがある。
  字は系列色ではなく本文の色にする(小さい字を系列色で塗るとライトテーマで地との対比が
  足りない。どの系列かは点との近さで読む)。
- **判定と基準範囲を点に持たせる**。検査は `Observation.interpretation`(HH/H/L/LL)と
  `referenceRange` の先頭、バイタルは施設のしきい値(`vitalInterpretationOf`、経過表と同じ)で
  判定する。判定のある点は輪で囲み(色だけに頼らない)、数値ラベルも検査結果の表と同じ色にする。
- **基準範囲は項目ごと表示の、系列が 1 本のレーンにだけ帯で敷く**。各点から次の点までの階段
  (年齢帯で範囲が変われば段になる)で、縦軸は帯も収まる範囲にとる。重ね表示は各系列を
  正規化しているので帯を出さず、血圧(2 系列)も出さない。
- **単位・測定法・JLAC11 が変わった所で線を切る**(検査のみ)。そのまま比べられない値どうしを
  つながないため。変わり目には系列色の破線と上端の ◆ を置き、ホバーで何が変わったかを出す。
  換算はしない。バイタルとテンプレートは項目の単位で揃える(書き方の揺れで線が切れないように)。
- **点・イベント・薬剤の区間を押すと、その場にメニューを出す**(「開く」「基準日に設定」)。
  押しただけで詳細を開かないのは、「この治療の前後を見たい」操作と取り合うため。
  - 開く先: イベントは `target`(化学療法はクールの最初の日オーダー。入退院は開く先が無い)。
    検査の点は、点が Observation しか持たないので `DiagnosticReport?result=` で報告書を引いて
    検査結果内容を開く(返った報告書の result に本当に含まれるかを確かめる)。テンプレートの点は
    `Observation.derivedFrom` の QuestionnaireResponse を開く。バイタルは開く先が無い。
  - 「基準日に設定」は view に `@日付` を入れ、その日が真ん中に来るよう右端を置き直す
    (`centeredBaseDate`。月・年は月末・年末に揃える)。基準がある間に単位・列数を変えても
    真ん中に置き直す。ツールバーの「基準 YYYY/MM/DD ✕」で外す。
- ホバーは時刻を 1 つだけ持ち、各レーンが自分の最近傍点をツールチップに出す。
  行には値と結果の単位・判定・基準範囲を出し、系列の中で測定法が複数あるときは測定法も添える。
  ツールチップはカーソルと反対側の角に置く(線と点を隠さず、上のレーンにも重ならない)。
- **カーソルのあるレーンのツールチップには、その時点で有効な状態も添える**(§6.1 の
  `describeStatesAt`): 「入院中(12 日目)」「mFOLFOX6 第 3 クール」「ワーファリン 2.5mg/日」
  「浮腫 軽度(12 日前)」「悪心 G2」。取得は増やさず、帯の区間・印を時刻で引くだけ。
  全レーンに同じ行を繰り返すと値が埋もれるので、カーソルのあるレーン(`hover.owner`)にだけ出す。
  状態は 1 行にまとめて折り返す(状態ごとに行を取るとレーンの高さを超えて下のレーンに掛かる)。
- 入院は期間バーだけで出し、入院日・退院日の印は重ねない(同じことを 2 回描かない)。
- 左の余白は帯の行ラベル(最長「放射線治療」)が収まる幅で決めてある。行を増やすときは
  ラベルの長さに注意する(はみ出すと viewBox の外で切れる)。
- タブ全体のスクロールは他のタブと同じく `.karte-tabpanel` が持つ。チャートは縦に伸びるので、
  この囲みが無いとカルテのレイアウトからはみ出す。ただし送るのは本文(レーン)だけで、
  ツールバーは上に残す(経過表が表のラップだけを送るのと同じ)。
- **viewBox はパネルの実測の大きさに合わせる**(1 単位 = 1px)。固定幅の viewBox を
  横に引き伸ばすと、全画面や広いペインで文字と点まで拡大されて読めなくなる。
  ResizeObserver が動かない環境があるので、まず同期で測ってから追う。
- 高さもパネルの残り(帯と凡例を引いたぶん)を使い切る。項目が多くて最小の高さに
  収まらないときは、本文を縦に送る。
- 操作の大きさ(高さ 24px・文字 12px)は経過表のツールバーに揃えてある。
- グラフのライブラリは入れず、`LabTimelineChart` の目盛り(`niceTicks`)・数値の書式・
  ツールチップの見た目(`.lab-chart__*`)を借りて自前の SVG で描く。

### 6.1 状態(帯の行を時刻で引く)と、全レーンの網掛け

帯の行のうち期間を持つもの —— 選択肢の項目(記録から次の記録まで)、追う薬剤(用量の区間)、
入院、化学療法のクール、有害事象(発現〜回復)—— を **時刻で引ける区間の並び**にしたのが
「状態」(`fhir/chartStateHelpers.ts` の `ChartStateTrack`)。ツールチップ(§6)、網掛け、
層別の要約(§8.1)が同じものを読む。タブが既に持つ行から作るので取得は増えない。
`chartStateHelpers` は `chartDefinitionHelpers` を import する側で、逆は無い
(`ChartTrackRef` は `chartDefinitionHelpers` に置く)。

区間の `index` は層の並び(選択肢の添字・用量の昇順・Grade)、`level` は 0〜4 の濃さ。
化学療法は区間の名前をクールごとに持つが、層は「クール中 / クール外」の 2 つに畳む
(クールごとに列を分けると n が小さくなりすぎる)。

**網掛け**: 定義の `background`(`{ kind: "item" | "drug", key }` か `{ kind: "event", event }`、
種別は `encounter` / `chemo` / `adverse` のみ)で行を 1 つ選ぶと、その状態を **全レーンに
薄い帯で敷く**(`.patient-chart__state--N`。基準範囲の帯よりさらに薄い 5 段)。凡例は
最初のグラフの見出しの行の右端に出す(重ね表示では系列の凡例の先頭。帯の直下に置くと帯の行の
説明に見えるため)(凡例の色見本は帯より濃くする。12px 角では帯と同じ薄さだと見えない)。
凡例の段は選択肢の並び順で決め、その患者に記録の無い選択肢も同じ濃さで並べる(記録の有無で
見本が「塗りなし」になると、程度の順が読めない)。
状態が変わった所には各レーンに本文色の点線を落とす(同じ状態の記録が続く所には引かない)。
定義に持つのは、単位・列数と同じく「誰が開いても同じ見え方」にするため。エディタの「網掛け」は
編集中の選択肢の項目・薬剤・ON の対象種別から選ばせ、元の行を外していれば保存時に落とす。

## 7. 申し送り

- **JLAC11 の前方一致で合流しない**。検体検査の時系列表は 17 桁のうち先頭 12 桁が同じ結果を
  同じ行にまとめる(測定法・結果単位が試薬で変わるため)が、チャートは `code=` の完全一致で
  引くので、施設の結果項目コードを持たない古い結果は拾えない。合流が要るなら、
  マスタから読み替えた JLAC11 を `codings` に足す形になる。
- 上流が Observation の `status:not` に応えるなら、取消の除外を検索側に寄せられる。

## 8. 相関を読む道具

ケバブメニューの「層別の要約」「対比」。どちらも読み捨ての分析で、**URL の `view` にも定義にも
載せない**(`KarteChartTab` のローカル state)。統計は n・中央値・範囲・Spearman の ρ までに留め、
p 値は出さない。因果の注意文は説明モーダルにだけ置き、分析のモーダルには出さない
(結果の読み取りに要らない文を画面に増やさない)。

### 8.1 層別の要約(`ChartStratifyModal`)

§6.1 の状態を 1 つ「層」に選び(定義の `background` が初期値)、各定量の系列(血圧は収縮期・
拡張期で 2 行)の点を層に振り分けて、層ごとに **n・中央値・範囲・基準外の割合** を表にする
(`stratifySeries`)。列は層の並び + どの区間にも入らない時間(「服用なし」「入院外」「クール外」
「なし」)。選択肢の項目は記録前の時間を持たないので、記録前の点は数えない。基準日を置いて
いれば「基準日の前後」も層に選べる(`anchorStateTrack`)。全行 n = 0 の列は省く。
基準外は `flag`(検査の interpretation・バイタルの施設しきい値)を持つ項目だけで、テンプレートは「—」。

### 8.2 対比(`ChartScatterModal`)

X と Y を選んで散布図にする。X には定量の系列に加えて **選択肢の項目**(添字を値にし、目盛りは
選択肢の名前)も置ける。Y は定量のみ。記録の対応は「同じ日」か ±3 / 7 / 14 日で、X の各記録に
窓の中で最も近い未使用の Y の記録を時刻順に貪欲に当てる(`pairByTime`)。点は古いほど薄く、
ホバーで両方の値と日付(基準日があれば日数も)。`n` は常に出し、`n < 3` か値が変わらないときは
ρ を出さず、`n < 10` は目安にならない旨を添える。自前 SVG で、目盛りは `niceTicks`。
見出しの「?」(`Modal` の `titleAction`)から使い方のモーダル(`ChartScatterGuide`)を開く。記録の対応の
当て方・ρ の読み方はそちらに置き、対比の画面そのものには説明文を足さない。
